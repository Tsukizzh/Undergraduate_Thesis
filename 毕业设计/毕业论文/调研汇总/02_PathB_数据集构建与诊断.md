## 1. Step 1-2：结构特征因子实验与 Gate A 决策

**关键因子与 2×2 设计**：
- **因子一：Heme 血红素处理**（开/关）— P450 活性中心的含铁辅因子。Step 1 发现模型原子词汇表缺失 Fe(26)，Heme 残基被映射为 UNK(20)，导致 **OOD 污染**
- **因子二：口袋半径**（6Å vs 10Å）— 配体周围蛋白原子的纳入范围
- **2×2 因子矩阵**：4 组配置（EXP01-EXP04）在完全相同的 495 样本上测试

**Gate A 结果**：

| 实验 | Heme | 半径 | AUC-ROC | 排名 |
|------|:---:|:---:|:---:|:---:|
| **EXP01** | 无 | 10Å | **0.7115** | 1st |
| EXP03 | 无 | 6Å | 0.6678 | 2nd |
| EXP02 | 有 | 10Å | 0.4894 | 3rd |
| EXP04 | 有 | 6Å | 0.4257 | 4th |

**Gate A PASS 原因**：
1. **Heme 效应负面（-0.2322）**：加 Heme 后 AUC 暴跌至 0.5 以下，因为 Fe 原子全零特征 + HEM 残基 UNK 编码通过 GNN 消息传递污染整个口袋表示
2. **半径效应微弱正面（+0.0537）**：10Å 略优于 6Å
3. **决策**：采用 **10Å / noHeme 配置**（EXP01）继续后续诊断

## 2. Step 3-5：对接管线搭建与 Gate B 诊断失败

**对接工具与流程**：
- **对接工具**：**AutoDock Vina v1.2.7**（注：memory 里写的是 Uni-Dock，以 session log 为准）
- **活性位点定位**：从原始 PDB 中识别 HEM 残基的 FE 原子，以其坐标为中心建立 **22.5³ Å³ 对接盒子**（FE ± 11.25Å）

**随机负样本生成策略**：
- **方向**：Direction A（固定底物，随机替换酶）— 确保同一底物同时出现在正样本和负样本中
- **比例**：1:9.36 倍（与 ESIBank 论文一致），270 正 × 9.36 ≈ 2,527 负

**Gate B FAIL 含义**：
- 对接成功 **2,766/2,797 = 98.9%**（265 正 + 2,501 负）
- 评估 AUC-ROC = **0.5170** [0.4804, 0.5521]，**接近随机猜测**（0.5）
- 相比 Path A 的 0.6636，性能**断崖式下跌 19.45%**，且 AUC-ROC CI 包含 0.5（统计上不显著异于随机）
- **核心问题**：仅改变负样本生成方式（抑制剂→随机配对）和结构来源（晶体→Vina 对接），模型失效

## 3. Step 6 消融实验与因果 DAG v2

**DAG v2 三个变量的贡献度**：

| 变量 | 对 AUC 贡献 | 机制 |
|------|:---:|------|
| **负样本身份**（抑制剂 vs 随机配对） | **88.2%** | 分子通道依赖：抑制剂与底物 Tanimoto=0.084 vs 组内 0.131-0.151，模型可利用指纹分布差异（捷径信号）；随机配对时同一底物既在正也在负，分子通道信号为 0 |
| **结构来源变化**（晶体 vs Vina） | **11.8%** | 结构质量：Vina 略低于晶体 |
| **正负样本比例**（1:1 vs 1:9.44） | **< 1%**（不显著） | 三组实验 AUC=0.515-0.517，近似随机 |

**关键发现**：
- ABL-04（Vina+抑制剂）AUC = 0.6885：仅改变结构来源，AUC 从 0.7115 微降至 0.6885（-2.3%），证明**结构质量不是瓶颈**
- ABL-01（Vina+随机配对）AUC = 0.5154：改变负样本身份后暴跌，证明**负样本的身份/语义是根本原因**

## 4. Step 7 Tier1 诊断（E1-E7 核心实验）

### E4：分数分解（最关键）

```
模型分数 = 酶偏置(R²=-0.06) + 底物偏置(R²=0.37) + 酶-底物交互(AUC=0.509)
```

- **酶 R² = -0.06（负数）**：模型完全**忽略酶的身份**。给酶 A 配底物 X 和给酶 B 配底物 X 的分数几乎完全相同
- **底物 R² = 0.37**：底物身份解释了 37% 的分数变化
- **残差 AUC = 0.509**：去掉两个偏置后，判别能力 = 随机，**不存在酶-底物交互信号**

### E4 + E5 为何不矛盾

- E5（指纹分类器）：GroupKFold 正确评估，底物化学指纹 AUC=0.503 ≈ 随机。Direction A 下，同一底物既在正也在负，指纹无法区分
- E4（分数分解）：底物身份**驱动分数数值变化**（R²=0.37），但这种变化**对分类毫无帮助**（AUC≈0.5），因为同一底物的正负样本都拿到相同的分数

### E6：7 家族对比（P450 唯一崩溃）

| 酶家族 | 正样本数 | 在训数据泛化 | AUC |
|------|:---:|:---:|:---:|
| P450（我们的） | 267 | 0%（训练集无 P450） | **0.517** |
| Esterase | ... | ... | **0.934** |
| Duf | ... | ... | 0.796 |
| 磷酸酶 | 6,291 | 48% | **0.877** |
| 其他 3 家族 | >100 | 5-40% | 0.79-0.93 |

### E7：ESIBank 内部 P450 基准

- 在 ESIBank 训练数据本身的 P450 部分（884 正 + 11,445 负）做内部测试：**AUC = 0.638**
- 高于 Step 5 的 0.517（因为有训练数据重叠），但仍是 8 个家族中最低
- **结论**：P450 原本就是模型的弱点，不仅仅是我们的数据问题

## 5. Step 8 通道消融（E8v1 vs E8v2 的惊人反差）

### E8v1（EXP01 晶体+抑制剂数据，AUC=0.712）

| 通道关闭 | AUC | 下降 | 结论 |
|--------|:---:|:---:|------|
| **关结构** | 0.437 | **-0.275** | 结构通道最关键 |
| 关序列 | 0.558 | -0.154 | 序列通道次要 |
| 关分子 | 0.697 | -0.014 | **分子通道基本无贡献** |

**关键悖论**：结构通道"离了不行（关掉 AUC→0.437），但光靠它也不行（仅留结构 AUC=0.451）"

### E8v2（Step 5 Vina+随机配对数据，AUC=0.517）

| 通道关闭 | AUC | 变化 | 显著性 |
|--------|:---:|:---:|:---:|
| 关序列 | 0.528 | +0.011 | 否 |
| 关分子 | 0.540 | +0.023 | 否 |
| 关结构 | 0.489 | -0.028 | 否 |

**dramatic shift**：在崩溃状态下（AUC=0.517），**所有通道效果都不显著**（95% CI 都包含 0）

**深度启示**：
- E8v1 的"结构通道最关键"**只在 EXP01 条件下成立**，不泛化到真正的问题数据
- 在近似随机的任务上做通道关闭没有意义——问题不在"哪个通道不行"，而在**整个模型对这个任务无能为力**
- **logit 爆炸现象**（关结构时 std=15.12）：模型在训练时期望三通道都存在，缺少通道时输出失控，但失控数值不包含有用信息

## 6. Step 9 AllSplit 从零训练

**超参配置**：

| 参数 | 值 | 说明 |
|------|-----|------|
| batch_size | 14 | 单卡 12GB RTX 4070S 极限 |
| accumulate_grad_batches | 2 | 有效批大小 = 28 |
| num_workers | 6 | 32GB 内存极限 |
| learning_rate | 3e-4 | 原始设置 |
| epochs（实际） | 14 | 早停 |
| GPU | RTX 4070S 12GB | Windows 本地单卡 |

**ep14 Val AUC=0.7667 获取过程**：
- 顺序：ep0(0.518) → ep6(0.652) → ep14(**0.7667** val best) → ep22(0.720) → ep27(0.751)
- ep14 为触发早停 patience 上界前的最优点

**数据泄露检测**：
- **酶层面**：0.15% 验证样本中的酶在训练集有同底物正样本（轻微）
- **底物层面**：100% 验证样本的底物也出现在训练集（Direction A 采样决定），但正样本对应的酶不同，**泄露程度评估为中等（6.56%）**
- 这种泄露可能使 ep14 的 0.7667 比纯粹下游评估**偏乐观**

## 7. Step 10 .pt 训练管线与云 DDP

### LMDB 失败原因（作者 256GB vs 我们 32GB）

- **60GB structure LMDB** 映射到 32GB 物理内存 → 系统不断 mmap 换页（page thrashing）
- **性能衰减**：早期 4.5 it/s → 稳态 epoch 14-19 时 2.09 it/s（衰减 54%）

### v1→v3 迭代

| 版本 | 方案 | 速度 | 每 epoch | 原因 |
|------|------|:---:|:---:|------|
| v1 | 分片 300MB | 0.01 it/s | 258h | SSD 100% thrashing，torch.load 不适合大文件 |
| v2 | flatbin+分片 graph | 0.5 it/s | 6.8h | graph 仍用分片，改进小 |
| **v3** | **per-sample .pt** | **7.56 it/s** | **29 min** | 每个 160KB 样本独立 .pt，一个 epoch 仅 28GB IO |

**7.56 it/s 来源**：
- 基础 4.3 it/s（Step 9 优化后无缓存基线）
- v3 改进：消除 CPU k-NN 瓶颈（预计算存入 .pt），减少 LMDB mmap 换页
- 最终：per-sample .pt + num_workers=2 + batch_size=14，稳定 7.33-7.56 it/s（无衰减）

### 云服务器 DDP（2×RTX 4090）

| 配置 | 速度 | 每 epoch | GPU 利用 |
|------|:---:|:---:|:---:|
| Cloud-1 单卡 (bs48, 4w) | 3.74 it/s | 16:41 | 100% |
| **Cloud-2 双卡 DDP (bs56, 6w)** | **2.65 it/s × 2** | **10:00 min** | ~90% |

- DDP 加速：165 samples/s (单卡) → 295 samples/s (双卡) = **1.79×**（非 2×，通信开销）

### legacy_bug test AUC = 0.7244（epoch 27）

- **超过论文基线**：论文 all_split AUC=0.7198，我们 0.7244（+0.0046）
- **边界排序 Bug**：`EdgeConnection` 类中 `complex_edge_index`=[real, knn] 但 `complex_edge_attr`=[knn_attr, real_attr]——**反了**！真实化学键被错误分配为 k-NN 类型属性
- **两种模式**：
  - **fixed** 模式：修复后真实化学键与属性正确对应
  - **legacy_bug** 模式：保留原始 bug（为复现论文）

### Val Loss↑ 但 AUC↑ 的解释

- **Loss 函数**：`BCEWithLogitsLoss` — 拟合绝对概率（outlier 主导）
- **AUC 指标**：只看相对排序（pairwise 对 outlier 鲁棒）
- 三阶段：warmup(ep0-8) → divergence(ep8-22, 排序↑过度自信↑) → true overfitting(ep22+)
- 在不平衡数据（266 正 : 2500 负）上常见，模型为最大化排序倾向高估正样本概率

## 总体结论

Path B 诊断链最终指向：**P450 单一家族的低杂泛性 + Direction A 采样导致的特征失效** 是模型崩溃的根本原因，而非结构质量或对接工具。legacy_bug test AUC=**0.7244** 超越论文基线（0.7198）标志从"诊断失败"到"重新训练成功"的转折，为 Path C 的微调方向提供直接指导。
