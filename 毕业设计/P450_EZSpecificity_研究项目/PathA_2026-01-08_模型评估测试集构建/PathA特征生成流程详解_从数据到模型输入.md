## 1. 模型需要什么输入？

### 1.1 模型配置文件中的定义

EZSpecificity模型的配置文件 `saved_model/model/run_0/complete-full-random-all-0-complex.yml` 中，明确定义了需要的所有输入：

```yaml
# 酶相关
enzyme_lmdb_path: enzyme_features.lmdb     # ESM蛋白质嵌入

# 底物相关
reaction_lmdb_path: reaction_features.lmdb  # 分子图特征
morgan_path: morgan_fingerprint.npy         # Morgan指纹
grover_path: grover_fingerprint.lmdb        # GROVER神经指纹

# 结构相关
structure_processed_path: structure_features.lmdb  # 口袋+配体结构
sequence_processed_path: str_features.lmdb         # 仅配体结构（后备）
high_quality_id_path: high_quality_str.txt         # 有效结构ID列表

# 原始数据
enzyme_path: Enzymes.csv                    # 酶序列
substrate_path: Substrates.csv              # 底物SMILES
data_path: data.csv                         # 酶-底物-对接三元组
```

### 1.2 特征维度说明

| 输入名称 | 维度 | 说明 |
|---------|------|------|
| **ESM嵌入** | (L, 1280) | L=序列长度，每个氨基酸1280维 |
| **Morgan指纹** | (1, 1024) | 1024位二进制向量 |
| **GROVER分子级** | (4885,) | 整个分子的神经嵌入 |
| **GROVER原子级** | (n_atoms, 2400) | 每个原子2400维 |
| **反应图** | 可变 | 原子特征+键特征+邻接表 |
| **结构特征** | 可变 | 3D坐标+距离矩阵+图结构 |

### 1.3 类比理解

想象你要教一个从没见过化学的AI判断"这个酶能不能催化这个底物"。你不能直接给它看分子式，因为它不懂化学。你需要把分子"翻译"成它能理解的数字：

```
人类看到的：
  酶 = MGLSDGEWQLVLNVWGKVEADIPGHGQE... (蛋白质序列)
  底物 = COc1ccccc1O (SMILES化学式)
  结构 = 一个PDB文件（3D坐标）

模型看到的：
  酶 = [[0.12, -0.34, 0.56, ...], [0.23, 0.45, -0.12, ...], ...]  ← 1280维向量序列
  底物 = [1, 0, 0, 1, 0, 1, 0, 0, ...] ← 1024位指纹
       + [[0.1, 0.2, ...], [0.3, 0.4, ...], ...] ← 2400维原子嵌入
       + 图结构（哪个原子连哪个原子）
  结构 = 3D坐标 + 距离矩阵 + 图连接
```

**PathA的Step 1-8就是做这个"翻译"工作。**

## 3. Step 1-8 详解

### Step 1: 下载PDB文件

| 项目 | 说明 |
|------|------|
| **做什么** | 从RCSB PDB数据库下载627个蛋白质结构文件 |
| **为什么需要** | PDB文件包含酶和配体的3D坐标，是Step 2提取序列和Step 8提取结构特征的原料 |
| **输入** | 独立测试集中的PDB ID列表 |
| **输出** | `data/01_Step1_PDB文件/` (627个.pdb/.cif文件) |
| **对应模型输入** | 间接 → 用于生成结构特征 |

**类比**：这一步就像去图书馆借来627本酶的"3D说明书"。

---

### Step 2: 提取酶序列

| 项目 | 说明 |
|------|------|
| **做什么** | 从740条记录中提取292条唯一酶序列（已删除PS-I污染） |
| **为什么需要** | 模型需要蛋白质序列来生成ESM嵌入 |
| **输入** | 独立测试集CSV中的`sequence`字段 |
| **输出** | `data/02_Step2_酶序列/Enzymes.csv` (292条) |
| **对应模型输入** | → `enzyme_path` (模型配置中的酶序列文件) |

**类比**：从627本"3D说明书"中抄出292份独特的"氨基酸配方"。

**技术细节**：
- 序列来自CSV的`sequence`字段（RCSB deposited sequence），不是从PDB文件提取
- 292个唯一序列 > 153个唯一UniProt，因为包含了同一蛋白的突变体

---

### Step 3: 配体处理与数据集构建

这是最复杂的一步，包含3个子任务：

#### 子任务3.1: 配体分类审核

| 项目 | 说明 |
|------|------|
| **做什么** | 将682条配体记录分为4类：SUBSTRATE(底物)/INHIBITOR(抑制剂)/PRODUCT(产物)/EXCLUDE(排除) |
| **为什么需要** | 机器学习需要标签。底物是正样本，抑制剂和产物是负样本 |
| **结果** | SUBSTRATE: 272, INHIBITOR: 244, PRODUCT: 23, EXCLUDE: 143 |

**类比**：把682种"化学物品"分拣到4个不同的箱子里。

#### 子任务3.2: 提取SMILES

| 项目 | 说明 |
|------|------|
| **做什么** | 从RCSB API获取543个配体的SMILES化学式 |
| **为什么需要** | SMILES是生成分子指纹和图特征的输入 |
| **成功率** | 100% (543/543) |

**类比**：为每种化学物品写一份"化学速记法"说明。

#### 子任务3.3: 数据集构建

| 项目 | 说明 |
|------|------|
| **做什么** | 生成6套不同的数据集方案(B1-B6)，包含不同的正负样本组合 |
| **输出** | Substrates.csv (436条唯一SMILES) + 6套data.csv |
| **对应模型输入** | → `substrate_path` + `data_path` |

**六套方案**：

| 方案 | 正样本 | 负样本 | 用途 |
|------|--------|--------|------|
| B1 | 272底物 | 无 | 仅正样本基线 |
| B2 | 272底物 | 23产物 | 底物vs产物 |
| B3 | 272底物 | 267(产物+抑制剂) | 完整测试 |
| B4 | 无 | 23产物 | 仅产物 |
| B5 | 无 | 244抑制剂 | 仅抑制剂 |
| B6 | 272底物 | 244抑制剂 | 底物vs抑制剂 |

---

### Step 4: CSV格式修正

| 项目 | 说明 |
|------|------|
| **做什么** | 调整CSV文件的列名和格式，使其符合模型代码的期望 |
| **为什么需要** | 模型代码硬编码了特定的列名（如`Protein sequence`而非`sequence`） |
| **修改内容** | Enzymes.csv列名→`Protein sequence`；Substrates.csv列名→`Substrate_SMILES` |
| **对应模型输入** | → `enzyme_path` + `substrate_path` (最终格式) |

**类比**：把"配方"和"化学式"的格式调整成模型能读懂的标准格式。

---

### Step 5: ESM酶嵌入生成 ✅ 已完成

| 项目 | 说明 |
|------|------|
| **做什么** | 用ESM-2蛋白质语言模型将292条酶序列转换为高维向量 |
| **为什么需要** | 模型不能直接理解氨基酸字母，需要转换为数字表示 |
| **输入** | Enzymes.csv (292条序列) |
| **输出** | `enzyme_features.lmdb` (~700MB) |
| **对应模型输入** | → `enzyme_lmdb_path` |

**技术规格**：
- ESM模型：esm2_t33_650M_UR50D (650M参数)
- 输出维度：每个氨基酸1280维向量
- 存储格式：per-residue embedding (L, 1280)，L=序列长度

**类比**：ESM就像一个"蛋白质翻译官"，它读过几千万条蛋白质序列，学会了如何把氨基酸字母翻译成有意义的数字向量。每个氨基酸都被翻译成一个1280维的"语义向量"，这个向量不仅包含氨基酸本身的信息，还包含它在蛋白质中的上下文信息。

**为什么是LMDB格式**：
- LMDB是一种高效的键值数据库
- 可以按需读取单条记录，不用全部加载到内存
- 支持多进程并发读取

---

### Step 6: 反应图特征生成 ✅ 已完成

| 项目 | 说明 |
|------|------|
| **做什么** | 将436个SMILES转换为分子图表示（原子、键、邻接关系） |
| **为什么需要** | 图神经网络需要图结构作为输入 |
| **输入** | Substrates.csv (436条SMILES) |
| **输出** | `reaction_features.lmdb` |
| **对应模型输入** | → `reaction_lmdb_path` |

**图结构包含**：
- 原子特征：原子类型、电荷、杂化状态等
- 键特征：键类型、共轭性、环内键等
- 邻接表：哪些原子相连

**类比**：把每个分子画成一张"社交网络图"——原子是人，化学键是好友关系，图神经网络就像社交媒体算法，通过分析这张社交网络来理解分子的性质。

---

### Step 7: 分子指纹生成 ✅ 已完成

分子指纹是分子的"数字指纹"，用于快速比较分子相似性。我们生成两种指纹：

#### 7.1 Morgan指纹

| 项目 | 说明 |
|------|------|
| **做什么** | 为每个分子生成1024位的二进制指纹 |
| **为什么需要** | 模型配置要求 `features: ["morgan", 1024]` |
| **输入** | Substrates.csv (436条SMILES) |
| **输出** | `morgan_fingerprint.npy` (436, 1024) int8 |
| **对应模型输入** | → `morgan_path` |

**什么是Morgan指纹**：
- 也叫ECFP（Extended Connectivity Fingerprint）
- 原理：对分子中每个原子，检查它周围半径2范围内的"邻域"，把这些邻域模式哈希成固定长度的位向量
- 特点：稀疏（96%是0），只有少数位是1

**类比**：想象你要描述一个人。Morgan指纹的方法是：对这个人身体的每个部位，看看它周围2步范围内有什么特征，然后把所有这些局部特征编码成一个1024位的"特征码"。

**为什么大部分是0**：
- 1024个位置代表1024种可能的化学模式
- 一个小分子只包含其中几十种模式
- 所以大部分位置都是0

#### 7.2 GROVER指纹

| 项目 | 说明 |
|------|------|
| **做什么** | 用预训练的GROVER神经网络生成分子嵌入 |
| **为什么需要** | 模型配置要求 `features: ["grover_mean", 4885]` 和 `atom_features: ["grover", 2400]` |
| **输入** | Substrates.csv (436条SMILES) + grover_large.pt (预训练模型) |
| **输出** | `grover_fingerprint.lmdb` (~10GB) |
| **对应模型输入** | → `grover_path` |

**GROVER vs Morgan的区别**：

| 维度 | Morgan | GROVER |
|------|--------|--------|
| 生成方式 | 规则化学规则（手工设计） | 神经网络（从1000万分子学习） |
| 输出格式 | 二进制向量 | 连续浮点向量 |
| 维度 | 1024 | 原子级2400 + 分子级4885 |
| 类比 | 用清单描述人（身高/体重/眼睛颜色） | 让AI画一幅肖像（捕捉清单无法描述的微妙特征） |

**GROVER的两种输出**：
- `embedding` (n_atoms, 2400)：每个原子一个2400维向量，用于图神经网络
- `total_embedding` (4885,)：整个分子汇总为一个向量，作为全局特征

---

### Step 8: 结构特征生成 ⏳ 待执行

| 项目 | 说明 |
|------|------|
| **做什么** | 从PDB文件提取3D结构特征（口袋+配体） |
| **为什么需要** | 模型需要理解酶-底物的3D结合方式 |
| **输入** | 627个PDB文件 + data.csv中的对接索引 |
| **输出** | `structure_features.lmdb` + `str_features.lmdb` + `high_quality_str.txt` |
| **对应模型输入** | → `structure_processed_path` + `sequence_processed_path` + `high_quality_id_path` |

**三个子步骤**：

#### 8.1 口袋提取

从每个PDB文件中提取：
- **口袋**：配体原子10Å范围内的蛋白质原子（不含氢）
- **配体**：小分子配体的3D坐标

**为什么是10Å**：这是分子对接领域的标准阈值，10Å范围通常包含所有与配体直接相互作用的蛋白质残基。

**类比**：就像从一幅"全家福"照片中裁剪出"合影区域"——不需要整个房间，只需要人物周围10米范围内的背景。

#### 8.2 配体对齐

PDB中的配体原子编号 ≠ SMILES中的原子顺序，需要对齐：
- 使用MCS（最大公共子结构）算法找到原子对应关系
- 确保3D坐标和2D图特征的原子顺序一致

**类比**：就像两张同一人的照片，角度不同，需要找到"鼻子对鼻子、眼睛对眼睛"的对应关系。

#### 8.3 结构LMDB生成

将口袋和配体的3D信息编码为图神经网络可用的格式：
- **节点**：原子坐标 + 原子类型
- **边**：k近邻连接（k=48）
- **边特征**：24个高斯基函数编码的距离

**两个LMDB的区别**：
- `structure_features.lmdb`：包含口袋+配体（完整结构）
- `str_features.lmdb`：仅包含配体（后备方案，用于口袋提取失败的情况）

## 5. 常见问题

### Q1: 为什么需要这么多种特征？

**答**：不同特征捕捉分子的不同方面：

| 特征类型 | 捕捉的信息 | 类比 |
|----------|-----------|------|
| ESM嵌入 | 蛋白质的进化和功能信息 | 人的"家谱+职业技能" |
| Morgan指纹 | 分子的化学子结构 | 人的"身份证特征" |
| GROVER嵌入 | 分子的深层语义 | 人的"AI肖像画" |
| 反应图 | 分子的拓扑结构 | 人的"社交网络图" |
| 结构特征 | 3D空间结合关系 | 人的"合影姿势" |

模型需要从多个角度"看"分子，才能做出准确预测。

### Q2: 为什么有些文件用LMDB，有些用NPY？

**答**：

| 格式 | 适用场景 |
|------|---------|
| **LMDB** | 记录大小不固定（如ESM嵌入，每个蛋白长度不同）|
| **NPY** | 记录大小固定（如Morgan指纹，每个都是1024维）|

LMDB是键值数据库，可以按需读取单条；NPY是NumPy数组，必须全部加载。

### Q3: Step 8的两个LMDB有什么区别？

**答**：

| 文件 | 内容 | 使用场景 |
|------|------|---------|
| `structure_features.lmdb` | 口袋+配体 | 优先使用（完整结构信息）|
| `str_features.lmdb` | 仅配体 | 后备方案（口袋提取失败时）|

有些PDB文件可能无法成功提取口袋（格式问题、原子缺失等），这时模型会回退到只用配体信息。

### Q4: 为什么Step 3要分6套数据集？

**答**：为了测试模型在不同场景下的表现：

- **B1** (仅底物)：检查模型对真正底物的预测
- **B3** (完整)：全面评估
- **B6** (底物vs抑制剂)：测试模型能否区分"能催化的"和"能结合但不能催化的"

### Q5: Morgan指纹为什么大部分是0？

**答**：完全正常！Morgan指纹是**稀疏编码**：

- 1024个位置代表1024种可能的化学模式
- 一个小分子只包含其中几十种模式
- 所以大约96%的位置是0，4%是1
- 平均每个分子37.2个位是1

这就像一份1024项的清单，每个分子只勾选其中几十项。

### Q6: 模型能处理多长的蛋白质？

**答**：根据配置文件：
- `max_enzyme_length`: 1450个氨基酸
- `max_substrate_length`: 280个原子

超过这个长度的会被截断或跳过。
