## 第一章：核心概念解释

在阅读本文档之前，请先理解以下核心概念。如果您已经熟悉，可以跳过本章。

### 1.1 什么是PDB文件？

**PDB (Protein Data Bank) 文件**是蛋白质的三维结构文件。

```
想象一下：
- 如果蛋白质是一座建筑
- PDB文件就是这座建筑的3D模型图纸
- 里面记录了每一块砖头（原子）的精确位置

文件特点：
- 格式：纯文本文件，扩展名 .pdb
- 大小：通常几百KB到几MB
- 来源：科学家用X射线或冷冻电镜解析得到
- 命名：4位字母数字组合，如 1ABC、7ZB9
```

**PDB文件内容示例**：
```
ATOM      1  N   MET A   1      27.340  24.430   2.614  1.00  9.67           N
ATOM      2  CA  MET A   1      26.266  25.413   2.842  1.00 10.38           C
ATOM      3  C   MET A   1      26.913  26.639   3.531  1.00  9.62           C
...
HETATM 3001  C1  CAM A 401      12.123  15.456   8.789  1.00 15.23           C
（前面是蛋白质原子，HETATM开头的是配体原子）
```

### 1.2 什么是CSV元数据？

**CSV (Comma-Separated Values) 元数据**是关于PDB文件的"说明书"。

```
类比：
- 如果PDB文件是一本书的完整内容
- CSV元数据就是这本书的封面信息（书名、作者、页数、ISBN等）

我们的CSV包含什么：
- pdb_id: 结构编号（如 1ABC）
- uniprot_id: 蛋白质序列编号（如 P00183）
- ligand_ccd: 配体代码（如 CAM）
- resolution: 分辨率（数值越小越清晰）
- classification: 配体分类（substrate/product/inhibitor/unknown）
```

### 1.3 什么是"酶-配体对"？

**酶-配体对**是我们数据的基本单位。

```
组成：
酶-配体对 = 一个酶（UniProt ID） + 一个配体（CCD代码）

举例：
- P00183 + CAM = "细菌P450cam酶与樟脑的结合"
- P9WPP7 + OXY = "结核杆菌CYP121酶与氧分子的结合"

为什么叫"对"？
因为酶和配体是成对出现的，就像"锁和钥匙"的关系。
模型要预测的就是：这个钥匙（配体）能不能打开这把锁（酶）？
```

### 1.4 什么是"去冗余"（Deduplication）？

**去冗余**就是删除重复数据，只保留最好的那一个。

```
为什么要去冗余？
- 同一个酶可能被多个实验室解析过，产生多个PDB结构
- 如果都用上，模型会学到重复的信息，导致过拟合（背答案）

去冗余规则变化：
旧规则（v1）：按UniProt ID去重
- 同一个酶，不管配体是什么，只保留1个结构
- 结果：158个结构

新规则（v2）：按(UniProt ID + 配体CCD)去重  <-- 导师要求
- 同一个酶+同一个配体，只保留1个结构
- 同一个酶+不同配体，各保留1个结构
- 结果：627个结构（740条记录）

举例说明：
旧规则下：CYP3A4酶只有1条记录
新规则下：CYP3A4+配体A、CYP3A4+配体B、CYP3A4+配体C 各1条记录
```

### 1.5 什么是B1/B2/B3方案？

**B1/B2/B3**是三种不同的数据筛选方案，根据配体类型区分。

```
配体类型说明：
- substrate（底物）：酶催化反应的原料，如咖啡因
- product（产物）：酶催化反应的产物，如羟基化咖啡因
- inhibitor（抑制剂）：阻止酶工作的物质，如某些药物
- unknown（未知）：自动分类无法判断的配体

三种方案：
+----------+------------------+------+------------------------+
| 方案     | 包含配体类型      | 数量 | 适用场景               |
+----------+------------------+------+------------------------+
| B1       | 仅底物           | 86   | 最严格，符合原始定义   |
| B2       | 底物+产物        | 128  | 稍宽松，包含代谢产物   |
| B3       | 底物+产物+抑制剂 | 292  | 最宽松，测试模型边界   |
+----------+------------------+------+------------------------+

为什么Unknown不进入B方案？
- 自动分类无法判断它是底物、产物还是抑制剂
- 需要人工查阅文献确认后才能使用
- 目前有448条Unknown，存放在"待人工复核列表"中
```

### 2.3 为什么740条记录只对应627个PDB文件？

这是因为**一个PDB文件可以产生多条CSV记录**。

```
原理图解：

    +-------------------+
    |   1个PDB文件       |
    |   (如 8U1I.pdb)   |
    +-------------------+
            |
            | 里面可能包含：
            | - 多个蛋白链（多个UniProt ID）
            | - 多个配体分子（多个CCD代码）
            |
            v
    +-------------------+
    | 多条CSV记录        |
    | 记录1: UniProt_A + 配体X |
    | 记录2: UniProt_A + 配体Y |
    | 记录3: UniProt_B + 配体X |
    +-------------------+

具体例子（来自真实数据）：
PDB文件 8U1I.pdb 产生了2条CSV记录：
- 记录1: A0AAX7FLX8 + UB9 (2,6-dimethoxy-4-methylphenol)
- 记录2: A0AAX7FLX8 + NO3 (NITRATE ION)

所以：
- 627个唯一的PDB文件
- 展开后产生740条酶-配体对记录
```

#### 3.2.2 【步骤1】展开配对：1426 → 3510

**做什么**：把每个PDB文件"拆解"成多条酶-配体配对记录。

**为什么要展开**：一个PDB文件可能包含：
- 多个蛋白链（不同的UniProt ID）
- 多个配体分子（底物、产物、抑制剂等）

```
举例说明：

    PDB文件 8U1I.pdb
    ┌────────────────────────────┐
    │  蛋白链：                   │
    │    · UniProt A0AAX7FLX8    │
    │                            │
    │  配体分子：                 │
    │    · UB9 (某种酚类化合物)   │
    │    · NO3 (硝酸根离子)       │
    │    · HOH (水分子) ×50      │
    └────────────────────────────┘
              │
              │ 展开操作
              ▼
    ┌────────────────────────────┐
    │ 记录1: A0AAX7FLX8 + UB9    │
    │ 记录2: A0AAX7FLX8 + NO3    │
    │ 记录3: A0AAX7FLX8 + HOH    │
    │ ... (每个水分子都是一条)    │
    └────────────────────────────┘

更复杂的例子（多酶多配体）：

    PDB文件 7M8I.pdb
    ┌────────────────────────────┐
    │  蛋白链：                   │
    │    · UniProt P10109 (酶A)  │
    │    · UniProt P19099 (酶B)  │
    │                            │
    │  配体分子：                 │
    │    · 配体X                  │
    │    · 配体Y                  │
    └────────────────────────────┘
              │
              │ 展开操作 (笛卡尔积)
              ▼
    ┌────────────────────────────┐
    │ 记录1: P10109 + 配体X      │
    │ 记录2: P10109 + 配体Y      │
    │ 记录3: P19099 + 配体X      │
    │ 记录4: P19099 + 配体Y      │
    └────────────────────────────┘

    一个PDB展开成了4条记录！
```

**数量变化**：1,426 个PDB → **3,510 条**配对记录

#### 3.2.3 【步骤2】配体分类 + 过滤：3510 → 1370

**做什么**：给每个配体贴标签，然后过滤掉"exclude"类别。

**为什么要做**：
- PDB里的"配体"包括了很多杂物（水、缓冲盐、血红素辅因子）
- 这些不是我们研究的目标，需要排除
- 同时要区分底物、产物、抑制剂，用于后续B方案

```
配体分类规则（按优先级判断）：

第1优先：排除名单（exclude）
┌─────────────────────────────────────────────────────────┐
│  直接排除的配体（这些100%不是研究目标）：                  │
│                                                         │
│  · 血红素辅因子：HEM, HEC, HEA, HEB                      │
│    （P450的"心脏"，每个P450都有，不是外来配体）           │
│                                                         │
│  · 水分子：HOH, WAT, DOD                                 │
│    （结构里到处都是，没有研究意义）                       │
│                                                         │
│  · 金属离子：NA, CL, MG, CA, ZN, K, FE, MN, CU          │
│    （来自缓冲液或蛋白本身）                               │
│                                                         │
│  · 结晶添加剂：GOL(甘油), EDO, PEG, MPD, DMS            │
│    （为了让蛋白结晶加进去的）                            │
│                                                         │
│  · 缓冲盐：SO4, PO4, ACT, CIT, TRS                       │
│    （维持pH用的）                                        │
│                                                         │
│  · 辅酶：FMN, FAD, NAD, NAP, NDP                         │
│    （酶的"工具"，不是底物）                              │
└─────────────────────────────────────────────────────────┘

第2优先：抑制剂（inhibitor）
┌─────────────────────────────────────────────────────────┐
│  配体名称包含这些关键词的 → 标记为 inhibitor：           │
│                                                         │
│  · azole类：ketoconazole, itraconazole, fluconazole     │
│  · 明确标注：inhibitor, antagonist                       │
│  · 特定药物：metyrapone                                  │
└─────────────────────────────────────────────────────────┘

第3优先：底物（substrate）
┌─────────────────────────────────────────────────────────┐
│  配体名称包含这些关键词的 → 标记为 substrate：           │
│                                                         │
│  · 类固醇：testosterone, progesterone, steroid          │
│  · 脂肪酸：fatty acid, palmit, oleic, lauric            │
│  · 其他天然底物：camphor, vitamin, cholest, retinoic    │
└─────────────────────────────────────────────────────────┘

第4优先：产物（product）
┌─────────────────────────────────────────────────────────┐
│  配体名称匹配这些模式的 → 标记为 product：               │
│                                                         │
│  · metabolite（代谢物）                                  │
│  · hydroxy-、-ol 结尾（羟基化产物）                      │
│  · epoxide（环氧化物）                                   │
│                                                         │
│  ⚠️ 排除误判：oxide但不是epoxide的排除                   │
│     如：carbon monoxide(CO), peroxide(H2O2)             │
└─────────────────────────────────────────────────────────┘

第5优先：未知（unknown）
┌─────────────────────────────────────────────────────────┐
│  以上都不匹配 → 标记为 unknown                           │
│  （需要人工查文献确认）                                   │
└─────────────────────────────────────────────────────────┘
```

**过滤操作**：只保留 classification ≠ exclude 的记录

**数量变化**：3,510 → **1,370** （过滤掉2,140条，占61%）

**被过滤掉的都是什么**：主要是水分子(HOH)和血红素(HEM)，几乎每个PDB都有大量这两种。

#### 3.2.4 【步骤3】去重：1370 → 930

**做什么**：按(UniProt + 配体CCD)组合去重，每组只保留分辨率最好的那条。

**为什么要去重**：
- 热门的酶（如CYP3A4）可能被解析过几十次
- 同一个酶+同一个配体的组合可能出现在多个PDB中
- 如果都保留，模型会对这些组合"过拟合"（死记硬背）

```
去重逻辑示意：

    去重前：同一个(酶+配体)出现了3次
    ┌──────────────────────────────────────┐
    │ PDB=1ABC, UniProt=P00183, CCD=CAM    │
    │         分辨率=1.80Å                  │
    ├──────────────────────────────────────┤
    │ PDB=2DEF, UniProt=P00183, CCD=CAM    │
    │         分辨率=2.40Å                  │
    ├──────────────────────────────────────┤
    │ PDB=3GHI, UniProt=P00183, CCD=CAM    │
    │         分辨率=3.10Å                  │
    └──────────────────────────────────────┘
                    │
                    │ 按分辨率排序，保留最小值
                    ▼
    ┌──────────────────────────────────────┐
    │ PDB=1ABC, UniProt=P00183, CCD=CAM    │
    │         分辨率=1.80Å  ← 保留这条！    │
    └──────────────────────────────────────┘

    为什么选分辨率最小的？
    · 分辨率数值越小，结构越清晰
    · 1.5Å 比 2.5Å 清晰得多
    · 高质量结构 = 更可靠的原子坐标
```

**数量变化**：1,370 → **930** （去掉440条重复）

---

#### 3.2.5 【步骤4】排除ESIBank交集：930 → 740

**做什么**：排除与EZSpecificity训练集(ESIBank)重叠的数据。

**为什么要排除**：这是机器学习的"红线"！
- ESIBank是模型训练时已经"看过"的数据
- 如果测试集里有训练集的数据，模型的高分是因为"记住了"而不是"学会了"
- 这叫**数据泄露(Data Leakage)**，会导致评估结果虚高

```
ESIBank排除逻辑（PDB级别严格排除）：

    为什么要"PDB级别"严格排除？
    ┌─────────────────────────────────────────────────┐
    │  问题场景：一个PDB有两个UniProt                  │
    │                                                 │
    │  PDB 7M8I 包含：                                │
    │    · UniProt P10109 (酶A) ← 不在ESIBank        │
    │    · UniProt P19099 (酶B) ← 在ESIBank！        │
    │                                                 │
    │  如果只按UniProt排除：                          │
    │    · P19099相关记录被排除 ✓                    │
    │    · P10109相关记录被保留 ✗ 危险！             │
    │                                                 │
    │  问题：这两个酶来自同一个物理结构！              │
    │        P10109的结构特征和P19099高度相关         │
    │        等于间接泄露了训练数据                    │
    └─────────────────────────────────────────────────┘
              │
              ▼
    ┌─────────────────────────────────────────────────┐
    │  解决方案：PDB级别严格排除                       │
    │                                                 │
    │  规则：只要一个PDB里有任何一个UniProt在         │
    │        ESIBank中，整个PDB都排除！               │
    │                                                 │
    │  结果：7M8I整体被排除，两个UniProt的记录都删    │
    └─────────────────────────────────────────────────┘
```

**数量变化**：
- 记录级：930 → **740** （删除190条）
- PDB级：**259个PDB被完全排除**

## 第七章：术语词典

| 术语 | 全称/含义 | 例子 | 在本项目中的作用 |
|------|----------|------|-----------------|
| **PDB** | Protein Data Bank | 1ABC.pdb | 蛋白质3D结构文件 |

| **CCD** | Chemical Component Dictionary | CAM, HEM | 配体的三字母代码 |

| **分辨率(Resolution)** | 结构清晰度(Å) | 1.5, 2.0 | 数值越小越好 |

| **ESIBank** | EZSpecificity训练数据 | - | 需要排除以防数据泄露 |

## 第八章：常见问题解答

### Q1: 为什么v2的数据量从158变成627？

**答**：因为去冗余规则改变了。
- v1：每个酶(UniProt)只保留1个结构 → 158个
- v2：每个(酶+配体)组合保留1个结构 → 627个
- 同一个酶如果和不同配体结合，在v2中会产生多条记录

### Q2: 448个Unknown配体怎么处理？

**答**：暂时不进入B1/B2/B3方案。
- 这些配体需要人工查阅文献确定它们是底物、产物还是抑制剂
- 确认后可以补充到相应的B方案中
- 即使不处理，B3方案也有292条数据，足够进行模型评估

### Q3: 为什么要排除ESIBank的数据？

**答**：防止数据泄露。
- ESIBank是EZSpecificity模型的训练数据
- 如果测试集和训练集有重叠，模型会"认出"这些数据
- 这会导致评估结果虚高，不能反映真实预测能力
- 我们采用PDB级别严格排除，确保测试集完全独立

### Q4: 实验二v2做了什么，没做什么？

**答**：
- **做了**：处理CSV元数据，确定要用哪些数据，生成B1/B2/B3清单
- **没做**：提取配体SMILES（这是PathA Step 3的任务）
- **已完成**：PathA Step 1（下载PDB）、Step 2（提取酶序列）
- **下一步**：执行Step 3（提取配体SMILES）
