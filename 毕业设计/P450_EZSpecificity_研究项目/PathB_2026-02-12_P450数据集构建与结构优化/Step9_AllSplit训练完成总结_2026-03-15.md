## 关键发现 ⚠️

### 1. 设备瓶颈：LMDB mmap 内存抖动
```
Windows 32GB RAM vs 60GB LMDB 缓存
├── 初期速度 (ep0-3):   4.5-5.5 it/s
├── 中期衰减 (ep8-12):  3.0 it/s (-45%)
├── 后期崩溃 (ep14-27): 2.09 it/s (-62%)
├── 根因: mmap thrashing，99% page cache hit rate，活跃swap使用
└── 解决: Phase 1 构建.pt预处理 → 65GB三层存储结构
```

### 2. Edge Fix 已在基线中 🚨
```
Step 9 baseline 当前状态:
├── EdgeConnection bug fixed: 是 (monkey-patch在ep0前)
├── 意义: ep14 AUC=0.7667 = "论文架构 + edge fix"，非纯复现
├── 问题: 无法与论文单seed对比
├── 解决: Phase 2 运行"不修复edge bug"对照实验
└── 预期delta: 0.005-0.015 (取决于edge bug的真实影响)
```

### 3. 数据泄露检测 ⚠️
```
底物级别 (Morgan指纹):
├── 泄露数量: 585条 (6.56%)
├── 泄露形式: brenda测试集底物 = Esterase训练集底物 (不同酶/底物索引)
├── 内部检查: 每个数据集内部干净 (索引0重叠)
├── 综合影响: AUC 0.7667 实际上是 "未知酶 + 部分已知底物"
├── 严重程度: 可能高估+0.01-0.04
└── 解决: Phase 3 分离泄露/清洁子集，量化膨胀量

酶级别:
├── 泄露数量: 27条 (0.15%) — 可忽略
└── 结论: 酶级别干净，主要问题在底物
```

## 速度分析与性能优化

### 配置对比测试
| 配置 | 速度 | 问题 | 备注 |
|------|------|------|------|
| Cached + float32 + 2w | 3.8→2.09 | mmap decay | 当前配置 |
| Uncached + fp16 + 6w | 1.35 it/s | fp16精度损失 | 更差 |
| Uncached + float32 + 6w | 4.3 it/s | Uncached失败 | 无法用 |
| **理想(.pt方案)** | **3-4 it/s** | 无mmap | Phase 1构建 |

### 三大瓶颈
1. **LMDB mmap thrashing** (最严重, 59%)
   - Windows 32GB RAM < 60GB LMDB
   - readahead=False 已实现，但无法根治
   - 解决: .pt分层存储 (3-4 it/s目标)

2. **CPU k-NN 负重** (25%)
   - EdgeConnection scipy k-nearest-neighbor
   - 数据加载时间 50-70% 用于图构建
   - 解决: GPU k-NN 或 预计算edge_index (Phase 1)

3. **GPU idle pattern** (16%)
   - 1.8M参数GNN计算快 (2-3s/batch)
   - 等待数据 (2-3s/batch)
   - 脉冲模式: GPU busy → idle → busy
