# EZSpecificity 模型完整流程图解（新手版）

## 一、模型要解决什么问题

```
已知：一个酶（蛋白质）  +  一个底物（小分子化合物）
问题：这个酶能不能催化这个底物发生反应？

模型输出：一个分数
  分数 > 0 → 模型认为"能催化"
  分数 < 0 → 模型认为"不能催化"
  分数的绝对值越大 → 模型越有把握
```

这是一个**二分类问题**：对每一对酶-底物，判断"能"或"不能"。

---

## 二、模型需要什么输入数据

模型不能直接读入一段蛋白质序列或一个分子式。它需要的是**数值化的特征**——把生物学信息转换成一组组数字。

本模型从三个角度描述一对酶-底物：

```
┌──────────────────────────────────────────────────────────────────┐
│                   一个酶-底物对的三种描述                           │
│                                                                  │
│  ① 序列信息（蛋白质序列）                                         │
│     酶由氨基酸组成，序列就是氨基酸的排列顺序                       │
│     例如：MATLK...（几百到上千个字母）                             │
│     包含信息：酶的身份、功能域、进化关系                            │
│                                                                  │
│  ② 结构信息（3D 对接复合物）                                      │
│     酶和底物在三维空间中的结合姿态（来自分子对接模拟）              │
│     包含信息：酶的活性口袋形状、底物的结合位置、                    │
│              哪些原子之间距离近（可能有相互作用）                    │
│                                                                  │
│  ③ 分子信息（底物的化学性质）                                      │
│     底物的分子式（SMILES 格式，例如 CC(=O)O 代表乙酸）             │
│     包含信息：底物的化学结构、官能团、物化性质                      │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

**为什么需要三种？** 每种描述捕捉不同层面的信息：
- 序列信息告诉模型"这是什么酶"
- 结构信息告诉模型"酶和底物在空间上怎么结合"
- 分子信息告诉模型"这是什么底物"

如果只用一种，模型就缺失了其他层面的信息。

## 三、数据预处理：把原始数据变成数字

原始数据（序列、3D 结构、分子式）不能直接输入模型。需要先用专门的工具把它们转换成数字向量。这一步叫**特征提取**，只需做一次，结果保存下来反复使用。

```
原始数据                 特征提取工具              数字化的特征
─────────────────────────────────────────────────────────────

蛋白质序列               ESM-2 蛋白质语言模型       每个氨基酸 → 一个 1280 维向量
"MATLK..."              （预训练的大模型，          整条序列 → 一组向量
                          类似 GPT 之于文本，       （一条 500 残基的序列
                          ESM 之于蛋白质序列）        = 500 个 1280 维向量）

                                │
                                ▼

对接复合物 PDB            BioPython + RDKit          蛋白质口袋原子的 3D 坐标
（3D 结构文件）           （BioPython 解析蛋白质      底物原子的 3D 坐标
                          部分的原子坐标；            原子之间的距离和键连接关系
                          RDKit 解析底物部分
                          的原子坐标和化学键；
                          "口袋"= 底物周围 10Å
                          范围内的蛋白质原子）

                                │
                                ▼

底物分子式 SMILES         GROVER 分子语言模型        每个原子 → 一个 2400 维向量
"CC(=O)O"               （类似 ESM，但是针对        整个分子 → 一个 4885 维向量
                          小分子预训练的模型）

                         RDKit 化学信息学工具        Morgan 指纹：1024 位的 0/1 向量
                         （基于规则的分子描述）       （描述分子中有哪些子结构）
```

**什么是"维"？** 一个 1280 维的向量就是 1280 个数字排成一列。每个数字从不同角度描述这个氨基酸的性质。维度越高，描述越细致，但计算量也越大。

**什么是"预训练语言模型"？** ESM-2 和 GROVER 都是在大量已知数据上提前训练好的模型。ESM-2 学习了数百万条蛋白质序列的规律，所以它输出的向量能捕捉到氨基酸的生化性质、在序列中的上下文等丰富信息。我们不需要重新训练它们，直接拿来用。

## 四、模型内部：从特征到预测

**重要前提**：本章讲的所有内容，都发生在模型的一次前向计算（SS.forward()）内部。训练时，这个前向计算会被反复调用几十万次——每次拿一批数据跑一遍第四章的全过程，算出预测分数，然后由训练框架（第五章）计算误差并调整参数。

预处理完成后，所有特征被打包成一个 batch（一批 16 个酶-底物对），送入模型。

上图中 ★ 标记的层在论文图中都看不到，但在代码中实际存在：

| 省略的层 | 作用 | 为什么需要 |
|---------|------|-----------|
| 线性层 1280→128 | ESM 输出降维 | ESM 输出 1280 维太大，统一到 128 维 |

| 线性层 4885→128、1024→128 | 全局分子特征降维 | 同上 |
| LayerNorm | 归一化，稳定训练 | 防止不同特征的数值范围差异太大 |
| 聚合器 MLP | 合并结构+分子原子特征 | 两种特征需要融合成统一表示 |
| 原子嵌入表 | 原子类型→向量 | GNN 需要初始节点特征 |
| 边特征构建（RBF+键类型） | 编码原子间关系 | GNN 需要边信息 |
| 注意力门控 | EGNN 中给边消息加权 | 让重要的边贡献更大 |
| 残差连接 | GNN 每层输出 = 输入 + 更新 | 防止深层网络信息丢失 |
| Dropout 90% | 交叉注意力中随机丢弃连接 | 防止过拟合（但 90% 极其激进） |
| 掩码均值池化 | 忽略填充位置取平均 | 不同样本长度不同，填充位不应参与计算 |
| 预测头 MLP 3层 | 从 896 维到 1 维 | 论文只画了一个圆，实际是 3 层网络 |

### 4.1 序列通道：处理蛋白质序列

```
输入：ESM 嵌入（每个氨基酸 1280 维）
      例：一个 500 残基的酶 → 500 个 1280 维向量

         ┌───────────────────────────────────────────┐
         │    通过一个线性层（Linear Layer）降维         │
         │                                           │
         │  1280 维太大了，后续计算会很慢。             │
         │  用一个线性层把每个向量从 1280 维             │
         │  压缩到 128 维，保留最重要的信息。            │
         │                                           │
         │  什么是线性层？                              │
         │  神经网络最基本的组件。                       │
         │  它做的计算是 y = Wx + b，其中：             │
         │    x = 输入向量（1280 维）                   │
         │    W = 权重矩阵（128×1280，可学习）          │
         │    b = 偏置向量（128 维，可学习）             │
         │    y = 输出向量（128 维）                    │
         │  W 和 b 是模型参数，训练时自动调整。          │
         └───────────────────────────────────────────┘

输出：酶的特征（每个氨基酸 128 维）
      例：500 残基 → 500 个 128 维向量

      由于不同酶的长度不同，统一填充到 1450 个位置。
      不足的位置用 0 填充，后续计算时用掩码忽略这些位置。
```

这一步很简单：只做了一次降维。ESM 已经把"蛋白质序列的含义"编码进了向量里，这里只是把维度压缩到适合后续处理的大小。

---

### 4.2 结构通道：处理 3D 对接结构

这是模型中最复杂的部分。它用**图神经网络（GNN）**处理三维结构。

#### 4.2.1 把 3D 结构变成"图"

首先要理解什么是"图"。这里的图不是图片，而是数学中的图结构：

```
图 = 一组节点 + 一组连接节点的边

在本模型中：
  节点 = 原子（蛋白质口袋的原子 + 底物的原子）
  边   = 原子之间的关系

原子之间什么情况下会连一条边？两种情况：
  1. 化学键：原子之间有共价键连接（单键、双键、三键、芳香键）
  2. 空间近邻：两个原子在 3D 空间中距离很近（每个原子连接距离最近的 48 个原子）

        蛋白质口袋原子                 底物原子
        ●─●─●                         ●═●
        │ │ │    ← 化学键 →            │ │
        ●─●─●                         ●─●
           ╲  ╲                      ╱ ╱
            ╲  ╲  ← 空间近邻边 →  ╱ ╱
             ╲  ╲              ╱ ╱
              ╲  ● ─ ─ ─ ─ ● ╱    ← 蛋白质和底物之间
               ╲          ╱           也有空间近邻边！
                ● ─ ─ ─ ●            这让模型能学到
                                      它们之间的相互作用

  空间近邻边是模型学习酶-底物交互的基础：
  酶口袋的某个原子和底物的某个原子距离很近 → 连一条边 → 模型能学到这种空间接触
```

每个节点（原子）需要一个**初始特征向量**才能进入 GNN。这个特征不是直接查一张嵌入表，而是分两步生成的：

**第一步：拼接 one-hot 特征（FeaturizeProteinAtom / FeaturizeLigandAtom）**

对蛋白质侧的每个原子，把三种信息拼接成一个向量：

```
蛋白质原子特征 = [元素 one-hot] + [氨基酸 one-hot] + [是否骨架]
                    6 维              21 维             1 维
                  = 共 28 维

  元素 one-hot（6 种）：H(氢), C(碳), N(氮), O(氧), S(硫), Se(硒)
    例：碳原子 → [0,1,0,0,0,0]
    例：氮原子 → [0,0,1,0,0,0]

    注意：没有 Fe(铁)！Fe 原子的编码会变成全零 [0,0,0,0,0,0]。
    这是 P450 研究中发现的一个已知局限。

  氨基酸 one-hot（21 种）：ALA, CYS, ASP, ..., TYR, UNK
    例：丙氨酸(ALA)的原子 → [1,0,0,...,0]（第 0 位为 1）
    例：未知残基的原子     → [...,0,0,1]（最后一位 UNK 为 1）

    注意：没有 HEM(血红素)！血红素原子只能被标为 UNK（未知）。

  是否骨架（1 维）：主链原子(CA,C,N,O)=1，侧链原子=0
```

对底物（配体）侧的每个原子，编码方式不同：

```
底物原子特征 = [元素 one-hot] + [原子属性 one-hot]
                  11 维              若干维

  元素 one-hot（11 种）：H, C, N, O, F, P, S, Cl, Fe, Br, I
    底物侧的元素表比蛋白质侧更丰富，包含了 Fe。
    这是因为论文作者考虑了有机化学中可能出现的金属配体。

  原子属性：原子序数、芳香性、度数、氢原子数、杂化类型
```

**第二步：线性层投射到 128 维（structure.py）**

```
蛋白质：28 维 one-hot → nn.Linear(28, 128) → 128 维向量
底物：  N 维 one-hot  → nn.Linear(N, 128)  → 128 维向量
```

nn.Linear 是一个可学习的线性变换（y = Wx + b），权重 W 在训练中自动调整。
这一步把稀疏的 one-hot 编码转换成稠密的 128 维表示，类似于 NLP 中的词嵌入。

投射完成后，蛋白质原子和底物原子都变成了 128 维向量，可以在同一张图中统一处理。

**总结：原子初始特征的生成流程**

```
蛋白质原子 → FeaturizeProteinAtom → 28维 → nn.Linear(28,128) → 128维 → 进入EGNN
底物原子   → FeaturizeLigandAtom  → N维  → nn.Linear(N,128)  → 128维 → 进入EGNN
```

代码位置：
- one-hot 拼接：`src/Datasets/Structure/transforms.py` 第 19-36 行
- 线性层投射：`src/Models/Structure/structure.py` 第 37-38 行
- 线性层的输入维度从 `FeaturizeProteinAtom().feature_dim` 动态读取，不是硬编码

**Fe 缺失的具体后果**：当蛋白质结构中出现 Fe 原子时，代码会将其原子序数（26）逐个与已知的 6 种元素比较，全部不匹配，得到全零的元素编码 `[0,0,0,0,0,0]`。同时血红素残基(HEM)不在氨基酸表中，被标为 UNK。Fe 原子仍然作为节点留在图中（有坐标、有边连接），但模型无法区分它和其他未知原子。

这对 P450 酶的影响尤其严重：P450 的催化核心是血红素（Heme）辅因子，其中心就是一个 Fe 原子。在本项目的 P450 研究中，实验对比了保留 Heme 与去除 Heme 两种配置：

| 配置 | AUC-ROC |
|------|---------|
| 10Å 口袋 / 不含 Heme | 0.7115 |
| 10Å 口袋 / 含 Heme | 0.4793（比随机猜还差） |

包含 Heme 导致性能暴跌 0.23，因为 Fe 的全零表示给模型引入了严重噪声。当前的处理办法是预处理时直接去掉 Heme 原子（noHeme 配置），牺牲催化中心信息以避免错误表示的干扰。

每条边也有一个**边特征**（39 维）：
- 键类型（6 维）：是单键？双键？还是空间近邻？
- 距离编码（32 维）：两个原子的距离，用高斯函数编码成 32 个数字
- 是否跨分子（1 维）：这条边连接的是同一个分子内的原子，还是蛋白质和底物之间的原子？

建图时还会生成**掩码**（mask）——一个标记列表，记录每个原子的身份。因为建图时底物原子排在前面、蛋白质原子排在后面，所以掩码就是按位置标记：

```
假设底物有 3 个原子，蛋白质口袋有 2 个原子：

底物掩码 = [1, 1, 1, 0, 0]   ← 前 3 个是底物
蛋白质掩码 = [0, 0, 0, 1, 1]   ← 后 2 个是蛋白质
```

后续需要"只取底物原子"或"只取蛋白质原子"时，用掩码筛选即可。

#### 4.2.2 图神经网络（GNN）：在图上传递信息

图建好后，用 GNN 处理它。GNN 的核心思想是**消息传递**：

```
消息传递（一轮）：

  对图中的每个原子，执行以下操作：

  1. 收集邻居信息
     找到所有和我相连的邻居原子
     对每个邻居，把三样东西拼成一个长向量：
       [我的特征(128维) + 邻居的特征(128维) + 我和邻居之间的边特征(39维)]
       = 一个 295 维的向量

     把这个 295 维向量送入一个 2 层 MLP（多层感知机），压缩成 128 维的"消息"
     （MLP 内部的详细计算过程见 4.2.2a 的方块流程图）

  2. 汇总消息
     把所有邻居发来的消息（每条 128 维）加在一起
     得到一个 128 维向量，代表这个原子从所有邻居那里收到的信息总和

  3. 更新自己
     把消息总和(128维) 和自己的特征(128维) 拼成 256 维
     送入另一个 2 层 MLP，压缩成 128 维的更新量
     最终：新特征 = 原特征 + 更新量（残差连接，保留原始信息）
     （详见 4.2.2a 步骤 4 的方块流程图）

  举例：
  ┌──────────┐
  │ 底物碳原子 │ ← 更新前：只知道自己是碳原子
  └─────┬────┘
        │  收集邻居消息
        ├──── 邻居1（底物氧原子，双键相连，距离 1.2Å）
        ├──── 邻居2（底物氢原子，单键相连，距离 1.1Å）
        └──── 邻居3（酶的赖氨酸氮原子，空间近邻，距离 3.5Å）
        │
        ▼  汇总 + 更新
  ┌──────────┐
  │ 底物碳原子 │ ← 更新后：知道自己旁边有氧（可能是羰基），
  └──────────┘           还靠近酶的赖氨酸（可能有氢键作用）
```

本模型做 **3 轮**消息传递。每一轮，信息都会向外扩散一步：
- 第 1 轮后：每个原子知道直接邻居的信息
- 第 2 轮后：每个原子知道 2 步以内邻居的信息
- 第 3 轮后：每个原子知道 3 步以内邻居的信息

**为什么一轮 = 扩散一步？** 因为每轮只在直接相连的邻居之间传递信息。多轮的效果是**间接传递**：

```
假设有三个原子连成一条链：A ── B ── C

第 1 轮：
  A 收集邻居 B 的信息 → A 的特征融入了 B 的信息
  B 收集邻居 A 和 C 的信息 → B 的特征融入了 A 和 C 的信息

第 2 轮：
  A 再次收集 B 的信息，但此时 B 的特征里已经包含了第 1 轮中从 C 获得的信息
  → A 间接地获得了 C（2 步之外）的信息

所以每多做一轮，每个原子的"感知范围"就向外扩展一步。
3 轮后，每个原子能感知到 3 步以内所有邻居的信息。
```

3 轮之后，每个原子的特征向量不再只代表它自己，而是融合了周围局部环境的信息。

#### 4.2.2a 每一轮消息传递的内部细节

上面 4.2.2 描述了"收集→汇总→更新"的大致过程，实际每一轮还有一个上面没提到的重要机制——**注意力门控**。下面是包含注意力门控的完整流程：

以原子 A 为例，假设 A 有 3 个邻居（B、C、D）。

**步骤 1：边 MLP — 为每条边计算一条消息**

对 A 的每个邻居（B、C、D），分别做一次下面的计算：

```
A的特征(128) + 邻居特征(128) + 边特征(39) = 拼接(295)

┌─────────┐      ┌──────────────┐      ┌──────┐      ┌──────────────┐      ┌──────┐      ┌─────────┐
│  输入    │      │    线性层     │      │      │      │    线性层     │      │      │      │  输出   │
│  295维   │─────→│ W1: 128×295  │─────→│ ReLU │─────→│ W2: 128×128  │─────→│ ReLU │─────→│  消息   │
│          │      │ b1: 128维    │      │      │      │ b2: 128维    │      │      │      │  128维  │
└─────────┘      └──────────────┘      └──────┘      └──────────────┘      └──────┘      └─────────┘
```

A 有 3 个邻居，所以得到 3 条消息，每条 128 维。

**步骤 2：注意力门控 — 给每条消息一个 0~1 的重要性权重**

对每条消息分别做：

```
┌─────────┐      ┌─────────────┐      ┌─────────┐      ┌──────────────┐
│  输入    │      │   线性层     │      │         │      │    输出      │
│  消息    │─────→│ W3: 1×128   │─────→│ Sigmoid │─────→│    权重      │
│  128维   │      │ b3: 1维     │      │         │      │ 1个数(0~1)  │
└─────────┘      └─────────────┘      └─────────┘      └──────────────┘

Sigmoid 是一种激活函数（和 ReLU 同类），区别是它把输出压缩到 0~1 之间，适合产生"比例/权重"。
128 个数字经过线性层压缩成 1 个数字，再被 Sigmoid 压到 0~1 之间，作为这条消息的重要性权重。

加权消息 = 消息(128维) × 权重
```

3 条消息各自得到一个权重，例如：
- A─B 消息 × 0.91（重要边）
- A─C 消息 × 0.12（不重要边）
- A─D 消息 × 0.67（中等）

**步骤 3：汇总 — 加权消息求和**

```
A─B 加权消息(128) + A─C 加权消息(128) + A─D 加权消息(128)
    = 消息总和(128)
```

权重大的消息贡献大，权重小的贡献小。

**步骤 4：节点 MLP — 更新原子 A 的特征**

```
消息总和(128) + A当前特征(128) = 拼接(256)

┌─────────┐      ┌──────────────┐      ┌──────┐      ┌──────────────┐      ┌─────────┐
│  输入    │      │    线性层     │      │      │      │    线性层     │      │  输出   │
│  拼接    │─────→│ W4: 128×256  │─────→│ ReLU │─────→│ W5: 128×128  │─────→│ 更新量  │
│  256维   │      │ b4: 128维    │      │      │      │ b5: 128维    │      │  128维  │
└─────────┘      └──────────────┘      └──────┘      └──────────────┘      └─────────┘
```

**步骤 5：残差连接**

```
A 的新特征 = A 的原特征(128) + 更新量(128)
```

不是替换，是相加。即使更新量学偏了，原始信息也不会丢失。

#### 4.2.2b 与论文 Fig.1 的对应关系

论文 Fig.1 画了两个独立的 MPNN 模块：**Internal MPNN** 和 **Interaction MPNN**。代码只用了**一个 EGNN**。下面用一个具体例子说明它们的关系。

假设底物有 3 个原子（S1、S2、S3），酶口袋有 2 个原子（P1、P2）。
S1─S2 之间有化学键（双键），S2─S3 之间有化学键（单键）。
同时 S1 和 P1 在 3D 空间中距离很近（3.2Å），S3 和 P2 距离很近（4.1Å）。

论文的画法 — 分成两个独立网络分别处理：

  ┌───────────────────────────────┐

  │                               │
  │    S1 ═══ S2 ─── S3           │    S1─S2: 双键

  ┌───────────────────────────────┐
  │      Interaction MPNN         │    只看酶和底物之间的空间接触
  │                               │
  │    P1 ╌╌╌ S1    P2 ╌╌╌ S3    │    P1─S1: 距离 3.2Å
  │    (3.2Å)       (4.1Å)       │    P2─S3: 距离 4.1Å

  └───────────────────────────────┘

代码的做法 — 把所有边放进同一张图，用一个 EGNN 一次处理：

  ┌───────────────────────────────────────────┐
  │              一个 EGNN                     │
  │                                           │
  │    P1 ╌╌╌╌╌ S1 ═══ S2 ─── S3 ╌╌╌╌╌ P2   │
  │    (近邻边)  (化学键边)  (化学键边) (近邻边) │
  │                                           │
  │    4 条边混在一起，但每条边的 39 维特征      │

#### 4.2.3 结构通道的两个输出

沿用 4.2.2b 的例子。EGNN 3 轮消息传递结束后，5 个原子各自有一个 128 维特征向量：

```
EGNN 输出（5 个原子，每个 128 维）：

  P1 的特征 [128维]  ← 蛋白质口袋原子
  P2 的特征 [128维]  ← 蛋白质口袋原子
  S1 的特征 [128维]  ← 底物原子
  S2 的特征 [128维]  ← 底物原子
  S3 的特征 [128维]  ← 底物原子

从这 5 个向量中，提取两个输出：
```

**输出 1：底物原子级特征**

用 4.2.1 中建图时生成的底物掩码，只保留底物原子（S1、S2、S3），丢弃蛋白质原子（P1、P2）。

```
底物掩码 = [0, 0, 1, 1, 1]  （P1=0, P2=0, S1=1, S2=1, S3=1）

保留掩码为 1 的原子 → S1、S2、S3 的特征向量，每个 128 维
用途：后续和分子通道合并，参与交叉注意力（4.4 节）
```

**输出 2：全局结构特征（str_mean）**

把所有 5 个原子的特征取平均，压缩成 1 个向量。

```
str_mean = (P1特征 + P2特征 + S1特征 + S2特征 + S3特征) ÷ 5
         = 1 个 128 维向量

这个向量概括了整个复合物（酶口袋+底物）的 3D 结构信息。
用途：跳过交叉注意力，直接拼接到最终的 896 维向量中参与预测
     （见 4.0 总览图中 str_mean 的箭头直接指向 ⑧）
```

**为什么只提取底物原子，丢弃酶原子？——架构的不对称性**

EGNN 处理完后，酶的口袋原子也有更新后的 128 维特征，但模型没有使用它们。这导致了一个不对称：

```
底物这边：结构通道(原子级) + 分子通道(原子级) → 合并 → 参与交叉注意力
酶这边  ：只有序列通道(残基级)                 → 直接参与交叉注意力
          结构通道算出的酶原子特征 → 丢弃
```

根本原因是**粒度不匹配**：序列通道是残基级的（1 个氨基酸 = 1 个向量），结构通道是原子级的（1 个原子 = 1 个向量，一个氨基酸有 5~20 个原子）。底物没有这个问题——②③ 都是原子级的，可以直接拼接合并。

这是一个潜在的改进方向：如果把酶的原子级结构特征按残基分组取平均，聚合回残基级，就可以和 ESM 残基特征合并，让酶也同时拥有序列+结构两份信息。但当前模型没有做这一步。

### 4.3 分子通道：处理底物的化学信息

分子通道从化学角度描述底物。分为**原子级**（每个原子一个向量）和**全局级**（整个分子一个向量）两个层次。

#### 4.3.1 原子级：GROVER 原子嵌入

GROVER 预训练模型为底物的每个原子生成一个 2400 维向量，描述该原子的化学环境（原子类型、连接的基团、所处的化学环境等）。

2400 维太大，需要降维到 128 维。这里用的是**单层线性层**（不是 MLP）：

```
┌──────────────┐      ┌──────────────┐      ┌───────────┐      ┌──────────────┐
│    输入      │      │   线性层      │      │           │      │    输出      │
│  GROVER嵌入  │─────→│ W: 128×2400  │─────→│ LayerNorm │─────→│  原子级     │
│  2400维      │      │ b: 128维     │      │           │      │  分子特征    │
│  (每个原子)   │      │              │      │           │      │  128维      │
└──────────────┘      └──────────────┘      └───────────┘      └──────────────┘

和 MLP 的区别：这里只有 1 层线性层，没有激活函数（ReLU），没有第 2 层。
计算方式和 4.2.2a 中的线性层完全相同：y = Wx + b。
W 和 b 是模型参数，在训练中自动学习。
```

**为什么这里是单层线性层 + LayerNorm，而 EGNN 用多层 MLP 且不需要 LayerNorm？**

关键区别在于**合并的时机不同**：

**EGNN 的做法：先拼接，再处理**

```
我的特征(128维) ─┐
邻居特征(128维) ─┼─→ 拼接成 295维 → 同一个 MLP 处理 → 128维
边特征  (39维)  ─┘
```

三种信息在进 MLP **之前**就合并成一个向量了。MLP 同时看到所有信息，可以学习它们之间的复杂关系（比如"当边类型是双键且邻居是氧原子时，消息应该更强"）。这需要多层 + 激活函数才能做到，单层线性层只能做加权求和。而且因为只有一个 MLP 统一处理，不存在"多条通路数值范围不一致"的问题，所以不需要 LayerNorm。

**GROVER/Morgan 的做法：先各自处理，再合并**

```
GROVER原子(2400维) → 线性层A → LayerNorm → 128维 ─┐
GROVER全局(4885维) → 线性层B → LayerNorm → 128维 ─┼─→ 后续合并使用
Morgan指纹 (1024维) → 线性层C → LayerNorm → 128维 ─┘
```

三条通路**各自独立**，每条只做降维（高维压缩到 128 维）。输入本身已经是预训练模型或化学规则算好的高质量特征，不需要学复杂变换，一层 y = Wx + b 就够了。

但三种输入的数值范围天差地别（GROVER 浮点数可能在 [-5, +5]，Morgan 全是 0 或 1），各自经过线性层后输出大小也很不一样：

```
通路A输出（来自GROVER）：[12.5, -8.3, 15.1, ...]  ← 数值大
通路C输出（来自Morgan）：[ 0.3, -0.1,  0.5, ...]  ← 数值小
```

后续合并时，数值大的通路会**压制**数值小的——不是 Morgan 信息不重要，纯粹因为数字太小被淹没了。**LayerNorm** 强制把每条通路的输出都调整到均值=0、标准差=1，这样合并时各通路**地位平等**，谁也不会压制谁。

**总结**：先合并再处理 → 用 MLP（需要非线性来学习组合关系，不需要 LayerNorm）；先各自处理再合并 → 用单层线性层（只需降维）+ LayerNorm（统一数值范围）。不过这也是作者的设计选择，并非唯一方案。

结果：每个底物原子一个 128 维向量。后续在 4.4 中和结构通道的原子级特征合并。

#### 4.3.2 全局级：GROVER 全局嵌入 + Morgan 指纹

全局级描述的是**整个分子**（不是单个原子），有两个来源。它们的核心区别：

- **GROVER 全局嵌入**：由 GROVER 预训练模型生成（和 4.3.1 的原子嵌入来自同一个模型）。它通过神经网络从分子的图结构中**学习**出来，能捕捉到原子之间的远程依赖关系（比如分子两端的基团如何相互影响）。输出一个 4885 维向量。
- **Morgan 指纹**：由化学规则直接计算（不需要训练）。做法是：以每个原子为中心，向外扩展 2 步，把遇到的原子类型和键类型组合编码成一个 1024 位的 0/1 向量。每一位代表"分子中是否存在某种特定子结构"，例如某一位=1 表示有苯环，另一位=1 表示有羟基。

简单说：**GROVER 是神经网络学出来的"软特征"，能捕捉复杂的全局模式；Morgan 是规则算出来的"硬特征"，直接列举分子有哪些子结构**。两者互补——GROVER 可能遗漏简单的局部子结构，Morgan 可能捕捉不到远程依赖。

两者各自经过线性层 + LayerNorm 压缩到 128 维：

```
┌──────────────┐      ┌──────────────┐      ┌───────────┐      ┌──────────────┐
│    输入      │      │   线性层      │      │           │      │    输出      │
│  GROVER全局  │─────→│ W: 128×4885  │─────→│ LayerNorm │─────→│  全局分子   │
│  4885维      │      │ b: 128维     │      │           │      │  特征       │
│  (整个分子)   │      │              │      │           │      │  128维      │
└──────────────┘      └──────────────┘      └───────────┘      └──────────────┘

┌──────────────┐      ┌──────────────┐      ┌───────────┐      ┌──────────────┐
│    输入      │      │   线性层      │      │           │      │    输出      │
│ Morgan指纹   │─────→│ W: 128×1024  │─────→│ LayerNorm │─────→│  指纹特征   │
│  1024维      │      │ b: 128维     │      │           │      │  128维      │
│  (整个分子)   │      │              │      │           │      │             │
└──────────────┘      └──────────────┘      └───────────┘      └──────────────┘
```

这两个全局级 128 维向量**不经过交叉注意力**，直接拼接到最终的 896 维向量中参与预测（见 4.0 总览图 ⑦）。

### 4.4 合并底物的原子级特征

到这里，底物的每个原子有两份 128 维的特征：

```
来自结构通道（4.2）：描述这个原子在 3D 空间中的位置和周围环境
来自分子通道（4.3）：描述这个原子的化学性质和在分子中的角色

两者提供不同视角的信息，合并后更全面：

结构特征 [每原子 128 维]  +  分子特征 [每原子 128 维]
                    │                    │
                    └────────┬───────────┘
                             ▼
                     拼接成 [每原子 256 维]
                             │
                             ▼
                   通过一个 MLP（多层感知机：256→128）压缩回 [每原子 128 维]
                             │
                             ▼
                   底物综合原子级特征（x_reaction）
```

**此时模型有两个关键变量：**

```
  酶的特征 x_pro        ← 来自 4.1 序列通道
  每个氨基酸一个 128 维向量（最多 1450 个残基）

  底物的特征 x_reaction  ← 来自 4.2 + 4.3 + 4.4
  每个原子一个 128 维向量（最多 280 个原子）
```

接下来就是让它们互相交换信息。

### 4.5 双向交叉注意力：酶和底物交换信息

这是模型的核心创新。在此之前，酶的特征和底物的特征是完全独立处理的。交叉注意力让它们互相参考对方的信息。

#### 4.5.1 注意力的基本原理

注意力机制做一件事：**从一组向量中，根据相关性选择性地提取信息**。

```
具体过程：

  有两组向量：查询方（Q）和被查询方（K, V）

  对查询方的每一个向量：
    1. 计算它和被查询方每个向量的相关性分数
       （通过向量点积：两个向量越相似，点积越大）
    2. 把相关性分数转换成权重（通过 softmax：所有权重加起来 = 1）
    3. 用这些权重对被查询方的向量做加权平均

  结果：查询方的每个向量获得了一个新向量，
       这个新向量是从被查询方中"选择性提取"的信息，
       越相关的部分贡献越大。

  示意：
  查询方（酶的 3 个残基）        被查询方（底物的 4 个原子）
  ┌────┐                        ┌────┐ ┌────┐ ┌────┐ ┌────┐
  │残基1│── 相关性: 0.7 ────────→│原子A│ │原子B│ │原子C│ │原子D│
  │    │── 相关性: 0.1 ────────→│    │ │    │ │    │ │    │
  │    │── 相关性: 0.15 ───────→│    │ │    │ │    │ │    │
  │    │── 相关性: 0.05 ───────→│    │ │    │ │    │ │    │
  └────┘                        └────┘ └────┘ └────┘ └────┘
     │
     ▼
  残基1 的新向量 = 0.7×原子A + 0.1×原子B + 0.15×原子C + 0.05×原子D
  （主要获取了原子 A 的信息，因为权重最高）
```

#### 4.5.2 本模型的双向交叉注意力

```
方向1：酶查询底物（enzyme_attention）

  查询方 = 酶的每个残基（x_pro）
  被查询方 = 底物的每个原子（x_reaction）

  对酶的每个残基，计算它和底物所有原子的相关性，
  加权提取底物信息。

  效果：酶的每个残基获得了"与它最相关的底物原子的信息"
  例如：酶活性口袋中的一个残基，可能和底物的羰基氧原子高度相关，
       那它就会主要获取那个氧原子的信息。


方向2：底物查询酶（reaction_attention）

  查询方 = 底物的每个原子（x_reaction）
  被查询方 = 酶的每个残基（x_pro）

  对底物的每个原子，计算它和酶所有残基的相关性，
  加权提取酶信息。

  效果：底物的每个原子获得了"与它最相关的酶残基的信息"
```

**为什么要双向？**

单向（只有方向1）只能回答"酶的每个残基关注底物的哪些原子"。双向还能回答"底物的每个原子关注酶的哪些残基"。两个方向捕捉的信息是不同的：
- 方向1 帮助模型理解"酶的活性位点是否适合这个底物"
- 方向2 帮助模型理解"底物的哪些部分被酶识别"

#### 4.5.3 多头注意力

本模型用 **8 个头**并行计算注意力。

每个头把 128 维的向量拆成 16 维（128 ÷ 8 = 16），独立计算注意力。不同的头可以学到不同类型的相关性——例如一个头关注电荷互补，另一个关注空间距离，另一个关注疏水性匹配。

8 个头的结果拼接后再映射回 128 维，综合了多种角度的信息。

### 4.6 池化：从变长序列到固定长度

到目前为止，酶有最多 1450 个残基的特征，底物有最多 280 个原子的特征。但不同样本的酶长度、底物大小都不一样，不能直接对比。

**池化**的作用是把变长的特征序列压缩成一个固定长度的向量：

```
  酶的 1450 个残基特征（128 维/个）
       │
       ▼ 掩码均值池化
       对所有真实残基（排除填充位置）取平均
       │
       ▼
  一个 128 维向量（概括了整个酶的信息）

  底物的 280 个原子特征（128 维/个）
       │
       ▼ 同样取掩码均值
       │
       ▼
  一个 128 维向量（概括了整个底物的信息）
```

交叉注意力的输出也做同样的池化。

池化后，模型手里有以下特征向量：

```
  来源                              维度     含义
  ─────────────────────────────────────────────────────
  ① 酶均值                          128     酶的整体序列特征
  ② 底物均值                        128     底物的整体综合特征
  ③ 交叉注意力输出（酶→底物）均值    128     酶视角下的酶-底物交互
  ④ 交叉注意力输出（底物→酶）均值    128     底物视角下的酶-底物交互
  ⑤ 全局结构特征                    128     3D 复合物的结构概要
  ⑥ GROVER 全局特征                 128     底物的整体分子性质
  ⑦ Morgan 指纹特征                 128     底物的子结构指纹
```

### 4.7 拼接 + 预测头

```
  7 个 128 维向量拼接在一起 → 一个 896 维向量
       │
       ▼
  ┌───────────────────────────────────────────────────┐
  │               预测头（MLP）                         │
  │                                                   │
  │  896 维 → 128 维 → 128 维 → 1 维                  │
  │                                                   │
  │  MLP = 多层感知机，就是多个线性变换叠加，            │
  │  中间插入非线性激活函数（ReLU）。                    │
  │  作用：从 896 维的综合特征中提取最终的判断。          │
  │                                                   │
  │  每一层的意思：                                     │
  │  896→128：压缩，去除冗余信息                        │
  │  128→128：进一步提取模式                            │
  │  128→1  ：输出最终的一个分数                        │
  └───────────────────────────────────────────────────┘
       │
       ▼
  输出：一个分数（logits）
  > 0 表示模型认为"能催化"
  < 0 表示模型认为"不能催化"
```

## 五、训练过程：模型怎么从数据中学习

以上描述的是模型对一批数据做**一次预测**的过程。但一开始，模型的参数是随机初始化的，预测结果基本是乱猜。**训练**就是反复调整参数，让预测越来越准。

### 5.1 一批数据的处理过程

```
一批数据（16 个酶-底物对，每对带有正确答案：0 或 1）
         │
         ▼
    模型做预测（上面第四章的全过程）
    输出 16 个预测分数
         │
         ▼
    计算误差（loss）
    拿 16 个预测分数和 16 个正确答案对比
    使用"二分类交叉熵损失"：
      - 正确答案是 1（能催化），模型的分数越高 → loss 越小
      - 正确答案是 0（不能催化），模型的分数越低 → loss 越小
      - 预测越离谱 → loss 越大
    最终得到一个数字，代表这批数据上预测的总误差
         │
         ▼
    反向传播（计算梯度）
    根据 loss，自动计算"每个参数应该增大还是减小、变化多少才能让 loss 减小"
    这个"方向和幅度"就是梯度。
    这一步由 PyTorch 自动完成（loss.backward()），不需要手动计算。
         │
         ▼
    更新参数
    沿着梯度方向微调所有参数
    调整幅度由"学习率"控制（学习率越大，每次调整越猛）

    注意：本模型每 2 批数据才更新一次参数。
    前一批只计算梯度不更新，和后一批的梯度累加后再一起更新。
    目的：2 批数据的梯度取平均，比 1 批更稳定，方向更准确。
```

### 5.2 一个 Epoch 的完整过程

```
┌───────────────────────────────────────────────────────────────┐
│                    一个 Epoch 的执行流程                        │
│                                                               │
│  ┌──── 训练阶段 ─────────────────────────────────────────┐    │
│  │                                                        │    │
│  │  训练数据（例如 32 万对酶-底物对）                       │    │
│  │  按每批 16 对划分，共约 2 万个 batch                    │    │
│  │                                                        │    │
│  │  对每个 batch 执行 5.1 的过程：                         │    │
│  │  预测 → 算误差 → 算梯度 → （每 2 批）更新参数           │    │
│  │                                                        │    │
│  │  所有 batch 跑完 = 训练数据用了一遍                     │    │
│  │                                                        │    │
│  └────────────────────────────────────────────────────────┘    │
│                          │                                     │
│                          ▼                                     │
│  ┌──── 验证阶段 ─────────────────────────────────────────┐    │
│  │                                                        │    │
│  │  验证数据（模型在训练中从未见过）                        │    │
│  │                                                        │    │
│  │  对每个 batch：                                         │    │
│  │  只做预测，不算梯度，不更新参数                          │    │
│  │                                                        │    │
│  │  所有 batch 跑完后，汇总计算指标：                       │    │
│  │                                                        │    │
│  │  AUC-ROC（面积 under ROC 曲线）                         │    │
│  │    衡量模型区分"能催化"和"不能催化"的总体能力             │    │
│  │    0.5 = 和随机猜一样    1.0 = 完美区分                 │    │
│  │                                                        │    │
│  │  AUPR（面积 under 精确率-召回率曲线）                    │    │
│  │    衡量模型说"能催化"时有多可靠                          │    │
│  │    值越高 = 模型说"能"的时候越准                         │    │
│  │                                                        │    │
│  └────────────────────────────────────────────────────────┘    │
│                          │                                     │
│                          ▼                                     │
│  ┌──── 决策阶段 ─────────────────────────────────────────┐    │
│  │                                                        │    │
│  │  决策1：是否降低学习率？                                 │    │
│  │    如果 AUPR 连续 10 个 epoch 没有提升                  │    │
│  │    → 把学习率减半                                       │    │
│  │    原因：学习率太大可能导致参数在最优解附近来回跳动，      │    │
│  │          减小学习率让调整更精细                           │    │
│  │                                                        │    │
│  │  决策2：是否保存模型？                                   │    │
│  │    如果当前 AUPR 是所有 epoch 中最高的                   │    │
│  │    → 保存模型参数到文件（.ckpt）                         │    │
│  │    原因：训练后期模型可能反而变差（过拟合），              │    │
│  │          保存历史最佳确保不会丢失最好的状态                │    │
│  │                                                        │    │
│  └────────────────────────────────────────────────────────┘    │
│                          │                                     │
│                          ▼                                     │
│                 开始下一个 Epoch                                │
│                                                               │
└───────────────────────────────────────────────────────────────┘

重复直到：
  - 达到最大 epoch 数（例如 200 个），或
  - 模型成绩长期不再提升（early stopping）
```

### 5.3 学习率的变化过程

学习率决定了每次参数更新的步幅大小。本模型的学习率有两个阶段：

```
学习率
  │
  │               3e-4 ──────────────────────────╮
  │             ╱                                 │ 连续 10 个 epoch
  │           ╱                                   │ AUPR 没提升
  │         ╱  预热阶段                           │
  │       ╱    从很小的值慢慢增大                   ▼
  │     ╱      避免一开始步子太大                 1.5e-4 ─────────────╮
  │   ╱        把随机初始化的参数带偏               │                  │
  │ ╱                                              ▼                  ▼
  │╱                                             7.5e-5         ... 继续减半
  │                                                              直到 5e-6
  └───────────────────────────────────────────────────────→ epoch
  0     8

  阶段1（epoch 0-8）：预热
    学习率从 5e-6 线性增大到 3e-4
    目的：模型参数刚开始是随机的，太大的学习率会导致参数剧烈跳动。
    先用小学习率让参数找到大致方向，再逐步加大。

  阶段2（epoch 8 以后）：按需衰减
    如果验证指标持续不提升，就把学习率减半。
    目的：随着训练推进，模型已经接近最优解，
    需要更小的步幅做精细调整，避免在最优解附近来回跳。
```

## 六、为什么验证阶段不更新参数？

这个问题值得单独说清楚。

训练的目标是让模型在**新数据**上表现好，而不只是在训练数据上表现好。

```
如果只看训练数据上的表现：
  模型可能记住了每一个训练样本的答案（过拟合）
  训练数据上 → 准确率 99%
  新数据上   → 准确率 50%（和随机猜一样）

所以需要一组模型从未见过的验证数据来检测：
  如果验证数据上表现也好 → 模型学到了通用规律
  如果验证数据上表现差   → 模型只是在背答案

为什么验证时不能更新参数？
  如果验证时也更新参数，模型就等于"看到了考试题"，
  验证指标就不能真实反映模型在新数据上的能力了。
```

## 七、从预测分数到最终判断

模型输出的是一个原始分数（logits），还需要转换才能得到"能/不能催化"的判断：

```
模型输出: logits（原始分数，范围 -∞ 到 +∞）
    │
    ▼  经过 sigmoid 函数
    概率值（范围 0 到 1）
    例如：0.85 表示 "85% 的概率能催化"
    │
    ▼  设定阈值（通常 0.5）
    最终判断
    概率 > 0.5 → 预测"能催化"
    概率 < 0.5 → 预测"不能催化"

  sigmoid 函数的作用：
    logits =  3  → sigmoid → 0.95（很有把握：能催化）
    logits =  0  → sigmoid → 0.50（完全不确定）
    logits = -3  → sigmoid → 0.05（很有把握：不能催化）
```

注意：训练时 loss 函数内部自带 sigmoid 计算，所以模型直接输出 logits 即可，不需要额外加 sigmoid。

## 附录：术语速查表

本文档中反复出现的技术术语，按功能分类解释。

### A. 激活函数

激活函数的作用是给神经网络引入**非线性**。如果没有激活函数，不管堆多少层线性层，效果都等价于一层（因为线性变换的叠加还是线性变换）。激活函数让网络能学到"如果 A 且 B 则 C"这种复杂的逻辑，而不仅仅是加权求和。

**ReLU（Rectified Linear Unit，修正线性单元）**

```
规则：如果输入 ≥ 0，输出不变；如果输入 < 0，输出变成 0

举例：
  输入：[ 3.2, -1.5,  0.7, -0.3,  2.1]
  输出：[ 3.2,  0.0,  0.7,  0.0,  2.1]
       （负数全部变成 0，正数原样保留）
```

用途：本模型中 EGNN 的 MLP 和预测头 MLP 都使用 ReLU 作为层与层之间的激活函数。

**Sigmoid**

```
规则：把任意数字压缩到 0~1 之间。越大的正数越接近 1，越小的负数越接近 0

举例：
  输入  3  → 输出 0.95（接近 1）
  输入  0  → 输出 0.50（正好中间）
  输入 -3  → 输出 0.05（接近 0）
```

用途：本模型中有两处使用——
1. EGNN 的**注意力门控**（4.2.2a 步骤 2）：把消息的重要性压缩到 0~1，作为权重。0 = 完全忽略这条消息，1 = 完全保留。
2. **预测输出**（七、推理阶段）：把预测头输出的 logits 转换成 0~1 的概率。接近 1 = 模型认为能催化，接近 0 = 认为不能催化。

**Softmax**

```
规则：把一组数字转换成一组"权重"，所有权重加起来 = 1，且都 ≥ 0。
      数字越大，分到的权重越高。

举例：
  输入：[2.0, 1.0, 0.5]
  输出：[0.59, 0.24, 0.17]  ← 加起来 = 1.00
       （2.0 最大，所以分到最多权重）
```

用途：**交叉注意力**（4.5 节）中，计算完 Q 和 K 的相关性分数后，用 softmax 把分数转成权重。这样模型就知道"关注哪些位置"——权重高的位置贡献大，权重低的位置几乎被忽略。

Sigmoid 和 Softmax 的区别：Sigmoid 对每个数字独立处理（各管各的），Softmax 让所有数字互相竞争（总和必须为 1，一个变大，其他就得变小）。

---

### B. 归一化

**LayerNorm（层归一化）**

```
规则：把一组数字调整到均值 = 0、标准差 = 1

举例：
  输入：[10.0, 20.0, 30.0, 40.0]   ← 均值=25，标准差≈12.9
  输出：[-1.16, -0.39, 0.39, 1.16]  ← 均值=0，标准差=1
```

用途：本模型中 GROVER/Morgan/ESM 的线性层后面都接了 LayerNorm。原因是这些特征来自不同来源（数值范围差很多），LayerNorm 把它们统一到相同的数值范围，防止合并时某条通路的信号压制其他通路（详见 4.3.1 节的解释）。

---

### C. 正则化（防止过拟合）

**Dropout（随机丢弃）**

```
规则：训练时，随机把一部分数字强制设为 0。预测时不丢弃。

举例（Dropout 50%）：
  训练时输入：[0.5, 1.2, 0.8, 0.3, 0.9, 0.7]
  训练时输出：[0.5, 0.0, 0.8, 0.0, 0.0, 0.7]  ← 随机 3 个被丢弃
  预测时输出：[0.5, 1.2, 0.8, 0.3, 0.9, 0.7]  ← 全部保留，不丢弃
```

用途：本模型在交叉注意力中使用了 **Dropout 90%**（即每次随机丢弃 90% 的连接）。这是为了防止模型"死记硬背"训练数据。90% 是非常激进的比例，意味着每次训练只让 10% 的注意力连接参与计算，强迫模型学到更鲁棒的模式。

---

### D. 聚合操作

**scatter_sum（分散求和）**

```
规则：把多条消息按目标节点分组，同一组内求和

举例：节点 A 收到 3 条消息 [0.3, 0.5, 0.2]
  scatter_sum → 0.3 + 0.5 + 0.2 = 1.0
  节点 A 的汇总消息 = 1.0
```

用途：EGNN 消息传递（4.2.2a 步骤 3）中，每个原子把所有邻居发来的消息加起来。

**scatter_mean（分散求平均）**

```
规则：和 scatter_sum 类似，但同一组内求平均

举例：节点 A 收到 3 条消息 [0.3, 0.5, 0.2]
  scatter_mean → (0.3 + 0.5 + 0.2) / 3 = 0.333
```

用途：结构通道末尾（4.2.3 节），把所有底物原子的特征取平均，得到一个代表整体结构的全局向量 str_mean。

---

### E. 编码方式

**one-hot（独热编码）**

```
规则：用一组 0/1 表示"是哪一类"。只有对应类别的位置是 1，其余全是 0。

举例：键类型有 6 种，当前键是第 3 种（双键）
  one-hot = [0, 0, 1, 0, 0, 0]
           （第 3 位是 1，其余是 0）
```

用途：本模型中边特征的键类型编码（4.2.2b 节）、蛋白质原子的氨基酸类型编码都使用 one-hot。好处是不引入大小关系——如果直接用数字 1,2,3 编码，模型可能误以为"类型 3 比类型 1 大"，但 one-hot 没有这个问题。

**RBF / 高斯展开（Radial Basis Function / Gaussian Smearing）**

```
规则：把一个距离值展开成一组数字，每个数字表示"离某个参考距离有多近"

举例：实际距离 = 5.0Å，设 4 个参考点（3Å, 5Å, 7Å, 9Å）
  输出 ≈ [0.14, 0.98, 0.14, 0.00]
        （离 5Å 最近 → 该位置最大）
```

用途：本模型边特征中的距离编码（4.2.2b 节）。原始距离是一个数字（如 5.0Å），但直接用一个数字很难表达丰富的信息。RBF 把它展开成 32 个数字，让模型更容易学到"近距离和远距离有不同的作用"。

### F. 网络结构

**MLP（Multi-Layer Perceptron，多层感知机）**

```
结构：线性层 → 激活函数 → 线性层 → (激活函数) → ...

举例（本模型 EGNN 的边 MLP）：
  输入 295维 → 线性层(295→128) → ReLU → 线性层(128→128) → ReLU → 输出 128维
```

和单层线性层的区别：单层线性层只做 y = Wx + b（加权求和），MLP 有多层 + 激活函数，能学到非线性的复杂模式。本文档中 4.3.1 节详细解释了什么时候用 MLP、什么时候用单层线性层。

**残差连接（Residual Connection）**

```
规则：输出 = 输入 + 变换(输入)

举例：
  输入 x = [1.0, 2.0, 3.0]
  变换后 = [0.1, -0.2, 0.3]
  输出   = [1.1, 1.8, 3.3]  ← 在原来基础上做微调，而不是完全替换
```

用途：EGNN 每一轮消息传递（4.2.2a 步骤 5）都使用残差连接。好处是保证信息不会在多层传递中丢失——即使某一轮的变换效果不好，原始信息仍然保留。
