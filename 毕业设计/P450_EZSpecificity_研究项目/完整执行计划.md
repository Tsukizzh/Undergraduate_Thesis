# P450 EZSpecificity 研究完整执行计划 (2026-03-16 版本)

## 核心目标与技术策略

### 研究终局目标
在P450细胞色素酶家族上构建高精度、可解释的酶-底物特异性预测模型，从诊断、改进、验证三个环节形成完整闭环。

### 技术枢纽：LMDB → .pt迁移
**关键发现（2026-03-16）**：论文作者用256GB+ RAM，我们32GB/16GB。LMDB方案在低RAM环境失效：
- LMDB 60GB mmap > 32GB RAM → mmap thrashing (page cache换页 99%) → 2.09 it/s 衰减
- Per-sample .pt v3：仅160KB/样本，~10GB工作集，no thrashing → **7.56 it/s stable**（3.6倍提速）
- **成本**：FREE (本地生成，无需传输)
- **结果**：baseline/Fe+Heme等所有后续实验都可复用.pt管线

### **Phase 1: .pt 迁移 + 速度基准** (Days 1-2)
**地点**: 本地 (Windows 4070 Super 12GB)

**任务**:
1. 在本地跑一个baseline epoch，确认.pt速度确实是7.56 it/s
2. .pt文件传输到服务器 (~57GB，校验md5)
3. 在服务器跑一个baseline epoch，确认RTX 4090上的速度 (预期 8-10 it/s)

**输出**:

### **Phase 2: 基线模型对照** (Days 3-5)
**地点**: 服务器 (RTX 4090 24GB, 16GB RAM single-channel)

**两轮训练** (各10-15 epochs, ~2h/epoch):

#### **2a. Legacy Bug Baseline**
- 使用 `--edge-mode legacy_bug` (原始EdgeConnection bug，与ep14相同)
- 参数: 同Step 9 (bs14/accum2, 2 workers)
- 记录: AUC@ep14, overfitting曲线
- **假设**: AUC ≈ 0.7667 (证明.pt + bug mode = ep14相同)

#### **2b. Fixed Edge Baseline**
- 使用 `--edge-mode fixed` (修复bug)
- 参数: 同2a
- 记录: AUC@ep14, overfitting曲线
- **假设**: AUC > 0.7667 (修复bug后更优)

**输出**:
- `baseline_legacy_bug_curves.png` : AUC/loss曲线
- `baseline_fixed_curves.png` : AUC/loss曲线
- 两个最优checkpoint (legacy_bug_ep*.pt, fixed_ep*.pt)
- **关键指标**: AUC@ep14, AUC@best, overfitting确认

**决策点**: 如果fixed模式显著优于legacy_bug, 后续Phase 3-7都用fixed;否则保留legacy_bug (与论文一致)

### **Phase 3a: 数据泄露量化** (Days 6-7)
**地点**: 服务器

**目标**: 量化substrate leakage (6.56% Morgan FP overlap) 对AUC的实际影响

**方法**:
1. 将176K训练样本分为两类:
   - **Clean subset**: 0 substrate FP leakage (≈164K samples)
   - **Leaked subset**: >1条leakage (≈12K samples)
2. 分别在Phase 2的best checkpoint上做inference
3. 对比: AUC_clean vs AUC_leaked vs AUC_all

**输出**:
```
Leakage Impact Report:
- AUC (all)     = 0.7667
- AUC (clean)   = 0.7XXX
- AUC (leaked)  = 0.7XXX
- Inflation     = AUC(all) - AUC(clean) = 0.0XXX
```

**决策规则**:
- 如果 Inflation ≤ 0.02 → **继续Phase 3b** (泄露可接受)
- 如果 Inflation > 0.02 → **启动Phase 3b-Clean** (重新生成清净数据集, 耗时1-2周)

### **Phase 4: Fe + Heme 创新** (Days 8-12)
**地点**: 本地 + 服务器

**目标**: 修复Fe缺失OOD问题 (effect = -0.2322, 从EXP02看到)

**两个改进**:

#### **4a. 蛋白质原子词汇扩展**
- 当前: protein vocab = {H,C,N,O,S,Se} (无Fe)
- 改进: add Fe(Z=26)
- 位置: `src/Datasets/Structure/transforms.py` 约23行
- **重新生成**: `data/08_Step8_结构特征` (保留, 仅修改transforms后新样本不同)
  - 或直接在.pt Dataset类中on-the-fly修改 (不重新生成)

#### **4b. Heme 结构缓存**
- 当前: 对接PDB中Fe原子被过滤掉
- 改进: 在build_pt_cache.py中添加 `--include-heme` flag
  - 在pocket原子中保留Fe及其邻域原子
  - 在k-NN边生成中包含Fe-C/O配位相互作用
- **重新生成**: .pt缓存 v4 (含Heme, ~60GB, 仅新样本不同)

**效果预期**:
- EXP01 (晶体+抑制剂, 有Heme) 会显著提升
- EXP04 (Vina无Heme) 无变化
- 跨-family分析 (E6) 磷酸酶会下降, P450可能提升

**训练**: Phase 2相同参数, 跑10 epochs, 记录AUC@ep5/10

**输出**:
- `fe_vocab_expanded_curves.png` : vs Phase 2b (fixed)
- `heme_included_curves.png` : vs Phase 2b (fixed)
- 两个最优checkpoint

**决策点**: 如果combined Fe+Heme AUC > fixed_ep14+0.01 → 继续Phase 5; 否则讨论是否值得

### **Phase 5: 融合通道修复** (Days 13-15, 可选)

**跳过条件**: Phase 4已获得显著进展 (AUC+0.02) 或时间紧张

### **Phase 6: P450 数据扩增** (Days 16-18)
**地点**: 本地 + 服务器

**目标**: 增加P450训练数据量, 验证扩增方案的可行性

**新增P450来源**:
- PDB官方新P450结构 (2025年新增, ~50 enzymes)
- BRENDA中遗漏的P450相关底物 (~200-300 pair)

**工作流** (使用Phase 10 .pt管线):
1. **新酶处理**: 新P450序列 → ESM-2嵌入 → append到`enzymes.bin`
2. **新底物处理**: 新substrate SMILES → GROVER/Morgan → append到`substrates_grover.bin`
3. **对接**: AlphaFold预测结构 (或PDB实验结构) + AutoDock Vina → `.pdb` (复用Phase 3工具)
4. **特征提取**: build_pt_cache.py --resume (增量生成新pair的.pt, skip existing)
5. **合并**: 新.pt文件 concat 到train/val/test分割

**成本**: ~1 day (对接+特征 = 2-4h 并行, .pt生成 = 30min)

**验证**:
- 跑10 epochs with augmented data
- 记录: 新数据对AUC的影响 (预期+0.01-0.03)

**输出**:
- `augmented_data_log.md` : 新增数据统计, 对齐确认
- `augmented_training_curves.png` : AUC vs baseline

**意义**: 证明.pt pipeline可复用于new P450数据 → 论文贡献"可扩展的数据构建方案"

## P450 数据扩增工作流详解 (Phase 6 Reference)

### 工作流组件
```
新P450酶序列 (FASTA)
    ↓
ESM-2 embedding → append enzymes.bin
    ↓
新底物 SMILES (CSV)
    ↓
GROVER/Morgan fingerprint → append substrates_grover.bin
    ↓
新酶-底物对 (CSV: enzyme_idx, substrate_idx)
    ↓
AlphaFold结构预测 / PDB下载
    ↓
AutoDock Vina 对接 (复用Phase 3脚本)
    ↓
PDB → pocket + ligand coordinates
    ↓
build_pt_cache.py --resume --include-new
    ↓
Per-sample .pt files (生成新对) + append train/val/test
    ↓
更新 index.pt, manifest
    ↓
训练: same hyperparams
```

- ✅ ESM embedding: `Datasets/create_features.py` (无需修改)
- ✅ GROVER pipeline: Phase 3 scripts (复制即用)
- ✅ AutoDock Vina: Phase 3 scripts (--resume flag)
- ✅ build_pt_cache.py: Phase 10 (修改support --resume --new-only)
- ✅ Dataset merge: 更新index.pt的train/val/test offset

## 常见问题排查

### Q: 为什么phase 3b (clean dataset) 可能需要1-2周?
**A**: 需要重新做AlphaFold预测 (每个酶10-20min) + Vina对接 (30s-2min per pair, 失败重试) + 特征生成 (2h for 50K pairs). 串行耗时长, 但可以预先准备.

### Q: 如果fe_vocab改进没有效果怎么办?
**A**: 跳到Phase 5 (通道配置) 或Phase 6 (数据扩增), 或综合聚焦到"诊断方面的论文贡献" (已足够发表).

### Q: 服务器16GB单通道RAM真的够吗?
**A**: 够. .pt方案仅需~10GB工作集 (vs LMDB需15-30GB). 速度可能不如RTX 4090最优, 但不会OOM.

### Q: 实验没按时完成怎么办?
**A**: 优先级: Phase 1-2 (必须) > Phase 3a (重要) > Phase 4-6 (nice-to-have). 论文可以用Phase 1-3的结果发表, Phase 4-6作为future work.
