# P450 全面数据集构建计划

## Context

**背景**: ESIBank论文为7个酶家族（Esterase、Phosphatase等）分别构建了small_family数据集并进行了4种场景的benchmark评估，但**没有为P450建立专属的family数据集**。我们的研究目标是为P450建立同等规格的数据集和评估体系，以系统性地评估和改进模型在P450上的表现。

**目标**: 构建一个全面的P450数据集，像论文对其他7个家族做的那样，为P450建立完整的数据集+4种benchmark场景。具体包括：
1. 从尽可能多的数据源收集所有P450酶-化合物数据（能拿尽量多就拿）
2. 每个数据源单独一个子数据集，清晰命名区分
3. 合并去重，生成一个大数据集，支持不同组合
4. 按论文方法生成4种split（random/reaction/enzyme/all），支持4折交叉验证
5. 用原始模型在4种场景下benchmark → 证明不足 → 优化架构 → 重新benchmark

**预期成果**: 一个结构与`ESIBank/small_family/Phosphatase/`完全一致的`P450/`文件夹，可直接接入现有训练管线。

#### 1.1 ⭐ P450Rdb v2.0 — P450反应数据库（最高优先）

**它是什么**: 专门收录P450酶催化反应的数据库，由成都中医药大学团队维护。是目前最大的跨物种P450反应数据库。

**里面有什么**:
- **~10,957条P450催化反应**（v2.0扩展后）
- **~850个P450酶**，来自**400+个物种**（植物57%、微生物23%、动物20%）
- 每条反应记录包含：P450酶名、底物结构(SMILES)、产物结构(SMILES)、反应类型（氧化/还原等）、反应位点、物种、文献引用(PMID)
- 提供4个可下载文件：
  - `P450s.csv` — 所有P450酶（Gene ID, UniProt ID, 物种, 分类ID）
  - `Compounds.csv` — 所有化合物（SMILES, PubChem CID/SID）
  - `Reactions.csv` — 所有反应详情（酶-底物-产物三元组）
  - `Sequences.fasta` — 所有P450酶的蛋白序列

**为什么要拿**: 这个数据库同时满足我们的所有需求——有酶序列（可做ESM-2编码）、有底物SMILES（可做GROVER/Morgan编码）、有UniProt ID（可获取AlphaFold结构用于对接）、跨物种（序列多样性高）。还有反应SMILES（底物>>产物），虽然当前模型不需要但值得记录。

**怎么拿**: 访问 https://www.cellknowledge.com.cn/p450rdb_v2/download.html 直接下载。如果下载页面受限，可能需要网页爬取或联系作者。

**预期产出**: 从Reactions中提取酶-底物正样本对，每个反应=一条(P450酶, 底物SMILES, label=1)记录。

#### 1.2 ⭐ Plant P450 DB (ERDA) — 植物P450数据库（最高优先）

**它是什么**: 哥本哈根大学维护的植物P450分类数据库，记录了已知功能的植物P450。

**里面有什么**:
- **874条植物P450序列**，每条标注了已知的内源底物（萜类、脂肪酸、黄酮、生物碱等）
- 7个晶体结构
- 38个除草剂代谢相关的植物P450
- 数据以HTML表格形式呈现，包含：CYP名称、物种、底物类别、功能描述、文献引用

**为什么要拿**: 植物P450是P450多样性的重要组成（P450Rdb中植物占57%），这个数据库提供了底物注释信息。与P450Rdb互补——P450Rdb侧重反应细节，Plant P450 DB侧重功能分类。

**怎么拿**: 访问 https://erda.dk/public/vgrid/PlantP450/ ，HTML表格需要爬取。需要评估每条记录是否有具体的底物SMILES（可能只有底物类别如"terpenoid"而没有具体SMILES，这种情况需要进一步从文献或PubChem获取）。

**预期产出**: 酶名→UniProt ID→序列 + 底物类别→具体SMILES。可能需要额外步骤解析底物。

#### 1.3 ⭐ PCPD — 植物细胞色素P450数据库（最高优先）

**它是什么**: 中国科学院团队开发的植物P450数据库，专注于已知功能的植物CYP。

**里面有什么**:
- **181个植物P450酶**，有已知催化功能
- 每个酶提供：蛋白序列(FASTA)、预测3D结构(PDB文件)、催化功能描述
- 底物类型分类：萜类、脂肪酸、黄酮、生物碱等
- 有配体对接工具（说明有配体结构数据）
- GitHub仓库可能有结构化数据

**为什么要拿**: 虽然规模较小(181酶)，但它有预测的3D结构和配体对接数据，可能省去我们对这部分数据做AlphaFold预测+Vina对接的工作。

**怎么拿**: GitHub https://github.com/JiangLab2020/PCPD 下载。网站 http://p450.biodesign.ac.cn/ 访问。

**预期产出**: 181个P450酶的序列+结构+底物信息。

#### 1.4 CYPED + CPK — CYP工程数据库 + P450知识库

**它是什么**: BioCatNet平台上的P450工程数据库(CYPED)，整合了CPK(Cytochrome P450 Knowledgebase)的化合物数据。

**里面有什么**:
- **8,614条P450蛋白序列**（跨物种，全部已分类到家族/超家族）
- 通过CPK整合了**3,257个化合物**：1,699个底物 + 723个诱导剂 + 1,227个抑制剂
- 每个序列有：多序列比对(MSA)、进化树、HMM profile、保守残基标注
- 47个晶体结构链接
- 化合物与酶的关联关系

**为什么要拿**: 8,614条序列是目前找到的最大P450序列集之一（仅次于Nelson的40K+）。且化合物数据已经按底物/抑制剂分类，省去我们手动分类的工作。跨物种覆盖。

**怎么拿**: 访问 https://cyped.biocatnet.de/ ，评估是否支持批量下载或API查询。CPK的原始网站已失效，但数据已整合到CYPED v2中。

**预期产出**: 大量P450酶序列 + 酶-化合物关联对（已标注底物/抑制剂）。

#### 1.5 EnzymeMap — 原子映射酶催化反应数据集

**它是什么**: 基于BRENDA数据构建的大规模原子映射反应数据集，每条反应都标注了原子对应关系。

**里面有什么**:
- **~63,000条原子映射的酶催化反应**（v2扩展到~235,000条含蛋白/物种信息）
- 每条记录：原子映射反应SMILES（精确标注哪个原子变成了什么）、EC编号、UniProt ID、物种
- CSV格式，直接可用

**为什么要拿**: 虽然63K条中P450只是子集，但这是唯一提供**原子级别反应映射**的数据集。对于未来的反应位点预测(Path D)很有价值。当前可用于补充酶-底物正样本。

**怎么拿**: Zenodo直接下载 https://zenodo.org/records/8254726 ，CSV文件。

**P450筛选方法**: 不能按EC号过滤（EC 1.14.x.x包含大量非P450单加氧酶）。正确做法：提取CSV中所有UniProt ID → 用UniProt protein_families("Cytochrome P450") + InterPro域(IPR001128/IPR036396/IPR002401)验证 → 只保留确认为P450的记录。

**预期产出**: 数百到数千条P450原子映射反应（具体数量取决于P450在BRENDA中的覆盖率）。

#### 1.6 P450 BM3 Variants Database — BM3变体反应数据

**它是什么**: ACS Catalysis 2024年论文的supplementary数据，收录了P450 BM3(CYP102A1)的>1,500个工程变体及其催化反应数据。

**里面有什么**:
- **>1,500个CYP102A1(P450 BM3)突变体**
- 每个变体：突变位点描述、反应类型（羟基化/环氧化/碳烯转移等）、底物/产物结构、活性数据
- 都是同一个野生型P450的不同位点突变

**为什么要拿**: 虽然都是BM3的变体（序列多样性有限），但提供了"序列微小变化如何影响底物选择性"的精细数据。这对模型学习序列-功能关系有独特价值。

**怎么拿**: 从论文(DOI: 10.1021/acscatal.4c00086) supplementary下载Excel/CSV。

**预期产出**: ~1,500条(BM3变体序列, 底物SMILES, 活性)记录。

---

#### 1.7 BRENDA — 综合酶数据库

**它是什么**: 全球最权威的酶学数据库，包含~83,000个酶分子的底物、产物、动力学参数(Km, kcat, Ki)、物种等信息。ESIBank就是基于BRENDA构建的。

**里面有什么**:
- P450相关条目分布在多个EC编号下（不仅是EC 1.14.14.1）
- 每条记录：底物/产物名称和结构、Km/kcat等动力学参数、物种、组织、文献引用
- UniProt/PDB交叉引用

**为什么要拿**: 是P450Rdb和EnzymeMap的上游数据源。可能包含这两个数据库遗漏的P450条目，特别是动力学参数数据。

**怎么拿**: SOAP API提取。需要先获取P450酶的UniProt ID列表，再逐个查询BRENDA获取其底物/产物/动力学数据。**不可以直接用EC号搜索**，必须用UniProt/InterPro确认P450身份。

**预期产出**: P450酶的底物列表 + 动力学参数(Km, kcat)——后者对模型训练不直接需要，但有研究价值。

### Phase 3: 统一格式与数据整合 (本地, 不需GPU)

#### 3.1 统一数据格式

每个Source_X目录产出3个标准CSV + 1个可选CSV:

**enzymes.csv**:
```
enzyme_id, source_db, uniprot_id, gene_name, organism, ec_number, p450_family, sequence, sequence_length, quality_tier
```

**compounds.csv**:
```
compound_id, source_db, compound_name, smiles_canonical, inchikey, pubchem_cid, relation_type
```

**interactions.csv**:
```
interaction_id, source_db, enzyme_id, compound_id, relation_type, label, evidence_type, pmid, quality_tier
```

**reactions.csv** (有就记录，没有就空):
```
reaction_id, source_db, enzyme_id, substrate_compound_id, product_compound_id, reaction_smiles, reaction_type, reaction_site
```

字段说明:
- `relation_type`: SUBSTRATE / INHIBITOR / PRODUCT / UNKNOWN（不确定的标UNKNOWN，后续多智能体协作验证）
- `quality_tier`: A(晶体结构) / B(文献实验) / C(注释不完整) / D(计算预测)
- `evidence_type`: crystal_structure / literature / database_annotation / computational / hts_assay

#### 3.2 SMILES标准化
- 所有SMILES用RDKit canonical化
- 生成InChIKey用于精确去重
- 无法解析的SMILES标记并保留原始值

**产出** (实际):
```
data/sources/
├── Source_RCSB/           (3 files: enzymes, compounds, interactions)
├── Source_ESIBank/        (4 files)
├── Source_P450Rdb/        (7 files)
├── Source_PlantP450DB/    (4 files)
├── Source_PCPD/           (4 files)
└── Source_Figshare_CYP450/ (4 files, 辅助数据源)
```
注: Source_CYPED/EnzymeMap/BM3Variants/BRENDA等已跳过，空占位符已清理。

### Phase 4: 合并去重 (本地, 不需GPU) ✅ 已完成 (2026-03-24)

**脚本**: `scripts/02_合并去重/merge_dedup.py`
**输出**: `data/combined/`

#### 4.1 酶去重策略（与Codex 4轮讨论确定）
- **主键**: UniProt ID（精确匹配，大写标准化）
- **Fallback**: 精确序列SHA256 hash（处理PCPD 447个无UniProt酶）
- **序列桥接**: 无UniProt酶若序列完全匹配有UniProt的酶 → 合并并继承UniProt（282个成功桥接）
- **同UniProt不同序列**: 合并，选最长序列为canonical，标记conflict

#### 4.2 化合物去重策略
- RDKit标准化（canonical isomeric SMILES）

### Phase 5: 生成负样本 + 4种Split (本地, 不需GPU)

#### 5.1 负样本生成
- **方法: 双向随机采样**（改进论文的单向方法）
  - **方向A — 固定底物换酶**: 每个正样本 → 5个负样本（随机配对其他P450酶）
  - **方向B — 固定酶换底物**: 每个正样本 → 5个负样本（随机配对数据集内其他底物）
  - 总计每个正样本产生 ~10个负样本，正负比约1:10
  - 具体比例可根据实际数据量微调（如数据量少时减为各3个）
- **约束: 负样本的酶必须也是P450**（用户要求）
- **去重**: 生成后检查负样本是否与已知正样本冲突（即随机配对恰好是真实催化对）

## 关键决策记录

1. **能拿尽量多就拿**: 不提前排除任何数据源，全部收集后分类管理
2. **负样本分三类管理**:
   - `positives.csv`: 所有来源的正样本（确认催化关系）

   - `negatives/neg_config.yml`: 负样本生成参数（比例/种子/方法/方向），方便复现和实验不同配置
3. **反应信息**: 有就记录(reactions.csv)，没有的来源就空着，不强求
4. **relation_type不确定的标UNKNOWN**: 后续可通过多智能体协作(Claude+Codex+Gemini)进行文献验证
5. **Benchmark**: 完全复现论文4种场景(random/reaction/enzyme/all split)，4折交叉验证
