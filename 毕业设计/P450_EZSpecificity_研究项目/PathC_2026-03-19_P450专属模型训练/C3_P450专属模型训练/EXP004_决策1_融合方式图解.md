# EXP004 决策 1：GVP 残基通道与 EGNN 原子通道的融合方式

本文档为 EXP004（Step 14 双尺度结构编码）的架构设计文档。目标：在 EXP003 基础上增加一条残基级 GVP-GNN 通路，本文列出四种融合方式，每种都给出**完整的端到端架构图**。

---

## 标记说明

- 🟥 **新增模块**（相比 EXP003 新加的部分）
- 🟦 **修改模块**（相比 EXP003 内部逻辑变了）
- ★ 重要差异点
- ⚪ 未标记 = 和 EXP003 完全一致

# 零、GVP 残基通路内部工作原理（公共基础）

不管选哪种融合方式，GVP 通路的**内部处理完全相同**。先把这部分讲清楚。

## 0.1 输入：从口袋 PDB 提取残基级特征

```
==========================================================================
  口袋 PDB 文件（配体 10Å 范围内残基，~40 个残基）
==========================================================================

  对每个残基 i，提取四组几何量：

  ┌─────────────────────────────────────────────────────────┐
  │ (1) 标量角度 node_s[i] ── 6 维数字                      │
  │     用主链原子 N_i, CA_i, C_i 及相邻残基计算：          │
  │       cos(φ_i), sin(φ_i)   ← 主链二面角 φ               │
  │       cos(ψ_i), sin(ψ_i)   ← 主链二面角 ψ               │
  │       cos(ω_i), sin(ω_i)   ← 肽键二面角 ω               │
  │     形状：node_s [N_res, 6]                             │
  └─────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────┐
  │ (2) 向量方向 node_v[i] ── 3 根 3D 箭头（真实向量）      │
  │     forward_i   = CA_{i+1} - CA_i   ← 主链正向          │
  │     backward_i  = CA_{i-1} - CA_i   ← 主链反向          │
  │     sidechain_i = 从 N/CA/C 几何构造的虚拟 Cβ 方向      │
  │     形状：node_v [N_res, 3, 3]                          │
  │             ↑     ↑  ↑                                  │
  │          残基数  3根 xyz                                │
  └─────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────┐
  │ (3) 边连接 edge_index ── K 近邻连接                     │
  │     对每个残基，基于 CA 坐标找最近 k=30 个邻居          │
  │     形状：edge_index [2, E]，E ≈ N_res × 30             │
  └─────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────┐
  │ (4) 边特征                                              │
  │     edge_s [E, 32] = 距离 RBF (16 维) + 位置编码 (16 维)│
  │     edge_v [E, 1, 3] = CA_j - CA_i 单位向量             │
  │             ↑  ↑  ↑                                     │
  │            边数 1根 xyz                                 │
  └─────────────────────────────────────────────────────────┘

  这四组特征离线预计算一次，存到 structure_features_gvp.lmdb
```

## 0.2 GVP-GNN 处理流程（运行时）

```
==========================================================================
  输入：(node_s, node_v, edge_index, edge_s, edge_v)
==========================================================================

  ┌───────────────────────────────────────────────────────┐
  │ 第 1 步：GVP 嵌入层（把输入特征投影到工作维度）        │
  │                                                       │
  │ node_s [N_res, 6] ────→ Linear ────→ [N_res, 100]    │
  │                         （标量通道）                  │
  │                                                       │
  │ node_v [N_res, 3, 3] ─→ LinearVec ──→ [N_res, 16, 3] │
  │                         （向量通道，保持最后一维 xyz）│
  └───────────────────────────────────────────────────────┘
                              │
                              ▼
  ┌───────────────────────────────────────────────────────┐
  │ 第 2 步：GVPConvLayer × 3 层（消息传递）               │
  │                                                       │
  │ 每层内部：                                            │
  │   ├─ 聚合邻居的标量和向量                             │
  │   ├─ 标量消息 m_s：                                   │
  │   │    输入 = [h_s_i, h_s_j, e_s_ij,                  │
  │   │           ‖h_v_i‖, ‖h_v_j‖, ‖e_v_ij‖]            │
  │   │    MLP → [E, 100]                                 │
  │   │                                                   │
  │   ├─ 向量消息 m_v：                                   │
  │   │    输入 = [h_v_i, h_v_j, e_v_ij] （真·3D 向量）  │
  │   │    LinearVec → [E, 16, 3]                         │
  │   │    ★ 保持 SE(3) 等变性：                          │
  │   │      旋转输入 → 旋转输出（方向跟着转）             │
  │   │                                                   │
  │   ├─ 聚合消息 (scatter_sum) → 节点级消息              │
  │   │                                                   │
  │   ├─ 更新节点 (标量/向量分开更新):                    │
  │   │    node_s ← node_s + MLP(m_s, ‖m_v‖)             │
  │   │    node_v ← node_v + LinearVec(m_v, node_s 缩放) │
  │   │                                                   │
  │   └─ LayerNorm + Dropout (对 node_s 单独做)           │
  │                                                       │
  │ 3 层之后：                                            │
  │   node_s [N_res, 100]                                 │
  │   node_v [N_res, 16, 3]                               │
  └───────────────────────────────────────────────────────┘
                              │
                              ▼
  ┌───────────────────────────────────────────────────────┐
  │ 第 3 步：标量化 + 投影到工作维度                     │
  │                                                       │
  │ 把 node_v 的模长拼到 node_s：                         │
  │ node_v_norm = ‖node_v‖ (沿 xyz 维度) → [N_res, 16]    │
  │ combined = concat(node_s, node_v_norm) → [N_res, 116] │
  │                                                       │
  │ Linear 116 → 128                                      │
  │                                                       │
  │ 输出 h_res [N_res, 128]                               │
  │       ↑                                               │
  │   残基级嵌入，每个残基一个 128 维向量                 │
  └───────────────────────────────────────────────────────┘
                              │
                              ▼
  ┌───────────────────────────────────────────────────────┐
  │ 第 4 步：池化（如果需要图级向量）                     │
  │                                                       │
  │ g_res = scatter_mean(h_res, batch) → [B, 128]         │
  │          ↑                                            │
  │      对所有残基取平均，得到整个酶的残基图级嵌入       │
  └───────────────────────────────────────────────────────┘

  两个输出：
  ● h_res [N_res, 128] ── 残基级细粒度嵌入
  ● g_res [128]        ── 图级全局嵌入
```

**四种融合选项就是针对这两个输出（h_res 和 g_res）如何接入现有架构的不同方案。**

# 选项 ①：晚期拼接（Late Concatenation）

**核心**：GVP 通路完全独立到底，只把 `g_res` 作为第 8 个向量塞进最后的拼接。`h_res` 不使用。

## 选项 ① 的改动点总结

| 位置 | 改动类型 | 说明 |
|---|---|---|
| 阶段一 ④ 号通路 | 🟥 新增 | 新加整条 GVP 通路（输入特征 → GVP 嵌入 → GVPConvLayer×3 → 池化 → g_res [128]） |
| 阶段三 ⑧ 号拼接 | ★ 修改 | 向量数量 7 → 8，总维度 [896] → [1024] |
| 预测头第一层 | 🟦 修改 | 线性层输入维度 896 → 1024 |
| 其他所有部分 | ⚪ 不动 | 包括 ①②③ 通路、交叉注意力、池化、预测头后两层 |

## 选项 ① 优缺点

**优点**：
- 改动范围最小，只在架构"前端加通路、末端加拼接维度"两处动手
- 和 EXP003 的单变量对比最干净：差别仅限"是否引入 g_res"
- 训练稳定：新通路梯度流路径清晰，不会干扰已有模块
- 失败代价低：如果 GVP 无效，删掉一个向量即可回退到 EXP003

**缺点**：
- `h_res` 的残基级细节信息**完全没用**，只用了全局平均后的 `g_res`
- 两条通路直到预测头才见面，中间没有交互，融合深度浅

# 选项 ②：残基信息回填到酶序列通道

**核心**：GVP 输出的 `h_res`（每个残基一个向量）**注入到 x_pro 的对应位置**，增强酶的残基级表示。然后进入交叉注意力。


## 选项 ② 改动点总结

| 位置 | 改动类型 | 说明 |
|---|---|---|
| 阶段一 ④ 号通路 | 🟥 新增 | GVP 通路，输出 h_res [N_pocket, 128]（不做全局池化）|
| 数据加载器 | 🟥 新增 | 需要记录并传入 pocket_residue_idx（口袋残基在酶序列的位置）|
| 阶段一半 | 🟥 新增 | 回填模块：x_pro_enhanced[idx] += Linear(h_res) |
| 阶段二交叉注意力 | ★ 使用 | 输入从 x_pro 变成 x_pro_enhanced |
| 阶段三之后 | ⚪ 不动 | 拼接数量、预测头维度都不变 |

## 选项 ② 优缺点

**优点**：
- 融合更深：GVP 信息进入交叉注意力，影响酶-底物的交互计算
- 向量数量和预测头都不变，后半段架构无感
- 残基级细节（h_res 每个残基的向量）**被实际使用**了

**缺点**：
- **实现复杂度最高的风险点**：必须正确维护"口袋残基 → 酶全长序列位置"的索引映射。EXP003 的数据加载器里没有这个字段，需要在 pt_cache 构建阶段新增。
- 索引错位 bug 风险大：如果 idx 错一个位置，GVP 信号就会注入到错误残基
- 训练稳定性中等：x_pro 同时承载两种来源的信号，可能互相干扰

# 选项 ③：跨尺度交叉注意力

**核心**：新增一个注意力模块，让底物原子 x_reaction 主动查询 GVP 残基嵌入 h_res，实现**原子↔残基跨尺度信息传递**。

## 选项 ③ 优缺点

**优点**：
- 融合方式最优雅：通过注意力机制让模型自动学习"哪个残基对哪个底物原子最重要"
- 不依赖硬索引：残基和原子的对应关系由 softmax 学出来
- 理论上限最高

**缺点**：
- 新增一整个注意力模块（参数 ~30-50K，新增头数、dropout 等超参数）
- 训练不稳定性高：新模块从头训练，可能收敛慢或欠拟合
- 调参成本大：新模块的学习率、dropout 等需要单独调
- 代码改动量最大

## 选项 ④ 优缺点

**优点**：
- 架构干净：两塔互不干扰，调试容易
- 类似 model ensemble，稳定性好

- 不破坏 EXP003：塔 1 在 α→1 时就退化为 EXP003

- **参数量翻倍**：塔 2 复制了塔 1 的交叉注意力 + 预测头（约 +80% 参数）
- 训练时间增加 ~60-80%
- 过拟合风险上升（参数量变大但数据量不变）
- 深度融合缺失：GVP 信息只在 logit 层面和 EGNN 见面

# 推荐与理由

## 我的推荐：**选项 ①（晚期拼接）**

### 核心理由

1. **时间压力真实存在**：毕设 ddl 4 月中旬，EXP004 需要在 4-6 天内跑完、评估、写进论文。选项 ① 的实施周期最短（~1 天代码 + 2-3 小时训练）。

2. **单变量对比最干净**：和 EXP003 的差别仅是"是否引入 g_res"这一个向量。论文里写"GVP 通路贡献了 +X AUC"这句话完全站得住脚。

3. **先建 MVP 的工程原则**：第一次验证一个新想法时，应该用最简单的方式回答"它到底有没有用"这个最核心问题。如果连简单版本都没效果，复杂版本也不会有。

4. **可扩展路径清晰**：
   - 如果 ① 有正收益 → EXP005 可以升级到 ② 或 ③
   - 如果 ① 无收益 → 说明 GVP 本身对 P450 任务帮助有限，复杂版本也没意义
   - 如果 ① 有负收益 → 直接回退，代价极小

5. **失败代价最低**：选项 ① 新增代码只有约 200 行，失败后删掉即可。选项 ②③④ 涉及更复杂的改动，失败回退成本高。

### 什么情况下应该选别的？

- **如果你对 GVP 极度有信心，愿意赌一次**：选 ③。它的上限最高，但失败风险也最高。
- **如果你对"原子-残基硬索引"的实现有把握**：选 ②。它深度融合但可维护性最差。
- **如果你想要 ensemble 式的稳健性**：选 ④。但参数量翻倍可能吃光训练预算。
