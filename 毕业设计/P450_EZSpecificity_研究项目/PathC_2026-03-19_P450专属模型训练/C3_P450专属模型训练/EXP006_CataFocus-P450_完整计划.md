## 一、我们遇到的问题是什么

在 P450 酶家族专属数据集（47510 对酶-底物）上，我们已经得到了一个性能不错的模型：

```
基线模型 EXP001_allfix_unified：
  架构：EZSpecificity 原始架构（原子级 EGNN + 交叉注意力）
  数据：P450 专属 47510 对
  结果：测试集 AUC = 0.9320
```

**但这个数字不足以支撑一个毕业设计的创新点**。原因是：

```
┌────────────────────────────────────────────────────┐
│  从架构角度看，我们做了什么？                        │
│                                                    │
│  论文模型架构 ──→ 我们的架构（完全一样）            │
│       ↓                    ↓                       │
│  论文的训练数据       我们的 P450 专属训练数据       │
│       ↓                    ↓                       │
│   AUC = 0.5586         AUC = 0.9320               │
│                                                    │
│  差别全在数据，架构零改动。                          │
└────────────────────────────────────────────────────┘
```

提升 0.36 的 AUC 全靠数据工程和重新训练。**本科毕业论文需要一个真正的架构贡献**。

---

## 二、我们之前尝试过什么，为什么没成功

我们已经做过三次架构改动尝试，全部是**给模型加入更多几何/化学信息**，结果全部失败：

```
尝试一：EXP002a_allfix_unified
  做法：把铁原子（Fe）和血红素（HEM）加入原子类型词汇表
       feature_dim 从 28 升到 31
  结果：AUC 0.9270（掉了 0.005）

尝试二：EXP003_allfix_unified
  做法：把每个残基的 φ/ψ/χ1 二面角加入节点特征
       feature_dim 从 31 升到 37
  结果：AUC 0.9300（比 EXP002a 好一点，但不如基线）

尝试三：EXP005_dualgraph_2plus
  做法：在原子级图之外再加一条残基级 GVP 通路（双图架构）
  结果：AUC 0.9253（掉了 0.007）
```

**三次失败说明一个重要规律**：

```
┌───────────────────────────────────────────────────────┐
│  规律：往现有架构里塞更多结构特征，不起作用             │
│                                                       │
│  不管是原子类型、二面角、还是完整的几何图神经网络，      │
│  只要是"作为新特征加入"，都会被原有信号稀释，            │
│  甚至因为增加了噪声而掉性能。                           │
└───────────────────────────────────────────────────────┘
```

我们把这个规律叫做**"结构通道饱和"**。

---

## 三、为什么会饱和？——一个关键的观察

为了弄清楚"饱和"背后的原因，我们可以看看基线模型**实际在关注什么**。

EZSpecificity 模型在最后有一层"交叉注意力"，模型会给每个底物原子打一个"重要性权重"——权重越高，模型在做最终判断时越依赖这个原子。

如果我们把这些权重提取出来，看看模型给哪些原子打了高分：

```
  实验：挑 100 个正样本（酶确实能催化底物），
       提取每个样本里模型关注度最高的前 3 个底物原子，
       计算这 3 个原子到铁原子的距离。

  结果（预期，工作 A 会验证）：
                     平均到 Fe 距离
    高关注度原子:         3~5 Å  （很近）
    随机选的原子:         8~12 Å （远多了）
```

**结论**：基线模型**已经自发地**学会了关注"靠近铁原子的底物原子"。我们没有告诉它铁原子是催化中心，它自己从数据里学到了。

这解释了为什么之前三次尝试都失败：

```
┌────────────────────────────────────────────────────┐
│  为什么给模型加"铁原子是特殊的"信息没用？            │
│                                                    │
│  因为模型已经自己学会了这件事。                     │
│  再显式告诉它一次，只是重复信息，                   │
│  还可能引入噪声，所以反而掉性能。                   │
└────────────────────────────────────────────────────┘
```

## 四、那要怎么办？——CataFocus 的核心思路

既然模型自己学会了关注铁原子，我们还能做什么架构创新？

关键观察是：**模型的"学会了"是隐式的、不稳定的**。具体来说：

```
隐式学习的脆弱性：

  原因 1：训练数据少的时候，模型可能学不到
         （所以在一些难样本上关注点会飘）

  原因 2：不同的初始化会让模型学到不同的东西
         （训练 5 次，每次关注模式都稍有不同）

  原因 3：没有直接的监督信号
         （模型是通过"预测对了"反向推出"该关注哪里"，
          这条推理链很长、很间接）
```

我们的想法是：**既然模型自己都能学到"关注铁原子"这个机制，不如用架构直接把它固化下来，让这个机制变成模型的硬结构，而不是需要模型从头学的软偏好**。

这就是 CataFocus 的核心思路：

```
┌─────────────────────────────────────────────────────────┐
│  核心思路一句话：                                         │
│                                                         │
│  把"以铁原子为催化中心来聚焦信息"这件事，                  │
│  从"模型自己学"变成"架构直接保证"。                        │
└─────────────────────────────────────────────────────────┘
```

---

## 五、CataFocus 怎么实现这个思路？三个组件

整体结构是：在现有模型基础上**新增**一条催化分支，这条分支专门处理"围绕铁原子的信息聚焦"。

```
┌────────────────────────────────────────────────────────┐
│  原有 EZSpecificity 模型（完全保留，不改一行）           │
│                                                        │
│  ESM → 酶序列特征                                      │
│  EGNN → 结构特征                                       │
│  GROVER + Morgan → 分子特征                            │
│  交叉注意力 → 酶-底物交互                              │
│  7 个向量拼接 → 预测头 → 最终分数                      │
└────────────────────────────────────────────────────────┘
                        +
┌────────────────────────────────────────────────────────┐
│  新增催化分支（CataFocus，零初始化）                    │
│                                                        │
│  组件 ①：软门控分支                                     │
│           ——给每个节点打一个"催化相关度"分数             │
│                                                        │
│  组件 ②：氧化位点辅助任务                               │
│           ——额外让模型预测"哪个原子会被氧化"            │
│                                                        │
│  组件 ③：残差调制融合                                   │
│           ——把催化信息叠加回结构特征                    │
└────────────────────────────────────────────────────────┘
```

下面三节分别讲每个组件怎么工作。

## 六、组件一：软门控分支

### 6.1 这个分支要做什么

一句话：**给对接复合物图里的每一个节点（每个原子），打一个 0 到 1 之间的分数，代表这个节点和催化反应的相关程度**。

```
图里的节点（例）：

  节点 1: 铁原子本身                 打分：1.0（最相关）
  节点 2: 铁附近的残基原子            打分：0.85
  节点 3: 底物中最靠近铁的碳原子       打分：0.80
  节点 4: 底物中远离铁的氧原子         打分：0.20
  节点 5: 口袋外围的残基原子           打分：0.10
  节点 6: 底物远端的甲基               打分：0.05
```

高分节点的信息会被**放大**，低分节点的信息会被**抑制**。这是"聚焦"的物理含义。

### 6.2 打分怎么算？

打分有两个依据：**几何距离** + **可学习的注意力**。

```
对每个节点 i，分数算法如下：

  第 1 步：拿到铁原子的特征向量 q_Fe
         （把铁原子在 EGNN 里的输出向量作为"查询"）

  第 2 步：计算节点 i 和铁原子的"特征相似度"
         similarity_i = Q·K / √d   （标准的注意力内积）

  第 3 步：计算节点 i 到铁原子的"几何距离编码"
         geom_i = RBF(||position_i - position_Fe||)
         （RBF 就是把距离转成 32 个数字的经典技巧，
          能区分"近/中/远"的不同作用）

  第 4 步：综合两者得到原始分数
         score_i = similarity_i + W · geom_i

  第 5 步：用 sigmoid 把分数压到 0~1 之间
         g_i = sigmoid(score_i)
```

**为什么要两个依据都用？**

```
  ┌──────────────────────────────────────────────────────┐
  │  只用几何距离：                                       │
  │    问题——离铁远但化学上重要的原子会被误判             │
  │    例如：底物末端有一个关键的氢给体残基                │
  │                                                      │
  │  只用注意力相似度：                                   │
  │    问题——和 EXP002a 失败原因一样，信号会被稀释        │
  │                                                      │
  │  两者结合：                                           │
  │    几何距离提供先验（近铁 = 可能重要）                 │
  │    注意力提供修正（学习"近铁 + 化学可氧化"的组合）     │
  └──────────────────────────────────────────────────────┘
```

### 6.3 算出来的分数怎么用？

用这些分数做**加权池化**：

```
催化描述符 h_cat = Σ (g_i · W · h_i)  /  Σ g_i

      ↑ 分数高的节点          ↑ 归一化
        贡献大
```

`h_cat` 是一个 128 维向量，代表"整个对接复合物里，和催化真正相关的那部分信息的综合"。

### 6.4 和 EXP002a 的根本区别是什么

这是很关键的问题。同样是"利用铁原子的信息"，为什么 EXP002a 失败，CataFocus 有机会成功？

区别在**作用方式**：

```
┌─────────────────────────────────────────────────────────┐
│  EXP002a 的做法：局部注入                                │
│                                                         │
│  铁原子的 one-hot 编码作为节点特征                        │
│        ↓                                                │
│  EGNN 消息传递：铁的信息沿着图的边扩散                    │
│        ↓                                                │
│  经过 3 层消息传递后，铁的信息已经被"平均"到邻居          │
│        ↓                                                │
│  距离铁 4 跳以上的节点，基本感知不到铁的存在              │
│                                                         │
│  比喻：在教室中间放了一个闹钟，                           │
│       离得近的人听得清，远处的人听不到。                  │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  CataFocus 的做法：全局加权                              │
│                                                         │
│  铁原子的特征作为"查询向量"                               │
│        ↓                                                │
│  同时对图里所有节点（不管远近）打分                       │
│        ↓                                                │
│  打分结果直接决定每个节点的贡献权重                       │
│        ↓                                                │
│  任何距离的节点都会被统一评估一次                         │
│                                                         │
│  比喻：在教室里广播 "请铁催化组的同学举手"，               │
│       每个人都能听见，符合条件的就举手。                  │
└─────────────────────────────────────────────────────────┘
```

**一句话总结这个区别**：EXP002a 让铁原子在图里"发声音"（局部），CataFocus 让铁原子"广播"（全局）。

## 七、组件二：氧化位点辅助任务

### 7.1 这个辅助任务要做什么

主任务是"预测酶能否催化底物"——这是一个二分类问题。

辅助任务是"预测底物的哪个原子会被氧化"——这是一个更具体的化学任务。

```
主任务（二分类）：
  输入：酶序列 + 底物 SMILES + 对接复合物
  输出：yes / no（能否催化）

辅助任务（氧化位点预测）：
  输入：同上
  输出：底物每个可氧化原子被氧化的概率
        例：5 个候选原子 → [0.45, 0.32, 0.15, 0.06, 0.02]
```

模型**同时**做这两个任务，两个任务共享底下的大部分网络。

### 7.2 为什么要加这个辅助任务

两个原因：

```
原因 1：给门控分支一个"学习锚点"

  组件一的门控需要学会打合理的分数，但它怎么知道什么是"合理"？
  如果只靠主任务的反向传播，信号很间接。
  辅助任务提供了一个直接的监督：
  "哪个原子应该被氧化"——这和"哪个原子最相关"高度相关。

原因 2：强迫模型学习化学反应性

  主任务只问"能不能"，不问"具体反应哪里"。
  加入辅助任务相当于逼模型回答更细节的问题，
  让底物的表示携带更丰富的化学信息。
```

### 7.3 可是我们没有"哪个原子被氧化"的真实标签

这是最棘手的问题。实验验证的氧化位点数据很难得到，我们的 47510 对数据中大部分没有标注。

**解决方案：用对接复合物的几何信息推出"软标签"**。

```
软标签生成流程：

  第 1 步：从底物分子中筛出"可氧化的重原子"
         （主要是 C、N、S、P，排除氢、卤素、金属）

  第 2 步：对每个可氧化原子 j，计算它到铁原子的距离 d_j

  第 3 步：用 softmax 把距离转换成概率分布
         target_j = softmax(-d_j / τ)    τ = 0.7 Å

  第 4 步：target_j 就是"原子 j 是氧化位点的概率"的软标签

举例：底物 5 个可氧化原子，到铁的距离分别是：
     原子 A: 2.5 Å
     原子 B: 3.0 Å
     原子 C: 4.2 Å
     原子 D: 5.1 Å
     原子 E: 6.8 Å

     经过 softmax(-d/0.7)：
     原子 A: 0.45  （最近，概率最高）
     原子 B: 0.32
     原子 C: 0.15
     原子 D: 0.06
     原子 E: 0.02  （最远，概率极低）
```

### 7.4 为什么用"软"标签而不是"硬"标签

硬标签的做法是：选距离最近的原子 = 1，其他全部 = 0。

硬标签的问题：

```
  ┌──────────────────────────────────────────────────────┐
  │  问题 1：对接结构有误差                               │
  │    如果"真正最近的原子"其实是原子 B 而不是原子 A，    │
  │    硬标签就完全错了。                                 │
  │                                                      │
  │  问题 2：化学上可能有多个候选位点                     │
  │    P450 经常有 2-3 个相邻的 C-H 键同时可以被氧化，    │
  │    选一个标 1 其他全标 0，等于否认化学事实。          │
  │                                                      │
  │  软标签的好处：                                       │
  │    承认"每个原子都可能是氧化位点，只是概率不同"，      │
  │    对对接误差不敏感，也符合 P450 的真实化学。         │
  └──────────────────────────────────────────────────────┘
```

### 7.5 这个辅助任务怎么接到模型上

在底物原子的 EGNN 输出上加一个小预测头：

```
对每个可氧化原子 j：

  输入向量 = 原子 j 的 EGNN 特征  [128]
          ⊕ 原子 j 到铁的距离 RBF 编码  [32]
          ⊕ 原子 j 的门控值 g_j  [1]

  预测头（小 MLP）→ 标量 logit_j

  对所有候选原子的 logits 做 softmax：
  预测分布 = softmax([logit_1, logit_2, ...])

  辅助损失 = KL散度(预测分布 || 软标签)
```

总损失是主任务损失 + 0.2 倍辅助任务损失：

```
L_total = L_main(主任务) + 0.2 × L_SoM(辅助任务)
```

主任务权重是 1，辅助任务权重 0.2，不喧宾夺主。

## 八、组件三：残差调制融合

### 8.1 为什么需要"融合"

组件一算出了催化描述符 `h_cat`（一个 128 维向量）。这个向量怎么影响最终预测？

回忆基线模型最后一步：

```
基线的最后一步：

  [酶全局特征] + [底物全局特征] +
  [酶看底物注意力] + [底物看酶注意力] +
  [结构特征 str_mean] +
  [GROVER 特征] + [Morgan 特征]
       ↓
  拼接成 896 维向量
       ↓
  MLP 预测头
       ↓
  最终分数
```

我们要把 `h_cat` 塞进这个流程。有两个选项：

```
选项 A：作为第 8 个向量拼接进去

  拼接 → [... 7 个原有向量, h_cat]  → 1024 维
  MLP 需要加宽输入层

选项 B：残差调制 str_mean（结构特征）

  新的 str_mean = 原 str_mean + r ⊙ P(h_cat)
  拼接总维度仍是 896，只是 str_mean 内容变了
```

### 8.2 我们选选项 B，为什么

```
┌────────────────────────────────────────────────────────┐
│  选项 A（第 8 向量）的缺点：                             │
│                                                        │
│  h_cat 只是"又一个向量"，和其他 7 个平等竞争。          │
│  最终预测头看到的只是 8 个向量拼起来的 1024 维。        │
│  h_cat 的信号很容易被其他向量盖过去。                    │
└────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────┐
│  选项 B（残差调制）的优点：                              │
│                                                        │
│  h_cat 不是"新增一个向量"，而是"修改已有的 str_mean"。  │
│  催化信息直接改造了结构特征的表示。                      │
│  str_mean 本来就是最关键的结构通道，改造它等于             │
│  把催化信号注入到最核心的位置。                          │
└────────────────────────────────────────────────────────┘
```

### 8.3 残差调制具体怎么算

```
第 1 步：从 h_cat 算出一个"门控向量" r

  r = sigmoid(MLP(h_cat))     r ∈ [0, 1]^128

  r 是一个 128 维的向量，每一维都在 0~1 之间。
  它的作用是控制"在 str_mean 的每个维度上，催化信息要加多少"。

第 2 步：把 h_cat 投影到和 str_mean 同样的维度空间

  P(h_cat) = Linear(h_cat)    [128] → [128]

  P 是一个线性投影，权重零初始化。

第 3 步：残差叠加

  str_mod = str_mean + r ⊙ P(h_cat)

  ⊙ 是逐元素乘法。
  r 控制每个维度叠加多少，P(h_cat) 提供叠加的内容。

第 4 步：用 str_mod 替代 str_mean 进入最终拼接

  最终向量 = [...其他 6 个原有向量, str_mod]  → 仍是 896 维
```

### 8.4 关键设计：零初始化保证基线等价性

投影 `P` 的权重**全部初始化为 0**。

```
训练刚开始时（第 0 步）：

  P 的权重 = 0
  所以 P(h_cat) = 0
  所以 str_mod = str_mean + r ⊙ 0 = str_mean

  新模型的输出 = 基线模型的输出（完全一样）
```

**这意味着什么**？意味着训练开始时，新架构**完全等价于基线**。训练过程中，`P` 的权重会逐渐学出来，催化分支才慢慢起作用。

这样做的好处：

```
┌───────────────────────────────────────────────────────┐
│  好处 1：训练稳定                                      │
│    如果新分支的初始化不好，不会污染基线的信号。         │
│                                                       │
│  好处 2：可以验证实现正确                              │
│    训练前跑一次前向，如果输出不等于基线，              │
│    说明代码有 bug。                                    │
│                                                       │
│  好处 3：延迟激活                                      │
│    训练早期模型先学主任务（和基线一样的行为），        │
│    随着训练进行，催化分支逐步激活并学习。              │
└───────────────────────────────────────────────────────┘
```

## 九、整体流程走一遍

把前面三个组件串起来，完整的 CataFocus 数据流是这样的：

```
┌──────────────────────────────────────────────────────────────┐
│  阶段一：和基线完全相同（不改任何东西）                        │
│                                                              │
│  ESM 序列嵌入     → x_pro [1450, 128]                        │
│  对接复合物图     → EGNN 3 层消息传递                        │
│                  → H = {h_i}（所有节点的 128 维嵌入）         │
│  GROVER、Morgan   → 分子特征                                 │
└──────────────────────────────────────────────────────────────┘
                             ↓
┌──────────────────────────────────────────────────────────────┐
│  阶段二：CataFocus 催化分支（并行，不影响基线计算）             │
│                                                              │
│  ① 软门控：                                                  │
│     从 H 里找到铁原子的嵌入 h_Fe → 作为查询                  │
│     对所有节点 i：                                           │
│       geom = RBF(节点 i 到铁的距离)                         │
│       score = Q·K / √d + W·geom                            │
│       g_i = sigmoid(score)                                  │
│                                                              │
│  ② 催化描述符池化：                                          │
│     h_cat = Σ g_i·W_v·h_i / Σ g_i     [128]                 │
└──────────────────────────────────────────────────────────────┘
                             ↓
┌──────────────────────────────────────────────────────────────┐
│  阶段三：融合                                                 │
│                                                              │
│  ③ 残差调制：                                                │
│     r = sigmoid(MLP(h_cat))                                 │
│     str_mod = str_mean + r ⊙ P(h_cat)    （P 零初始化）     │
│                                                              │
│  ④ 7 向量拼接：                                              │
│     把 str_mean 换成 str_mod，其他 6 个向量不变              │
│     拼接成 896 维 → MLP 预测头 → 主任务 logit               │
└──────────────────────────────────────────────────────────────┘
                             ↓
┌──────────────────────────────────────────────────────────────┐
│  阶段四：辅助任务（独立分支，共享底下的 EGNN）                 │
│                                                              │
│  ⑤ 氧化位点预测：                                            │
│     对每个可氧化底物原子 j：                                 │
│       logit_j = MLP([h_j, RBF(d_j), g_j])                  │
│     softmax(logits) = 预测分布                              │
│     软标签 target_j = softmax(-d_j / 0.7)                   │
│     L_SoM = KL(预测分布 || 软标签)                           │
└──────────────────────────────────────────────────────────────┘
                             ↓
                   总损失 = L_主 + 0.2 × L_SoM
                             ↓
                        反向传播，更新参数
```

## 十、这个设计为什么和 EXP005 双图不同

EXP005 的残基级 GVP 双图失败了（-0.0067）。你可能会问：CataFocus 也是"加一条新分支"，凭什么这次会成？

关键区别在"新分支做什么"：

```
┌─────────────────────────────────────────────────────────┐
│  EXP005 双图架构做的：加信息                             │
│                                                         │
│  原子级 EGNN  ──→ 信息源 A（结构）                      │
│  残基级 GVP   ──→ 信息源 B（残基级几何）                │
│  两者平等地提供信息 → 合并                              │
│                                                         │
│  问题：信息 B 和 A 高度重叠，又引入新的训练难度，        │
│       净效果是负的。                                    │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  CataFocus 做的：改信息组织方式                          │
│                                                         │
│  原子级 EGNN  ──→ 信息源 A（结构）                      │
│  门控分支     ──→ 对信息源 A 的节点打权重               │
│  加权池化     ──→ 催化相关部分被放大，无关部分被抑制    │
│                                                         │
│  区别：不增加信息，只是组织已有信息。                    │
│       参数量增加 3~5%（而 EXP005 增加了 45%）。         │
└─────────────────────────────────────────────────────────┘
```

一句话总结：**EXP005 是"加更多"，CataFocus 是"更聚焦"**。

## 十一、用什么实验来验证这个设计

设计讲完了，怎么证明它有效？需要做 4 组实验，这些实验共同构成一个"证据链"。

### 实验一：单独加门控，不加辅助任务

```
配置：基线 + 组件① + 组件③，不加组件②
目的：单独看门控分支的贡献有多大
预期：AUC 比基线高一点点（0.9335 左右）
```

### 实验二：单独加辅助任务，不加门控

```
配置：基线 + 组件②，不加组件①③
目的：单独看辅助任务的贡献
预期：AUC 比基线高一点点（0.9325 左右）
```

### 实验三：完整版（门控 + 辅助任务 + 残差调制）

```
配置：基线 + 全部三个组件
目的：这是完整方法，看综合效果
预期：AUC 0.9370 左右
```

### 实验四：把铁原子位置随机化

```
配置：和实验三完全一样，唯一区别——把每个样本的"铁原子坐标"
     换成图里随机选一个节点的坐标
目的：这是最关键的对照实验（见下一节）
预期：AUC 回落到基线水平（0.9320 左右）
```

## 十二、为什么实验四（铁随机化）是生死线

假设实验三得到 AUC = 0.9370，比基线高 0.005。老师可能质疑：

> "你这个提升，是因为加了新分支、参数变多了，模型容量大了自然表现好。
>  不一定和铁原子有关系。"

这个质疑要用实验四来反驳。

```
实验三：真实铁位置 → AUC = 0.9370
实验四：随机铁位置 → AUC = ?

如果实验四 ≈ 实验三（都是 0.937）：
  说明架构的提升和铁原子没关系，
  只是多了点参数导致的微弱拟合提升。
  我们的方案失败。

如果实验四回到基线水平（0.932）：
  说明唯一的变量就是铁原子位置，
  真实铁位置带来的 0.005 提升，
  完全来自架构利用了铁原子的几何先验。
  我们的方案成功。
```

实验四**必须做**，而且**要先做**。如果它提示方案无效，后续实验就不用做了。

## 十三、可能的失败情况

这个方案不保证成功。可能的失败情况有几种：

### 情况一：baseline 等价性验证不过

```
训练开始前跑一次前向，如果 CataFocus 模型的输出不等于基线模型，
说明零初始化没做对，代码有 bug。
应对：debug 代码。这个问题能解决。
```

### 情况二：门控值全部退化

```
训练几个 epoch 后，所有节点的门控值都接近 0 或者都接近 1。
这说明门控没学到有意义的分数，等于白加了。
应对：调整门控的初始化，或者加门控熵正则化。
```

### 情况三：辅助任务的软标签噪声太大

```
对接结构本身有误差，导致软标签对"哪个原子是氧化位点"给的分布很不合理。
表现是辅助任务的 loss 一直不下降。
应对：退化为"只加门控，不加辅助任务"的版本（实验一）。
```

### 情况四：实验四（随机铁）和实验三差不多

```
这是最致命的情况。说明架构没有真的在学铁原子的几何信息。
应对：停止推进 CataFocus，退回到只讲"结构通道饱和"的评估型故事。
      这时的故事变成：
      "我们系统性地验证了，不管怎么加结构信息，当前架构在当前数据
       规模下都无法突破。未来需要更大数据规模或全新架构范式。"
```

情况四是唯一"方案失败后没法补救"的情况。所以实验四要先做。

## 十四、总结

**现在手上有的**：
- 基线 EXP001_allfix_unified，AUC 0.9320
- 一个关键观察：基线模型已经隐式地关注铁原子周围
- 三次失败的结构增补（EXP002a/EXP003/EXP005）

**我们要做的**：CataFocus-P450，三个组件：
- 组件一：软门控分支——对每个节点打催化相关度分数
- 组件二：氧化位点辅助任务——预测底物哪个原子会被氧化
- 组件三：残差调制——把催化信息叠加回 str_mean

**和之前失败的区别**：
- 不是"加更多信息"，而是"改信息组织方式"
- 不是"局部注入"，而是"全局加权"
- 不是"平等拼接"，而是"残差调制"

**为什么这个设计能成功**：
- EXP002a 失败是因为 Fe 信息在 EGNN 里被局部消息传递稀释
- CataFocus 用 Fe 作全局查询锚点，打分不会被稀释
- 辅助任务提供直接监督信号，让门控学得有意义
- 零初始化保证训练稳定

**怎么验证**：
- 4 组消融实验，尤其是"铁位置随机化"对照
- 如果随机化后性能回到基线，就证明真的是铁原子几何先验在起作用
