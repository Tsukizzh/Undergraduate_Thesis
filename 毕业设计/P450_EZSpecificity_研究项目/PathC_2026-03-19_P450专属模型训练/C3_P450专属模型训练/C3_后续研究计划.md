## 二、各Step详细说明

### Step 06：Fe + 血红素编码（P0，最高优先级）

#### 背景

P450催化完全依赖血红素中心的Fe原子。但现在的模型：
- PDB解析器跳过所有HETATM行 → 血红素在第一步就被丢弃
- 蛋白质原子词汇表没有Fe → 即使进来也编码为全零
- 氨基酸表没有HEM → 被标为UNK（未知）

实测数据（20个含HEM的对接结构）：
- Fe到底物最近原子平均距离 **4.9Å**（中位4.5Å）
- 95%的PDB文件含有血红素（191/200）
- 10Å口袋截距能覆盖90%的Fe

#### 代码改动（2个文件，7处修改）

**protein_ligand.py（4处）：**
1. `_enum_formatted_atom_lines()` — 读HETATM中的HEM残基
2. `_parse()` — HEM原子的aa_type=21, is_backbone=0, is_hetero=1
3. `to_dict_atom()` + `get_zero_protein_feature()` — 输出字典加is_hetero
4. `query_residues_ligand()` — 残基质心距离 → 最近原子距离

**transforms.py（3处）：**
5. `__init__()` — 元素表+Fe(原子序数26)，max_num_aa 21→22
6. `feature_dim` — 28→31（+Fe+HEM+is_hetero）
7. `__call__()` — 拼接时加入is_hetero

structure.py 不需要改（维度从feature_dim动态读取）。

#### 数据管线

```
1. 重新提取口袋 → str_tmp_data_heme/（包含HEM原子）
2. 重新生成结构特征 → structure_features_heme.lmdb（31维）
3. 重建pt_cache → pt_cache_heme/
4. 训练 EXP002a（random_split，对比EXP001 AUC=0.7730）
```

ESM/Morgan/GROVER特征不需要重新生成。

#### 实验设计

- **EXP002a**: Fe + 10Å（与EXP001唯一区别：加了Fe/HEM编码）
- 对比基线：EXP001（无Fe, Test AUC=0.7730）

#### 关键数据

正样本vs负样本Fe-配体距离对比（各50个样本）：
- 正样本：mean=5.0Å, median=4.2Å
- 负样本：mean=5.3Å, median=4.5Å
- **无显著差异**（p=0.637）— Fe距离本身不能区分正负样本
- Fe的价值在于提供催化中心的完整3D上下文和消息传递路径，不在于距离本身

#### 背景

- 其余：无结构

其中AlphaFold DB下载(561)和ColabFold预测(88)使用的都是通用模板或自动搜索的模板。
老师建议用一个特定的P450晶体结构 **6A15**（甾体研究时用过的P450模板）作为自定义模板，
让AF2更多依赖P450特异性的结构信息来预测，从而获得更准确的血红素口袋几何形状。

#### ColabFold命令参考

```bash
colabfold_batch input.fasta ./output/ \
  --custom-template-path templates_6A15 \
  --num-recycle 0 \
  --num-seeds 10 \
  --use-dropout \
  --max-msa 32:64
```

参数说明：
- `--custom-template-path`: 6A15模板目录
- `--num-recycle 0`: 不精化，保留结构多样性
- `--num-seeds 10`: 10次随机采样
- `--use-dropout`: 激活dropout增加多样性
- `--max-msa 32:64`: 限制MSA数量，强制模型更依赖模板结构

所有非实验结构的酶（约1,400+个），全部用AF2 + 6A15模板重新预测。
实验结构（103个RCSB PDB）保留不动。

### Step 09：底物类别辅助MLP（P2）

#### 背景

对应老师的方向："催化哪类底物（萜类？黄酮？生物碱？）：MLP输出层改一下，打分平均按照化合物的类别"。

#### 实现方案

**方案A：辅助训练目标（推荐）**

在模型中间层加一个分支，用C3标签做额外监督：
```
酶序列 → ESM嵌入 → 128维
                      │
         ┌────────────┼────────────┐
         ↓            ↓            ↓
    辅助头           正常流程      辅助头
 "预测底物类别"    交叉注意力   "预测酶家族"(可选)
      │              ↓            │
   辅助损失        主损失       辅助损失

总损失 = 主损失 + α × 辅助损失
```

好处：迫使中间表征学到类别相关信息，但不直接把类别告诉交叉注意力（避免捷径）。

### Step 10：序列<40%相似度划分（P2）

#### 背景

老师要求："1600多个酶按序列划分聚类、序列不同泛化性（test、train中的序列相似度必须低于40%，增加难度）"。

现有的all_split保证训练集和测试集的酶/底物完全不重叠，但没有控制序列相似度。
两个"不同"的酶可能序列相似度高达80%，模型可以从相似酶中"借"信息。

40%相似度阈值意味着测试集里的酶和训练集的任何酶都不超过40%相似——真正的"陌生酶"。

#### 实现

```
1. 用CD-HIT或MMseqs2对1,622个酶序列按40%阈值聚类
2. 以聚类为单位划分train/val/test（同一聚类的酶不能分到不同集合）
3. 生成对应的data.csv和split文件
4. 构建pt_cache
5. 训练并评估
```

#### 预期

AUC会比current all_split低（更难的泛化场景）。这是论文中展示泛化能力的最强证据。

### Step 11：负样本质量验证（P3）

#### 背景

老师提到："负样本中我们底物到底能否被催化"。

我们的负样本是随机配对生成的（固定底物随机配酶 + 固定酶随机配底物）。
有些"负样本"可能实际上是真正的酶-底物对（假负样本），会给训练引入噪声。

#### 实现

- 从负样本中抽检100-200对
- 查文献/数据库验证这些酶是否真的不能催化对应底物
- 估计假负样本率
- 如果假负样本率高，考虑清洗策略

#### 优先级较低的原因

正负比1:10，即使有少量假负样本（比如5%），对训练影响也不大。但对论文数据质量的严谨性论述有帮助。

### Step 12：Fe-催化原子距离选构象（P3）

#### 背景

老师提到："能量选 变成 FE与催化原子的距离去选"。

现在用Uni-Dock的对接能量选最佳构象。但对P450来说，更合理的选择标准是：
**底物被催化的原子离Fe越近，越可能是真实催化构象。**

#### 前置条件

- 需要知道每个底物的哪个原子被P450催化（催化位点标注）
- 这个信息在部分数据源中有（如P450Rdb的反应SMILES标注了反应位点），但不是所有底物都有

#### 实现难点

- 确定催化位点：需要反应SMILES或文献验证
- 多构象对接+距离筛选：每对可能有多个对接构象

#### 优先级较低的原因

我们实测正负样本的Fe-配体距离没有显著差异（p=0.637），说明Uni-Dock已经把底物对接到了合理位置。换用距离选构象可能改善不大，但对论文的生物学故事有价值。

### Step 13：残基级几何特征注入（P1）⭐ 架构创新

> 灵感来源：与EnzymeCAGE（Nature Chem Eng 2025）的对比分析

#### 背景与动机

当前EGNN在原子级别建kNN图（k=48），每个蛋白质原子的特征是one-hot拼接（元素+AA类型+is_backbone+is_hetero = 31维）。EGNN能学到原子间距离和类型，但**学不到残基级别的几何信息**：

- **骨架二面角φ/ψ**：描述蛋白质骨架在每个残基处的弯折方式（N-Cα-C链的扭转）。kNN图不包含骨架链式连接关系，EGNN无法推断这些角度
- **侧链扭转角χ1**：描述侧链从骨架伸出去的方向。对P450尤其重要——口袋腔体的形状由侧链朝向直接决定，同样的氨基酸组成+不同的侧链朝向 = 完全不同的口袋形状和底物选择性

EnzymeCAGE使用GVP-GNN在残基级别编码蛋白质结构，天然包含这些方向信息。我们可以用更轻量的方式获得类似效果。

#### 方案：角度特征拼接到EGNN节点

**不新增GNN模块**，只在数据预处理层面提取φ/ψ/χ1角度，拼接到每个蛋白质原子的特征向量中。

**新增特征（6维）**：
| 特征 | 物理含义 | 编码 | 维度 |
|------|---------|------|------|
| φ (phi) | 骨架弯折角1：C(i-1)─N─Cα─C | sin(φ), cos(φ) | 2 |
| ψ (psi) | 骨架弯折角2：N─Cα─C─N(i+1) | sin(ψ), cos(ψ) | 2 |
| χ1 (chi1) | 侧链朝向：N─Cα─Cβ─Cγ | sin(χ1), cos(χ1) | 2 |

用sin/cos编码的原因：角度是周期性的（-180°和+180°是同一构象），sin/cos避免人为断裂。

**残基→原子广播**：角度是per-residue的，同一残基内所有原子共享该残基的角度值。配体原子和HETATM（Heme）填0。

**维度变化**：31（EXP002a）→ **37**

**代码改动（与EXP002a完全同构）**：
1. `protein_ligand.py`：解析完原子后按残基分组，通过N/Cα/C/Cβ坐标计算二面角，用`Bio.PDB.vectors.calc_dihedral`或手写向量叉乘
2. `transforms.py`：feature_dim 31→37，`__call__`中拼接sin/cos特征
3. `build_pt_cache.py`：新字段的提取、存储、自检
4. `pt_dataset.py`：PROTEIN_FEAT_DIM=37，rebuild_protein_x加入角度特征

**EGNN代码完全不动**——`nn.Linear(37, 128)`自动适配。

#### 资源估算

- 不需要重新提取口袋或重新对接
- 结构特征LMDB重新生成：~1.3GB
- pt_cache重建：~8GB（净增量~0.5GB）
- 训练时间：与EXP002a相同（~2.5小时）

#### 实验设计

- **EXP003a**: EXP002a基线 + φ/ψ/χ1角度特征（random_split）
- 对比：EXP002a（Test AUC=0.7816）

#### 论文价值

- 属于"特征工程层面的P450定制"创新——利用P450活性口袋的几何特性
- 如果有效，为Step 14（双尺度结构编码）提供证据支持

### Step 14：双尺度结构编码（P2）⭐ 架构创新

> 灵感来源：EnzymeCAGE的GVP-GNN + SchNet双编码器设计

#### 背景与动机

如果Step 13验证了残基级几何信息有价值，可以进一步升级为完整的**双图架构**——在现有EGNN旁边新增一条残基级GNN通道：

```
当前（3条通道 + EGNN）:
  ①序列通道（ESM-2）
  ②结构通道（EGNN原子级混合图：口袋蛋白原子+配体原子）
  ③分子通道（GROVER/Morgan）

改造后（3条通道 + EGNN + 新GNN）:
  ①序列通道（ESM-2）
  ②结构通道（EGNN原子级混合图，保留不动）
  ②b 新增通道（残基级蛋白图，只有口袋残基，无配体）
  ③分子通道（GROVER/Morgan）
```

**两张图看同一个口袋的不同层面**：
- EGNN（原子级）：每个原子是什么元素、原子间距离多远、蛋白原子↔配体原子的精细接触
- 新GNN（残基级）：每个残基的类型、残基间空间距离、主链走向、侧链朝向

#### 方案

新增一个轻量GNN（如2层GVP-GNN或简单的GAT），输入为口袋残基图：
- 节点：口袋中~40-50个残基，每个节点特征包含残基类型+φ/ψ/χ1+二级结构
- 边：残基间kNN图（如k=10，基于Cα距离）
- 输出：经过pooling得到128维向量

新GNN的128维输出拼接到预测头输入中：从7个向量(896维)变为**8个向量(1024维)**。
EGNN和交叉注意力模块完全不动。

#### 与Step 13的关系

**Step 13是Step 14的前置验证**：
- Step 13有效 → 残基级信息确实有用 → Step 14值得做（更强的编码能力 + 论文创新点更好）
- Step 13无效 → 残基级信息本身不重要 → Step 14大概率也没用，不值得投入

#### 资源估算

- 额外磁盘：~2.5GB（残基图数据）
- 代码改动：需要新的图构建管线 + 新GNN模块 + ss.py融合逻辑
- 开发周期：1-2周
- 过拟合风险：新GNN增加数万参数，需要注意（dropout=0.9的教训）

#### 论文价值

- **"双尺度结构编码"**作为架构创新点很强——原子级EGNN捕获精细接触，残基级GNN捕获口袋几何形状
- 类似EnzymeCAGE的"GVP + SchNet"双编码器，但针对EZSpecificity架构做了适配
- 可以讲"P450活性口袋的腔体形状由残基侧链朝向决定，单纯的原子级编码无法捕获这一信息"
