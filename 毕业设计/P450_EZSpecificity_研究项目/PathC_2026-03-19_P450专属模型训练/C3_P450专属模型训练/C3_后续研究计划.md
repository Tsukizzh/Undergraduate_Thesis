## 二、各Step详细说明

### Step 06：Fe + 血红素编码（P0，最高优先级）

#### 背景

P450催化完全依赖血红素中心的Fe原子。但现在的模型：
- PDB解析器跳过所有HETATM行 → 血红素在第一步就被丢弃
- 蛋白质原子词汇表没有Fe → 即使进来也编码为全零
- 氨基酸表没有HEM → 被标为UNK（未知）

实测数据（20个含HEM的对接结构）：
- Fe到底物最近原子平均距离 **4.9Å**（中位4.5Å）
- 95%的PDB文件含有血红素（191/200）
- 10Å口袋截距能覆盖90%的Fe

#### 代码改动（2个文件，7处修改）

**protein_ligand.py（4处）：**
1. `_enum_formatted_atom_lines()` — 读HETATM中的HEM残基
2. `_parse()` — HEM原子的aa_type=21, is_backbone=0, is_hetero=1
3. `to_dict_atom()` + `get_zero_protein_feature()` — 输出字典加is_hetero
4. `query_residues_ligand()` — 残基质心距离 → 最近原子距离

**transforms.py（3处）：**
5. `__init__()` — 元素表+Fe(原子序数26)，max_num_aa 21→22
6. `feature_dim` — 28→31（+Fe+HEM+is_hetero）
7. `__call__()` — 拼接时加入is_hetero

structure.py 不需要改（维度从feature_dim动态读取）。

#### 数据管线

```
1. 重新提取口袋 → str_tmp_data_heme/（包含HEM原子）
2. 重新生成结构特征 → structure_features_heme.lmdb（31维）
3. 重建pt_cache → pt_cache_heme/
4. 训练 EXP002a（random_split，对比EXP001 AUC=0.7730）
```

ESM/Morgan/GROVER特征不需要重新生成。

#### 实验设计

- **EXP002a**: Fe + 10Å（与EXP001唯一区别：加了Fe/HEM编码）
- 对比基线：EXP001（无Fe, Test AUC=0.7730）

#### 关键数据

正样本vs负样本Fe-配体距离对比（各50个样本）：
- 正样本：mean=5.0Å, median=4.2Å
- 负样本：mean=5.3Å, median=4.5Å
- **无显著差异**（p=0.637）— Fe距离本身不能区分正负样本
- Fe的价值在于提供催化中心的完整3D上下文和消息传递路径，不在于距离本身

### Step 07：15Å口袋消融（P1）

#### 背景

现在口袋截距10Å，覆盖90%的Fe。15Å可覆盖100%，还能额外捕获：
- 底物通道（substrate access channel）残基
- 更多与血红素配位的外围残基
- 影响口袋形状的第二壳层残基

#### 实现

只需改配置文件 `cutoff: 10` → `cutoff: 15`，代码不用改。
但口袋变大 → 节点数增加 → 需要重新生成结构特征和pt_cache。

#### 实验设计

- **EXP002b**: Fe + 15Å
- 对比：EXP002a（Fe + 10Å）— 评估口袋大小的边际贡献

可与Step 06共享代码改动，只是cutoff参数不同。两套特征可以同时生成。

### Step 08：6A15模板重预测结构（P1）

#### 背景

现有酶结构来源：
- 103个：RCSB实验结构（高质量，不需要重新预测）
- 246个：PCPD预测结构
- 493个：AlphaFill（含血红素的AF2结构）
- 561个：AlphaFold DB下载 + 血红素移植
- 88个：ColabFold自动模板预测
- 其余：无结构

其中AlphaFold DB下载(561)和ColabFold预测(88)使用的都是通用模板或自动搜索的模板。
老师建议用一个特定的P450晶体结构 **6A15**（甾体研究时用过的P450模板）作为自定义模板，
让AF2更多依赖P450特异性的结构信息来预测，从而获得更准确的血红素口袋几何形状。

#### ColabFold命令参考

```bash
colabfold_batch input.fasta ./output/ \
  --custom-template-path templates_6A15 \
  --num-recycle 0 \
  --num-seeds 10 \
  --use-dropout \
  --max-msa 32:64
```

参数说明：
- `--custom-template-path`: 6A15模板目录
- `--num-recycle 0`: 不精化，保留结构多样性
- `--num-seeds 10`: 10次随机采样
- `--use-dropout`: 激活dropout增加多样性
- `--max-msa 32:64`: 限制MSA数量，强制模型更依赖模板结构

#### 需要重新预测的酶

所有非实验结构的酶（约1,400+个），全部用AF2 + 6A15模板重新预测。
实验结构（103个RCSB PDB）保留不动。

#### 基础设施

- 需要在Cloud-2上安装ColabFold（wanglab太慢）
- 或者考虑其他GPU云服务器

#### 数据管线

```
1. 安装ColabFold到Cloud-2
2. 准备6A15模板文件
3. 批量预测~1,400个酶的结构
4. 血红素移植（新结构 + HEM）
5. 重新对接（Uni-Dock，全部50K对）
6. 重新生成全部特征
7. 重建pt_cache
8. 训练EXP003
```

工作量最大的一个Step，建议等Step 06/07结果出来后再启动。

### Step 09：底物类别辅助MLP（P2）

#### 背景

对应老师的方向："催化哪类底物（萜类？黄酮？生物碱？）：MLP输出层改一下，打分平均按照化合物的类别"。

Step 05（底物分类v6 FINAL）已完成，2,125个化合物分为7类：
Terpenoid(484), Amino_acid(388), Fatty_acid(278), Alkaloid(251), Steroid(211), Phenylpropanoid(176), Polyketide(137), Other(255)。

#### 实现方案

**方案A：辅助训练目标（推荐）**

在模型中间层加一个分支，用C3标签做额外监督：
```
酶序列 → ESM嵌入 → 128维
                      │
         ┌────────────┼────────────┐
         ↓            ↓            ↓
    辅助头           正常流程      辅助头
 "预测底物类别"    交叉注意力   "预测酶家族"(可选)
      │              ↓            │
   辅助损失        主损失       辅助损失

总损失 = 主损失 + α × 辅助损失
```

好处：迫使中间表征学到类别相关信息，但不直接把类别告诉交叉注意力（避免捷径）。

**方案B：按类别报告AUC（论文Fig用）**

不改模型，只在测试时按底物类别分组，分别计算AUC：
```
全部测试集 AUC = 0.773
  Terpenoid   AUC = ???
  Alkaloid    AUC = ???
  Steroid     AUC = ???
  ...
```

这可以直接做，不需要改模型，用于论文Fig 4。

#### 前置条件

- Step 05 底物分类数据（已完成）
- 需要将底物类别标签映射到训练数据中

### Step 10：序列<40%相似度划分（P2）

#### 背景

老师要求："1600多个酶按序列划分聚类、序列不同泛化性（test、train中的序列相似度必须低于40%，增加难度）"。

现有的all_split保证训练集和测试集的酶/底物完全不重叠，但没有控制序列相似度。
两个"不同"的酶可能序列相似度高达80%，模型可以从相似酶中"借"信息。

40%相似度阈值意味着测试集里的酶和训练集的任何酶都不超过40%相似——真正的"陌生酶"。

#### 实现

```
1. 用CD-HIT或MMseqs2对1,622个酶序列按40%阈值聚类
2. 以聚类为单位划分train/val/test（同一聚类的酶不能分到不同集合）
3. 生成对应的data.csv和split文件
4. 构建pt_cache
5. 训练并评估
```

#### 预期

AUC会比current all_split低（更难的泛化场景）。这是论文中展示泛化能力的最强证据。

### Step 11：负样本质量验证（P3）

#### 背景

老师提到："负样本中我们底物到底能否被催化"。

我们的负样本是随机配对生成的（固定底物随机配酶 + 固定酶随机配底物）。
有些"负样本"可能实际上是真正的酶-底物对（假负样本），会给训练引入噪声。

#### 实现

- 从负样本中抽检100-200对
- 查文献/数据库验证这些酶是否真的不能催化对应底物
- 估计假负样本率
- 如果假负样本率高，考虑清洗策略

#### 优先级较低的原因

正负比1:10，即使有少量假负样本（比如5%），对训练影响也不大。但对论文数据质量的严谨性论述有帮助。

### Step 12：Fe-催化原子距离选构象（P3）

#### 背景

老师提到："能量选 变成 FE与催化原子的距离去选"。

现在用Uni-Dock的对接能量选最佳构象。但对P450来说，更合理的选择标准是：
**底物被催化的原子离Fe越近，越可能是真实催化构象。**

#### 前置条件

- 需要知道每个底物的哪个原子被P450催化（催化位点标注）
- 这个信息在部分数据源中有（如P450Rdb的反应SMILES标注了反应位点），但不是所有底物都有

#### 实现难点

- 确定催化位点：需要反应SMILES或文献验证
- 多构象对接+距离筛选：每对可能有多个对接构象

#### 优先级较低的原因

我们实测正负样本的Fe-配体距离没有显著差异（p=0.637），说明Uni-Dock已经把底物对接到了合理位置。换用距离选构象可能改善不大，但对论文的生物学故事有价值。
