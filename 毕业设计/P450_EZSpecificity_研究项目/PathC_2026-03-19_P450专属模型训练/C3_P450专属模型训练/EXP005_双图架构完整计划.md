## 一、核心设计（Option 2+，经 codex 三轮讨论定稿）

### 1.1 架构图

在现有 SS 模型基础上新增一条 **GVP 残基级图神经网络通路**，该通路对每个 pocket 残基输出一个 128 维向量 `h_res`，然后走**双出口**：

1. **出口 1（h_res → x_pro 残基注入）**：把 h_res 按 `pocket_residue_idx` 注入到酶序列表示 `x_pro` 的对应位置，让 GVP 信号参与后续双向交叉注意力
2. **出口 2（g_res → 末端拼接）**：对 h_res 做 scatter_mean 得到图级向量 `g_res [128]`，直接拼接到末端预测头前（第 8 个向量）

**概念类比**：
- 原子级 EGNN = 看精细接触
- 残基级 GVP = 看口袋整体几何形状（SE(3)-等变，首次引入真正的方向向量信号）
- h_res = 残基级细节灌回酶序列
- g_res = 残基图全局总结直通预测头

### 1.2 与 EXP001/002a/003 的关键差异

| 维度 | EXP001 (bare) | EXP002a (Fe/HEM) | EXP003 (残基几何) | **EXP005 (dualgraph 2+)** |
|---|---|---|---|---|
| feature_dim | 28 | 31 | 37 | **28（回到 bare）** |
| 结构通路 | 1（原子 EGNN，标量距离不变）| 1 | 1 | **2（原子 EGNN + 残基 GVP）** |
| 几何信息 | 标量距离 | + Fe/HEM 原子 | + 残基标量角度 | **+ 真实 3D 方向向量** |
| 等变性 | SE(3) 不变 | 同 | 同 | **真 SE(3) 等变** |
| Header 输入 | 896 (7×128) | 同 | 同 | **1024 (8×128)** for v1/v3; 896 for v2 |
| vs 0.9320 | **0.9320 基线** | 0.9270 (-0.005) | 0.9300 (-0.002) | **待测** |

### 1.3 为什么做 2+ 而不是选项 ①（late concat）

选项 ① 只加 g_res 到末端拼接，简单但融合深度浅。**2+ 的关键是 h_res → x_pro 残基注入让 GVP 信号提前参与主干交叉注意力**，是真正的"双图"。

之前最担心 `pocket_residue_idx` 对齐问题，但 **Step 1 验证通过**（详见第二节）——以为可以安心做。**然而 Step 3 发现了另一类对齐 bug**（pocket PDB 残基编号和 Enzymes.csv 序列位置不匹配，详见第四节）。

### 1.4 4 个融合方案的对比（2026-04-13 决策文档里定的）

来源：`毕业设计/P450_EZSpecificity_研究项目/PathC_2026-03-19_P450专属模型训练/C3_P450专属模型训练/EXP004_决策1_融合方式图解.md`（697 行）

**选项 ①（late concat）**：
- GVP 通路完全独立到底，只把 `g_res` 作为第 8 个向量塞进最后拼接
- `h_res` 不使用，残基级细节被丢弃
- 改动最小：~100 行代码
- 优点：干净单变量对比、失败回退零成本、训练稳定
- 缺点：融合深度浅，两个通路只在预测头才见面

**选项 ②（residue backfill）**：
- GVP 输出 `h_res [N_pocket, 128]`
- 按 `pocket_residue_idx` 注入到 `x_pro` 的对应位置：`x_pro_enhanced[idx] += alpha * LN(Linear(h_res))`
- 不输出 g_res
- 进入交叉注意力的是 enhanced x_pro，底物原子 attention 时看到的酶表示已经带残基几何
- 优点：深融合
- 缺点：索引对齐风险最高（`pocket_residue_idx` 必须严格对应 ESM 序列位置）

**选项 ②+（residue backfill + g_res bypass）【当前选定】**：
- 选项 ② 的增强：除了 h_res 注入，还保留 g_res 直接 bypass 到末端拼接
- 双出口：h_res 走注意力前注入 + g_res 走末端拼接
- 预测头输入：8 × 128 = 1024（比 baseline 的 7 × 128 = 896 多一个向量）
- 对称 EZSpecificity 原作者的结构通道双出口设计（`x_str` 进注意力 + `str_mean` 进末端）
- 用户选定的方案

**选项 ③（跨尺度注意力）**：
- 新增跨尺度注意力模块：底物原子作为 Q，GVP 残基嵌入 `h_res` 作为 K/V
- 通过 softmax 自动学习"哪个残基对哪个原子最重要"
- 上限最高但代码复杂度最高、训练不稳定性风险大
- 不做

**选项 ④（双塔独立 + 末端加权）**：
- 完整两条预测管道，末端 `α * logit_1 + (1-α) * logit_2` 融合
- 参数量翻倍，过拟合风险高
- 不做

### 1.5 codex 对 2+ 方案的评价（round 1 原话翻译）

> 你们选的 2+ 方案在架构理念上是成立的，甚至比文档里的选项 ① 更符合最初"双尺度互补"的目标。原因是它解决了一个关键问题：现有模型里，酶侧的主干表示 x_pro 基本来自序列嵌入；结构侧虽然有原子级图，但主要通过 x_str 和 str_mean 走到底物/结构分支。`src/Models/ss.py` 里可以看到，x_pro 和 x_reaction 做交叉注意力，而 str_mean 只是最后再拼接。也就是说，**酶侧"残基级几何"一直没有以独立通道深度进入主交互**。2+ 正好补这个洞。

> 但 2+ 的最大风险不是 GVP，也不是训练不收敛，而是**对齐**。真正决定成败的是：`pocket_residue_idx` 能不能和 `x_pro` 的序列位置严格一一对应。口袋残基提取顺序、PDB 残基编号、ESM 输入序列编号，这三套索引能不能闭环验证。

> **值得做，但必须按"数据对齐先行、模型接入第二、训练第三"的顺序推进**。不能先写 GVP 模块，再回头补索引。

## 二、已完成工作（Step 1 + Step 2）

### 2.0 前置技术背景：pt_cache 的三层存储结构

必须先理解 pt_cache 才能理解后续步骤。`pt_cache_allfix_unified/random/` 的结构：

```
pt_cache_allfix_unified/random/
├── manifest.pt                     # 元数据
├── enzymes/
│   ├── enzymes.bin                 # 所有酶的 ESM 嵌入顺序拼接（fp16 二进制）
│   └── enzymes_index.pt            # {enzyme_global_id: (byte_offset, seq_len)}
├── substrates/
│   ├── substrates_grover.bin       # 所有底物的 GROVER 原子嵌入顺序拼接（fp16）
│   ├── substrates_meta.pt          # GROVER mean [N,4885] + Morgan [N,1024]
│   └── substrates_index.pt         # {substrate_global_id: (byte_offset, atom_len, meta_row)}
├── train/
│   ├── index.pt                    # 样本索引：dict of 5 arrays
│   └── samples/
│       ├── 000/
│       │   ├── sample_000000.pt
│       │   └── ...
│       └── NNN/
├── val/（同上结构）
└── test/（同上结构）
```

**index.pt 的格式**（3 个 split 各一份）：
```python
{
    'sample_ids':    int32 [N],  # 在 split CSV 里的 0-indexed 行号，允许有 gap
    'enzyme_ids':    int32 [N],  # 酶的 global_id，对应 enzymes_index.pt 的 key
    'substrate_ids': int32 [N],  # 底物的 global_id
    'graph_shards':  int16 [N],  # (legacy) shard id，per-sample 布局下未用
    'graph_rows':    int32 [N],  # (legacy) row within shard
}
```

**sample_*.pt 文件的字段**（通过 recon 查到的真实字段）：
```python
{
    'ligand_pos':         float32 [n_lig, 3],
    'ligand_element':     uint8 [n_lig],
    'ligand_atom_aux':    uint8 [n_lig, 4],      # degree/charge/aromatic/hydrogen
    'ligand_index_raw':   int32 [n_lig],         # 原子在 SMILES 里的位置
    'protein_pos':        float32 [n_prot, 3],   # 原子坐标（去 H，pocket 范围）
    'protein_element':    uint8 [n_prot],
    'protein_aa_type':    uint8 [n_prot],        # 每个原子所属残基的氨基酸类型 (0-20)
    'protein_is_backbone': uint8 [n_prot],       # 是不是 N/CA/C/O
    'bond_index':         int32 [2, n_bonds],    # 底物内部键
    'bond_type':          uint8 [n_bonds],
    'knn_edge_index':     int32 [2, n_knn],      # 蛋白-底物 kNN 图（非常大，~17k）
    'enzyme_id':          int,                    # 对应 enzymes_index 的 key
    'substrate_id':       int,                    # 对应 substrates_index 的 key
    'dataset_id':         int,                    # 数据集 tag (0=brenda...)
    'str_tag_code':       int,                    # complex/ligand 标志
    'label':              int,                    # 0 or 1
    'sample_weight':      float,
}
```

**关键发现（recon 阶段）**：
- sample_*.pt 里**没有 `dock_index` / `pocket_id` / `residue_idx` 字段**
- 只有原子级 tensor，没有残基级的映射信息
- 这就是为什么我们需要建 dock_sidecar

### 4.5 复用的暴力 delta 检测算法（作为 fallback）

即使溯源找到 bug 并从源头修复，也可能有少量残留 case 无法修好（比如 RCSB 实验结构的 N 端真的缺失）。codex 建议保留一个 delta 检测作为 fallback：

```python
def find_best_delta(residues, seq, delta_range=200):
    """residues: list of (resid, one_letter_aa); seq: str of full enzyme sequence"""
    best_delta, best_match, best_total = 0, -1, 0
    for delta in range(-delta_range, delta_range + 1):
        match, total = 0, 0
        for resid, aa in residues:
            idx = resid + delta - 1
            if 0 <= idx < len(seq):
                total += 1
                if seq[idx] == aa:
                    match += 1
        if total == 0:
            continue
        if match > best_match or (match == best_match and total > best_total):
            best_match, best_delta, best_total = match, delta, total
    return best_delta, best_match, best_total
```

**已验证有效**（6 个测试 case 100% 修复）：
- dock=3 (alphafill): delta=0, match=507/507
- dock=8444 (pcpd_predicted): delta=0, match=481/481（结构从 resid=43 开始但编号延续）
- dock=34 (short): delta=0, match=213/213
- dock=24 (experimental_pdb): **delta=+1**, match=456/456
- dock=985 (enzyme 54): **delta=+1**, match=468 complex 里 93.2%（32 个点突变），但 pocket 77/77 全对
- dock=30789 (enzyme 952): **delta=+68**（结构截掉 N 端 68 个残基），match=56/56 in pocket

```python
def _normalize(tensor, dim=-1):
    """Normalize with NaN safety."""
    return torch.nan_to_num(
        torch.div(tensor, torch.norm(tensor, dim=dim, keepdim=True)))

def _rbf(D, D_min=0., D_max=20., D_count=16, device='cpu'):
    """Radial Basis Function embedding of distances."""
    D_mu = torch.linspace(D_min, D_max, D_count, device=device).view([1, -1])
    D_sigma = (D_max - D_min) / D_count
    D_expand = torch.unsqueeze(D, -1)
    return torch.exp(-((D_expand - D_mu) / D_sigma) ** 2)

def _dihedrals(X, eps=1e-7):
    """
    Compute phi, psi, omega dihedrals.
    Input X: [N, 3, 3] = (N, CA, C) per residue
    Output: [N, 6] = cos(phi), cos(psi), cos(omega), sin(phi), sin(psi), sin(omega)
    """
    X = torch.reshape(X[:, :3], [3*X.shape[0], 3])
    dX = X[1:] - X[:-1]
    U = _normalize(dX, dim=-1)
    u_2, u_1, u_0 = U[:-2], U[1:-1], U[2:]
    n_2 = _normalize(torch.cross(u_2, u_1), dim=-1)
    n_1 = _normalize(torch.cross(u_1, u_0), dim=-1)
    cosD = torch.clamp(torch.sum(n_2 * n_1, -1), -1 + eps, 1 - eps)
    D = torch.sign(torch.sum(u_2 * n_1, -1)) * torch.acos(cosD)
    D = F.pad(D, [1, 2])   # phi[0], psi[-1], omega[-1] are undefined
    D = torch.reshape(D, [-1, 3])
    return torch.cat([torch.cos(D), torch.sin(D)], 1)

def _orientations(X_ca):
    """Forward and backward C-alpha direction vectors."""
    forward = _normalize(X_ca[1:] - X_ca[:-1])
    backward = _normalize(X_ca[:-1] - X_ca[1:])
    forward = F.pad(forward, [0, 0, 0, 1])
    backward = F.pad(backward, [0, 0, 1, 0])
    return torch.cat([forward.unsqueeze(-2), backward.unsqueeze(-2)], -2)

def _sidechains(X):
    """
    Virtual sidechain direction from backbone atoms.
    Input X: [N, 4, 3] = (N, CA, C, O) per residue
    Output: [N, 3] = unit vector pointing "down" from CA (where Cbeta would be)
    """
    n, origin, c = X[:, 0], X[:, 1], X[:, 2]
    c, n = _normalize(c - origin), _normalize(n - origin)
    bisector = _normalize(c + n)
    perp = _normalize(torch.cross(c, n))
    return -bisector * math.sqrt(1/3) - perp * math.sqrt(2/3)

def _positional_embeddings(edge_index, num_embeddings=16, period_range=[2, 1000]):
    """Sinusoidal positional encoding based on residue index difference."""
    d = edge_index[0] - edge_index[1]
    frequency = torch.exp(
        torch.arange(0, num_embeddings, 2, dtype=torch.float32)
        * -(np.log(10000.0) / num_embeddings))
    angles = d.unsqueeze(-1) * frequency
    return torch.cat((torch.cos(angles), torch.sin(angles)), -1)
```

### 5.2.3 GVP_embedding 顶层类（从 EnzymeCAGE `model.py:68-115`）

这是我们要用的顶层包装器，输入残基级图，输出 `[N_res, 128]` 纯标量：

```python
class GVP_embedding(nn.Module):
    def __init__(self, node_in_dim, node_h_dim,
                 edge_in_dim, edge_h_dim,
                 seq_in=False, num_layers=3, drop_rate=0.1):
        super().__init__()
        if seq_in:
            self.W_s = nn.Embedding(20, 20)
            node_in_dim = (node_in_dim[0] + 20, node_in_dim[1])

        self.W_v = nn.Sequential(
            LayerNorm(node_in_dim),
            GVP(node_in_dim, node_h_dim, activations=(None, None))
        )
        self.W_e = nn.Sequential(
            LayerNorm(edge_in_dim),
            GVP(edge_in_dim, edge_h_dim, activations=(None, None))
        )

        self.layers = nn.ModuleList(
            GVPConvLayer(node_h_dim, edge_h_dim, drop_rate=drop_rate)
            for _ in range(num_layers))

        ns, _ = node_h_dim
        self.W_out = nn.Sequential(
            LayerNorm(node_h_dim),
            GVP(node_h_dim, (2*ns, 0))  # 关键！向量通道扔掉，输出纯标量 [N, 2*ns]
        )

    def forward(self, h_V, edge_index, h_E, seq=None):
        """
        :param h_V: (node_s [N, 6], node_v [N, 3, 3])
        :param edge_index: [2, E]
        :param h_E: (edge_s [E, 32], edge_v [E, 1, 3])
        :return: scalar tensor [N, 2*ns] = [N, 128]
        """
        if seq:
            seq = self.W_s(seq)
            h_V = (torch.cat([h_V[0], seq], dim=-1), h_V[1])
        h_V = self.W_v(h_V)
        h_E = self.W_e(h_E)
        for layer in self.layers:
            h_V = layer(h_V, edge_index, h_E)
        out = self.W_out(h_V)
        return out  # [N_res, 128] pure scalar
```

## 六、关键设计决策（来自 3 轮 codex 讨论）

### 6.0 三轮 codex 讨论的完整问答记录（Q1-Q20）

#### Round 1（架构和依赖评估）

**Q1：checkpoint 加载兼容性**
- 我们的 SS 类和上游 paper 用的是同一份代码，state_dict 应该能直接 load
- codex：**如果用 `strict=True` 加载成功且没有 missing/unexpected keys，就是安全的**。如果需要 `strict=False`，要审计忽略的 key 是不是都是无关的 buffer

**Q2：edge-mode 在 dataset 运行时切换**
- 我们 `--edge-mode` 是 runtime flag，同一份 cache 能同时跑 legacy 和 fixed
- codex：确认 `__getitem__` 时构造 edge_attr，cache 是 edge-agnostic 的，没问题

**Q3：用 PyG Data 子类还是 dict**
- codex：**必须用子类 `DualgraphSequenceData(StructureSequenceData)`**，因为 PyG 的批处理机制通过 `__inc__` 和 `__cat_dim__` 方法处理节点/边索引的偏移，只有子类能正确 override

**Q4：GVP 输入特征的 shape 和内容**
- codex 确认用 EnzymeCAGE 原论文的 (6, 3) → (64, 16) → (32, 1) → (32, 1) 参数
- 输出纯标量 [N, 128]

**Q5：数据存储策略**
- codex：**用 per-dock .pt 或 shard .pt，不要用 LMDB**，因为我们之前踩过 LMDB 的 key mapping bug（ESM + GROVER）
- 最终选 per-dock（和现有 pt_cache 一致）

**Q6：提前 dock_index 字段**
- 我们 sample_*.pt 里没有 dock_index，只有 enzyme_id/substrate_id
- codex：**split 级 row-aligned sidecar** 是最干净方案。不要改 sample_*.pt

**Q7：pocket_residue_idx 的语义**
- codex：必须是**酶全长序列里的 0-indexed 位置**，对应 `x_pro[sample, j, :]` 的 j

#### Round 2（数据对齐和边界情况）

**Q8：join 整合机制**
- codex：**先用 Step 1 的 sample_id → CSV row 关系建 sidecar**，不要用 (enzyme_id, substrate_id) 三元组做 join（后者可能不唯一）

**Q9：insertion code 处理**
- codex：扫全量 50177 pockets 统计有多少
- 我们扫完发现 **0 个 insertion code**，这个风险可以排除

### 11.3 SS 模型 forward 完整逻辑（`src/Models/ss.py`）

```python
def forward(self, G):
    # 1. ESM embedding → x_pro
    x_pro = self.protein_mlp(G.embedding)
    x_pro = x_pro.view(-1, 1450, self.hidden_dim)  # [B, 1450, 128]

    # 2. 原子级 EGNN（结构通路）
    atom_features = []
    if self.config.model.use_gnn:
        str_mean, x_str = self._get_graph_output(G, x_pro.shape[0])  # str_mean [B, 128], x_str [B, 280, 128]
        atom_features.append(x_str)

    # 3. GROVER 分子嵌入
    if "grover" in self.config.data.atom_features:
        grover = G.grover.view(-1, 280, int(self.config.data.atom_features[1]))
        grover = self.atom_feature_mlp_dict["grover"](grover)
        atom_features.append(grover)

    # 4. 底物原子特征聚合
    x_reaction = self.atom_feature_aggregator(atom_features)  # [B, 280, 128]

    # 5. 双向交叉注意力
    if self.use_attention:
        weighted_sum_pro, _ = self.enzyme_attention(
            x_pro, x_reaction, x_reaction,
            need_weights=True, key_padding_mask=G.reaction_padding_mask)
        weighted_sum_reaction, _ = self.reaction_attention(
            x_reaction, x_pro, x_pro,
            need_weights=True, key_padding_mask=G.enzyme_padding_mask)

    # 6. Masked mean pooling
    reaction_mask = (~G.reaction_padding_mask).unsqueeze(-1).float()
    enzyme_mask = (~G.enzyme_padding_mask).unsqueeze(-1).float()
    x_reaction = (x_reaction * reaction_mask).sum(dim=1) / reaction_mask.sum(dim=(1,2)).unsqueeze(-1)
    x_pro = (x_pro * enzyme_mask).sum(dim=1) / enzyme_mask.sum(dim=(1,2)).unsqueeze(-1)
    if self.use_attention:
        weighted_sum_reaction = (weighted_sum_reaction * reaction_mask).sum(dim=1) / reaction_mask.sum(dim=(1,2)).unsqueeze(-1)
        weighted_sum_pro = (weighted_sum_pro * enzyme_mask).sum(dim=1) / enzyme_mask.sum(dim=(1,2)).unsqueeze(-1)

    # 7. 末端拼接 7 个向量
    embeddings = [x_pro, x_reaction]
    if self.use_attention:
        embeddings.extend([weighted_sum_pro, weighted_sum_reaction])
    if self.config.model.use_gnn:
        embeddings.extend([str_mean])
    if "grover_mean" in self.config.data.features:
        embeddings.append(self.feature_mlp_dict["grover_mean"](G.grover_mean))
    if "morgan" in self.config.data.features:
        embeddings.append(self.feature_mlp_dict["morgan"](G.morgan))

    # 8. 预测头（896 → 128 → 128 → 1）
    specificity_output = self.specificity_header(embeddings)
    return specificity_output, [G.tag, G.str_tag]
```

EXP005 的改动点：
- 在 step 1 之后、step 5 之前插入 GVP 通路和 h_res 注入
- 在 step 7 的 embeddings list 里追加 g_res（变 8 个向量）
- 在 SS.__init__ 里让 `specificity_header` 支持 896 和 1024 两种输入维度

### 11.4 我们自己写的 kNN（替代 torch_cluster.knn_graph）

```python
def knn_graph_custom(X_ca, k=30):
    """
    Returns edge_index [2, E] with E = N * min(k, N-1).
    For each node, connect to k nearest neighbors (excluding self).
    Deterministic: topk with sorted=True, stable tie-break by index.
    """
    N = X_ca.shape[0]
    if N < 2:
        return torch.zeros(2, 0, dtype=torch.long, device=X_ca.device)
    dist = torch.cdist(X_ca, X_ca, p=2)
    dist.fill_diagonal_(float("inf"))  # exclude self
    k_eff = min(k, N - 1)
    _, nbr_idx = torch.topk(dist, k_eff, dim=1, largest=False, sorted=True)
    src = torch.arange(N, device=X_ca.device).unsqueeze(1).expand(-1, k_eff).reshape(-1)
    dst = nbr_idx.reshape(-1)
    return torch.stack([src, dst], dim=0)  # [2, N * k_eff]
```

### 11.5 PyG 子类化（关键！）

```python
from torch_geometric.data import Data

class DualgraphSequenceData(StructureSequenceData):
    """PyG batching overrides for dualgraph extra fields."""

    def __inc__(self, key, value, *args, **kwargs):
        if key == "gvp_edge_index":
            return self.gvp_node_s.size(0)  # node count offset (for edge index)
        if key == "pocket_residue_idx":
            return 0  # NO offset; this is an absolute sequence position
        return super().__inc__(key, value, *args, **kwargs)

    def __cat_dim__(self, key, value, *args, **kwargs):
        if key == "gvp_edge_index":
            return 1  # [2, E] concat along dim 1
        if key in {"gvp_node_s", "gvp_node_v", "gvp_edge_s", "gvp_edge_v", "pocket_residue_idx"}:
            return 0  # concat along dim 0
        return super().__cat_dim__(key, value, *args, **kwargs)
```

**关键坑**：`PtCacheDualgraphDataset.__getitem__` 必须返回 `DualgraphSequenceData` 实例，不能返回 `StructureSequenceData` 再事后改属性。PyG 的批处理是通过对象的 class method 查 `__inc__`/`__cat_dim__` 的，基类返回后 set attribute 不会触发子类行为。

### 11.6 h_res 批量注入（index_add_ 版本，不用 for loop）

```python
# x_pro: [B, 1450, hidden_dim]
# h_res_all: [sum_N_pocket, 128]（PyG 批处理后拼接的所有 pocket 残基）
# gvp_batch: [sum_N_pocket]（每个残基所属 batch idx）
# G.pocket_residue_idx: [sum_N_pocket]（每个残基对应的 seq 位置）

# 投影 + layer norm
h_res_proj = self.h_res_proj(h_res_all)  # [sum_N, hidden_dim]

# 学习门控
alpha = torch.sigmoid(self.alpha_param)  # 标量，初始 sigmoid(-2.2) ≈ 0.1

# 批量 scatter 注入
B = x_pro.shape[0]
x_pro_flat = x_pro.view(B * 1450, self.hidden_dim)  # [B*1450, 128]
abs_idx = gvp_batch * 1450 + G.pocket_residue_idx    # [sum_N] 每个残基的绝对位置
x_pro_flat.index_add_(0, abs_idx, alpha * h_res_proj)
x_pro = x_pro_flat.view(B, 1450, self.hidden_dim)
```

**注意**：这里没有考虑 padding 溢出。如果某个 `pocket_residue_idx[i] >= seq_len`，会注入到 padding 区域，虽然后续 attention 会 mask 掉，但更严谨的做法是在 dataset 构造时就确保 `pocket_residue_idx < seq_len`。

### 11.9 暴力 delta 检测算法

```python
def find_best_delta(residues, seq, delta_range=200):
    """
    residues: list of (resid, one_letter_aa)
    seq: enzyme full sequence string
    Returns: (best_delta, best_match, best_total)
    """
    best_delta, best_match, best_total = 0, -1, 0
    for delta in range(-delta_range, delta_range + 1):
        match, total = 0, 0
        for resid, aa in residues:
            idx = resid + delta - 1
            if 0 <= idx < len(seq):
                total += 1
                if seq[idx] == aa:
                    match += 1
        if total == 0:
            continue
        if match > best_match or (match == best_match and total > best_total):
            best_match, best_delta, best_total = match, delta, total
    return best_delta, best_match, best_total
```
