## 1. 硬负样本重构

**发现日期**：2026-03-09
**灵感来源**：EnzymeCAGE (Nat Catal 2026) + Path B 假说验证

### 问题

EZSpecificity 使用单向随机采样生成负样本（固定底物、随机配对酶），EC 层级难度 0-5 混合。我们的 P450 任务约等于难度 3，但 ESIBank P450 在难度≥3 时仅 AUC=0.549，与我们的 0.517 仅差 0.032。**负样本太容易是崩溃的首要原因。**

### 改进方案

借鉴 EnzymeCAGE 的硬负样本策略：

1. **同源酶负样本**（序列相似度 >40%）：同是 P450 但催化不同底物的酶作为负样本
2. **反应模板扰动**：对正样本的底物/产物用 RXNMapper 生成结构相似但不被催化的底物
3. **抑制剂/非底物配体**：利用 PDB 中已知的 P450 抑制剂作为负底物
4. **比例控制**：同源:远源 = 2:1（EnzymeCAGE 验证的最优比例）

### 预期收益

- 直接消除"底物身份捷径"——负样本与正样本的底物结构相似，迫使模型学习酶-底物交互
- EXP01（晶体+抑制剂负样本）AUC=0.71 已证明更好的负样本可大幅提升性能
- 与论文 HaloS 微调策略一致（~3,300 对 → 91.7% Top-1）

### 实施难度：中

需要整理 P450 底物/抑制剂数据库（可从 BRENDA、ChEMBL 获取），编写负样本生成脚本。

### 风险

- 负标签噪声：某些"抑制剂"可能在特定条件下也是底物
- 数据量可能不足：高质量 P450 底物-抑制剂标签稀缺

## 2. 对比学习检索范式（CLIP-style）

**发现日期**：2026-03-09
**灵感来源**：EnzymeCAGE (Nat Catal 2026) + DrugCLIP (Science 2026)

### 问题

当前 EZSpecificity 使用二分类 BCEWithLogitsLoss，容易退化为记忆底物全局分布的分类器。DrugCLIP 在数学上证明对比学习比回归/分类对坐标噪声更鲁棒（这在 AlphaFold 预测结构场景下至关重要）。

### 改进方案

将任务从"二分类"转为"对比检索"：

```
酶编码器 g_φ(enzyme) → 酶嵌入向量 (归一化)
底物编码器 f_θ(substrate) → 底物嵌入向量 (归一化)

loss = InfoNCE(正对 vs batch内负对)
推理 = cosine_similarity(酶, 底物) → 排序
```

核心变化：
- 双塔架构，酶和底物独立编码后通过点积相似度交互
- Batch 内负采样（与硬负样本策略配合）
- 评估指标从 AUC-ROC 转向 Top-k 检索准确率、MRR

### 预期收益

- DrugCLIP 论证：在 DUD-E 上零样本 AUROC=80.93%，超越 Glide/Vina 等对接方法
- EnzymeCAGE 论证：1.5M 对上训练后，Top-10 成功率 58%（未见酶）
- 天然避免"底物身份捷径"——排序任务迫使模型区分不同酶对同一底物的催化能力

### 实施难度：中

需要重写训练循环（InfoNCE loss）、batch 构建逻辑、评估指标。模型编码器可复用。

### 风险

- 需要强 batch 设计和硬负样本挖掘，否则 trivial negatives 仍会导致捷径
- 对比学习对 batch size 敏感，12GB VRAM 可能限制 batch 大小

## 3. 反平衡批次设计（Anti-Shortcut Batching）

**发现日期**：2026-03-09
**灵感来源**：Path B E4 诊断（R²(底物)=0.37）+ Codex 分析

### 问题

当前训练中，每个 batch 的底物分布不均——某些底物出现频率远高于其他底物。模型发现"只看底物就能猜对大部分标签"，于是退化为底物分类器。

### 改进方案

构建"反平衡"批次：

1. **同底物多酶批次**：每个 batch 包含同一底物与多个不同酶的配对（正+负），迫使模型关注酶的差异
2. **同酶多底物批次**：每个 batch 包含同一酶与多个不同底物的配对，迫使模型关注底物结合特异性
3. **残差化损失**：先用底物-only 基线预测得分，再对残差进行训练（类似 E4 诊断中的分数分解思路）

```python
# 伪代码：残差化训练
substrate_baseline = substrate_only_model(substrate)  # 冻结
residual_target = true_label - substrate_baseline
loss = BCE(model_output - substrate_baseline, residual_target)
```

### 预期收益

- 直接攻击 R²(底物)=0.37 的捷径——如果 batch 内底物相同，底物特征无法区分正负
- 实施门槛低，不需要改架构，只改 DataLoader
- 可与任何其他创新点叠加

### 实施难度：低-中

改写 DataLoader/Sampler 即可，核心模型不变。

### 风险

- 降低每个 batch 的多样性，可能减慢收敛
- 极端情况下某些底物仅有 1-2 个酶，无法构建有效批次

## 4. Heme 中心口袋/通道编码器

**发现日期**：2026-03-09
**灵感来源**：EnzymeCAGE + DrugCLIP（口袋级编码）+ P450 结构文献

### 问题

EZSpecificity 对整个对接复合物进行 SE(3)-GNN 编码（k=32 近邻，3 层），但 P450 的特异性决定区域非常局部化：Heme 周围的催化口袋（~10Å）、F/G 螺旋通道、B/C 环。全蛋白编码可能稀释了关键区域的信号。

### 改进方案

替换全结构编码为以 Heme 为中心的局部图：

1. **Heme 中心裁剪**：以 Fe 原子为中心，提取 12-15Å 范围内的所有原子构建局部图
2. **通道几何特征**：计算底物进入通道的几何描述符（通道瓶颈半径、通道长度、Heme-底物距离、底物接近角度）
3. **关键残基标注**：标注 F/G 螺旋、B/C 环、I 螺旋上的残基（P450 文献中已知的功能区域）
4. **口袋体积/形状描述符**：活性位体积（190-490 Å³ 范围），空腔形状指数

### 预期收益

- EnzymeCAGE 和 DrugCLIP 均验证口袋级编码优于全蛋白编码
- P450 文献明确指出活性位体积、通道形状是决定底物选择性的关键因素
- 减少 GNN 中的信息稀释，聚焦特异性决定区域

### 实施难度：中

需要开发口袋提取工具（可基于现有 protein_ligand.py 扩展），通道计算可用 CAVER/MOLEonline。

### 风险

- 局部裁剪可能丢失远端变构效应（P450 的 Pdx 结合位点距 Heme ~15Å）
- 通道计算工具对 AlphaFold 结构可能不够准确

## 5. 反应中心感知标签

**发现日期**：2026-03-09
**灵感来源**：EnzymeCAGE（反应中心编码）+ CYP716A 文献

### 问题

当前 EZSpecificity 的标签是"酶是否催化底物"（二分类），但 P450 的特异性更细致——它关乎"在底物的哪个位点发生什么类型的氧化反应"。二分类标签将不同化学机制的反应混为一谈。

CYP716A 文献明确显示：同一 TBGC 中的两个 P450（CYP716A1278 和 CYP716A277）催化同一底物但产生不同产物——单一氨基酸差异决定产物特异性。二分类标签无法区分这种情况。

### 改进方案

将标签从"yes/no"升级为更细粒度的信息：

1. **代谢位点标注**（Site of Metabolism, SoM）：标注底物上被氧化的原子
2. **反应类型标注**：羟基化 / 脱烷基 / 环氧化 / 其他
3. **产物信息**：编码底物→产物的化学转变（EnzymeCAGE 的做法）
4. **反应中心权重**：对底物中参与反应的原子赋予更高注意力权重

### 预期收益

- EnzymeCAGE 证明反应中心感知显著提升酶-反应匹配准确率
- 区分"结合但不催化"vs"结合且催化"——直接解决抑制剂负样本的歧义

### 实施难度：高

需要收集 P450 代谢位点标注数据（可从 SoM 数据库、KEGG、文献获取），编写反应中心提取管线。

### 风险

- 标注数据稀缺且噪声大
- P450 区域选择性预测本身就是 Path D 的目标，可能超出当前范围

## 6. 蛋白质原子词汇表扩展——加入 Fe（铁）

**发现日期**：2026-03-03
**来源**：Path B Step 2 因子实验（Heme 效应 = -0.2322）

### 问题

EZSpecificity 的蛋白质端原子词汇表只有 6 种元素：H, C, N, O, S, Se。
当口袋中包含 HEM（血红素）时，Fe 原子（原子序数 26）不在词汇表中，被编码为零向量，信息完全丢失。
实验结果：加入 HEM 后 AUC-ROC 从 0.7115 降至 0.4894（降幅 31%）。

### 改进方案

**最小改动**：在蛋白质原子词汇表中加入 Fe。

```python
# src/Datasets/Structure/transforms.py 第 23 行
# 修改前
self.atomic_numbers = torch.LongTensor([1, 6, 7, 8, 16, 34])      # 6 维

# 修改后
self.atomic_numbers = torch.LongTensor([1, 6, 7, 8, 16, 34, 26])  # 7 维，加入 Fe
```

**连锁影响**：
- 蛋白质原子特征维度 28 → 29
- GNN 输入层需适配（`src/Models/Structure/egnn.py`）
- 模型权重不兼容——需重新训练或微调
- 配体端已有 Fe（无需修改）

**扩展方案**：加入完整金属词汇表（Fe, Zn, Mg, Mn, Cu, Co, Ni, Mo）以推广到其他金属蛋白。

### 预期收益

- P450 催化依赖 Fe 配位化学，模型能"看到"Fe 后应能学到更丰富的催化特征
- 可推广到其他金属蛋白（Zn 蛋白酶、Cu 氧化酶等）

### 实施难度：低

代码改动极小（1-2 行），但需要重新训练模型。

### 风险

- 训练集中仅 389/8,124 个酶含 HEM（4.8%），Fe 相关训练数据稀少
- 微调可能影响非金属蛋白的性能（需对比消融实验）

### 相关文件

| 文件 | 行号 | 内容 |
|------|------|------|
| `src/Datasets/Structure/transforms.py` | 23 | FeaturizeProteinAtom（蛋白质词汇表） |
| `src/Datasets/Structure/transforms.py` | 42 | FeaturizeLigandAtom（配体词汇表，已含 Fe） |
| `src/Models/Structure/egnn.py` | — | GNN 输入层维度 |

## 7. 难度分层课程学习

**发现日期**：2026-03-09
**灵感来源**：Path B 假说验证（EC 层级难度分析）

### 问题

ESIBank 训练数据混合了 EC 难度 0-5 的负样本，但我们的 P450 任务约等于难度 3（同 EC 前 3 位）。模型在简单负样本上"刷分"，对困难负样本学习不足。

### 改进方案

实施课程学习（Curriculum Learning）：

1. **第一阶段**（热身）：EC 难度 0-1 的负样本（完全不同的酶家族）
2. **第二阶段**（中等）：EC 难度 2-3 的负样本（同大类但不同小类）
3. **第三阶段**（困难）：EC 难度 4-5 的负样本（同 EC 前 4 位，高度同源酶）

同时按难度分层报告指标，不再用混合 AUC 掩盖困难任务的真实表现。

### 预期收益

- 直接对齐训练目标与部署场景（难度≥3）
- ESIBank P450 在难度≥3 时 AUC 从整体的 0.638 降至 0.549——说明模型确实在困难任务上挣扎

### 实施难度：低-中

需要 EC 号标注（ESIBank 已有），修改采样策略和训练调度器。

### 风险

- 可能提升鲁棒性但不一定提升 Top-line AUC
- 标签质量在高难度层级更差

## 8. P450 专家头 / 混合专家（MoE）

**发现日期**：2026-03-09
**灵感来源**：E8v1 通道消融（P450 vs 磷酸酶通道重要性完全逆转）

### 问题

E8v1 发现 P450 依赖结构通道（-0.275），磷酸酶依赖序列通道（-0.300），两个家族的特征融合权重应该完全不同。但当前模型用一套固定的融合权重处理所有家族。

### 改进方案

1. **P450 专用适配器**：共享骨干网络 + P450 专用的融合层/预测头（独立的 MLP 权重）
2. **混合专家（MoE）架构**：
   - 路由器根据酶序列/家族特征选择专家
   - 不同专家学习不同的通道融合权重
   - 例如：P450 专家侧重结构通道，磷酸酶专家侧重序列通道

```
酶输入 → 路由器 → 专家选择
                  ├── P450专家（结构权重高）
                  ├── 磷酸酶专家（序列权重高）
                  └── 通用专家（均衡权重）
```

### 预期收益

- 论文已证明家族微调有效（HaloS → 91.7%）
- MoE 在 NLP/CV 中已被广泛验证，可有效处理多模态/多任务场景

### 实施难度：中

需要设计路由机制和专家头，修改 `ss.py` 的预测层。

### 风险

- P450 训练数据太少可能导致专家头过拟合
- 路由器本身需要足够的训练数据学习分派策略

## 9. 构象集成建模

**发现日期**：2026-03-09
**灵感来源**：P450 Dynamics (Acc Chem Res 2022) + P450 Structural Diversity (JBC 2013)

### 问题

P450 文献明确指出：

- F/G 螺旋和 B/C 环发生大规模开/关构象变化
- 脯氨酸顺反异构化（Pro89/Pro105）开启双底物通道
- 氧化还原伴侣（Pdx）结合是变构效应器
- **静态结构不能完全捕捉 P450 特异性**

当前模型使用单一对接构象，丢失了构象动态信息。

### 改进方案

1. **多构象采样**：对每个 P450 生成多个构象状态（开放/闭合、底物结合/未结合）
   - 来源：AlphaFold2 多次预测、短 MD 模拟、正则模式分析（NMA）
2. **注意力聚合**：对多个构象的 GNN 输出用注意力机制聚合
3. **RMSD 特征**：添加 F/G 螺旋和 B/C 环的构象灵活性作为额外特征

### 预期收益

- CYP2E1 活性位体积在 190-490 Å³ 之间变化——单一构象无法表示这种范围
- 构象集成可区分"专一型"（刚性口袋）和"广谱型"（柔性口袋）P450

### 实施难度：高

需要 MD 模拟或多构象生成工具，计算成本高。

### 风险

- 可能引入比信号更多的结构噪声
- 计算量大幅增加

## 10. 专一型 vs 广谱型路由

**发现日期**：2026-03-09
**灵感来源**：P450 Structural Diversity (JBC 2013)

### 问题

P450 家族内部存在根本性的架构差异：
- **专一型**（甾体合成 P450）：活性位高度约束，底物精确定位，高效高选择性
- **广谱型**（药物代谢 P450）：活性位灵活可扩展，底物范围广但效率较低

用单一评分模型处理两种截然不同的催化策略是不合理的。

### 改进方案

1. **先分类后评分**：根据活性位体积/灵活性/EC 亚类将 P450 分为专一型和广谱型
2. **专一型评分头**：重视形状互补性、Heme-底物距离、反应位点精确度
3. **广谱型评分头**：重视口袋容积、通道动态、底物穿过通道的可能性

### 预期收益

- 不同评分策略匹配不同催化机制
- 参考 JBC 2013 文献中 CYP3A4（可容纳 734 Da 分子）vs CYP1A1（窄通道）的巨大差异

### 实施难度：中

需要 P450 亚型分类数据（可从 CYP 命名数据库获取），设计路由逻辑。

### 风险

- 亚型标签可能模糊（某些 P450 兼具两种特征）
- 路由错误可能比无路由更差

## 11. 酶原子级结构特征聚合

**发现日期**：2026-03-10

### 诊断依据

模型流程图解过程中发现的架构不对称性：

- **底物侧**：同时拥有原子级结构特征（EGNN 输出）+ 分子级特征（GROVER/Morgan），两者都参与后续交叉注意力
- **酶侧**：EGNN 同样计算了酶的原子级结构特征，但这些特征在 `structure.py` 中被**直接丢弃**，仅保留底物原子的结构特征

代码证据（`src/Models/Structure/structure.py`）：
- EGNN 输出的节点特征 `h` 包含所有原子（底物 + 蛋白质），维度 `[N_substrate + N_protein, 128]`
- 通过 `ligand_mask`（底物掩码）过滤后，仅保留底物原子的特征
- 蛋白质原子的 EGNN 特征被丢弃，酶侧仅使用 ESM 序列嵌入（残基级）

### 问题描述

**粒度不匹配导致的信息丢失**：

```
底物侧（原子级）：
  ┌─ 结构通道 → EGNN → 原子级特征 [N_substrate, 128] ──→ ✅ 参与交叉注意力
  └─ 分子通道 → GROVER/Morgan → 原子级特征 [N_substrate, 128] → ✅ 参与交叉注意力

酶侧：
  ┌─ 结构通道 → EGNN → 原子级特征 [N_protein, 128] ──→ ❌ 被丢弃！
  └─ 序列通道 → ESM → 残基级特征 [N_residue, 128] ────→ ✅ 参与交叉注意力
```

丢弃原因：序列通道是残基级（1 个氨基酸 = 1 个向量），结构通道是原子级（1 个原子 = 1 个向量，每个氨基酸 5-20 个原子）。两者粒度不同，无法直接拼接。当前代码选择丢弃原子级特征。

**后果**：酶侧缺少 3D 结构信息（原子间距离、空间排布等），仅依赖 ESM 序列嵌入。对于 P450 这类高度依赖活性位口袋 3D 构型的酶家族，这可能是关键信息损失。

### 改进方案

**残基级聚合**：将酶的原子级结构特征按氨基酸归属分组，组内取平均，得到残基级结构特征，再与 ESM 嵌入拼接或相加。

```
酶原子级特征 [N_protein_atoms, 128]
    │
    ▼ 按 protein_atom_to_aa_type 分组
    │  (transforms.py 中已有此映射)
    ▼ 组内 scatter_mean
    │
残基级结构特征 [N_residue, 128]
    │
    ▼ 与 ESM 嵌入 [N_residue, 128] 拼接/相加
    │
酶融合特征 [N_residue, 128 或 256]
    │
    ▼ 参与交叉注意力
```

关键：`protein_atom_to_aa_type` 映射在 `transforms.py` 的 `FeaturizeProteinAtom` 中已经存在，无需额外数据。

### 预期收益

- 酶侧获得 3D 结构信息，与底物侧形成对称的双通道覆盖
- 对 P450 尤其重要：活性位口袋的精确 3D 构型（Fe-底物距离、I 螺旋位置等）直接决定催化特异性
- 与创新点 4（Heme 口袋编码器）和 6（Fe 词汇表）形成互补——6 解决 Fe 识别问题，4 聚焦口袋区域，11 解决信息传递问题

### 实施难度：低-中

- `protein_atom_to_aa_type` 映射已存在，`scatter_mean` 是 PyG 标准操作
- 主要工作：在 `structure.py` 中增加聚合逻辑 + 在 `ss.py` 中调整酶特征拼接维度
- 不影响底物侧和现有训练流程

### 风险

- 聚合可能丢失原子级细节（平均操作的信息损失）
- 拼接后维度翻倍（256）可能需要额外投影层
- 需验证 EGNN 计算的蛋白质原子特征质量是否足够（当前从未被优化目标驱动过梯度）

## 附：Codex 建议的首选实验顺序

Codex 审核后建议按以下顺序推进前三个实验：

> 1. **硬负样本替换**：保持现有模型不变，仅替换负样本为 P450 硬负样本，重跑实验
> 2. **对比学习 + 反平衡批次**：在相同数据上添加对比排序训练 + 反平衡采样
> 3. **Heme 中心口袋编码器**：替换全结构编码为局部口袋编码，再尝试完整构象集成
>
> **理由**：这三步直接针对已诊断的失败模式（底物捷径、弱负样本、结构信号稀释），且成本远低于完整构象集成建模。如果这三步仍无法将 P450 AUC 推至 0.55-0.60 以上，则有力证据表明需要更丰富的标签（如反应中心/产物特异性监督）。
