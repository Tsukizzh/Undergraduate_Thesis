## 一、Unknown Enzyme + Substrate 场景从头训练复现

### 1.1 背景与目标

论文设计了 4 种评估场景，其中 **Unknown Enzyme + Substrate** 是最难的场景（训练集和测试集的酶和底物完全不重叠），论文报告 AUC=0.720。但论文只提供了最简单场景的预训练模型，这个最难场景需要我们自己从头训练。

从头训练的目的：
1. 验证我们的训练管线是否正确
2. 建立可复现的基线，为后续 P450 优化提供对照

### 1.2 训练环境

| 项目 | 配置 |
|------|------|
| 服务器 | 云服务器：2×RTX 4090（48GB 显存），180GB 内存，14 vCPU |
| 框架 | PyTorch 2.1.0 + PyTorch Lightning 1.9.0，DDP 策略 |
| 数据 | ESIBank 7 个酶家族，176K 样本（Unknown Enzyme + Substrate 场景，fold 0） |
| 批次 | bs=56/GPU × 2 GPU = 有效 112，FP16 混合精度 |
| 速度 | ~7.56 it/s（本地单卡），~10 min/epoch（云服务器 DDP） |


### 1.3 数据缓存优化

论文使用 LMDB 格式存储特征（~60GB），需要 256GB+ 内存才能高效运行。我们内存不足导致训练速度不断衰减（3.8→2.09 it/s）。解决方案：设计了 per-sample .pt 缓存方案替代 LMDB，速度提升至 **7.56 it/s（稳定不衰减）**，提速 3.6 倍。

### 1.4 训练结果

#### 复现结果（云服务器 DDP，32 epochs）

> **说明：** "legacy_bug"指原始代码中边索引构建的一个 bug（分子内键边被重复计入 k-NN 边），论文作者的所有结果均在此 bug 下训练得出。

| 指标 | 我们的结果 | 论文报告 | 对比 |
|------|----------|---------|------|
| **Test AUC-ROC** | **0.7244**（ep27） | 0.7198 | **+0.005 超越论文** |
| Val AUC 最佳 | 0.722（ep22） | — | — |
| 训练配置 | 2×4090 DDP，32ep | 4×GPU，~256ep | 我们用更少 epoch |

**核心结论：** 我们的训练管线正确，在 AllSplit 场景下成功复现并略超论文结果。

#### 云服务器 DDP 训练曲线

| Epoch | Train Loss | Val Loss | Val AUC | Val AUPR |
|-------|-----------|----------|---------|----------|
| 0 | 0.362 | 0.319 | 0.598 | 0.141 |
| 4 | 0.298 | 0.333 | 0.637 | 0.165 |
| 8 | 0.263 | 0.328 | 0.670 | 0.170 |
| 13 | 0.230 | 0.354 | **0.722** | 0.200 |
| 22 | 0.202 | 0.393 | **0.722** | 0.203 |
| 27 | 0.191 | 0.417 | 0.720 | 0.217 |
| 31 | 0.180 | 0.427 | 0.708 | 0.206 |

**关键观察：Val Loss ↑ 但 AUC 也 ↑，看似过拟合实则不是**

| 现象 | 解释 |
|------|------|
| Train Loss ↓，Val Loss ↑ | 看似过拟合 |
| 但 Val AUC 同时 ↑ | **不是过拟合，是两个指标衡量的东西不同** |
| Test AUC=0.7244 ≈ Val AUC=0.722 | 模型泛化正常，确认非过拟合 |

**核心原因：BCE Loss 和 AUC 衡量的东西不同**

简单示例——假设有 5 个样本（2 正 3 负），模型给出预测分数：

| 样本 | 真实标签 | 模型输出 logit | 经 sigmoid 转概率 | BCE Loss 贡献 |
|------|---------|-------------|----------------|-------------|
| A | 正(1) | 2.2 | 0.90 | 0.105 |
| B | 正(1) | 1.4 | 0.80 | 0.223 |
| C | 负(0) | -0.8 | 0.31 | 0.357 |
| D | 负(0) | -1.4 | 0.20 | 0.223 |
| E | 负(0) | **5.0**（极端自信错误） | **0.993** | **4.96** ← 一个样本贡献 84% 总 loss |

- **BCE Loss** = (0.105+0.223+0.357+0.223+4.96)/5 = **1.17**（被 E 一个样本拉高）
- **AUC**：按 logit 排序，正样本 A(2.2)、B(1.4) 都排在负样本 C(-0.8)、D(-1.4) 前面，6 个正负对中 5 对排序正确 → **AUC=5/6=0.833**（E 虽然 logit 最高但只影响 1 对）

→ 一个极端样本可以让 loss 翻倍，但几乎不影响 AUC。这就是为什么 Val Loss ↑ 和 Val AUC ↑ 可以同时发生。

ep8→ep22 期间：模型的**排序能力持续改善**（AUC ↑），但对少数样本**过度自信**导致 loss 被拉高（Val Loss ↑）。两者并不矛盾。

## 二、模型消融实验

### 2.1 实验目标

在确认训练管线正确后，测试两个架构改动对 Unknown Enzyme + Substrate 场景性能的影响：
1. **边索引修复（edge-mode fixed）**：修复分子键边被重复计入 k-NN 的 bug
2. **Dropout 率调整**：论文原始 dropout=0.9（交叉注意力层），测试降低 dropout 是否改善泛化

### 2.2 实验 1：边索引修复

| | 含 Bug 基线 | 修复后 | 差异 |
|---|-----------|--------|------|
| **Val AUC** | 0.722 | 0.715 | -0.008 |
| **Test AUC** | **0.724** | **0.706** | **-0.018** |


**结论：** 边修复未带来提升，反而略有下降。原因是论文原始模型在含 Bug 条件下训练了 ~256 epochs，已适应了错误的边结构。我们从头训练 32 epoch 不足以让修复后的模型收敛到同等水平。

### 2.3 实验 2：Dropout 消融

在修复后的基线上，测试不同 dropout 值：

| Dropout | Val AUC | Test AUC |
|---------|---------|----------|
| **0.9（基线）** | 0.715 | **0.706** |
| 0.3 | 0.740 (+0.025) | 0.696 (-0.010) |
| 0.1 | 0.722 (+0.007) | 0.694 (-0.012) |

**结论：** 降低 dropout 后 Val AUC 上升，但 Test AUC 反而下降——说明模型只是更好地拟合了验证集，并没有学到真正可迁移的模式。Dropout=0.9 虽然极端，但在当前数据规模下反而是最优的。

### 2.4 三个实验的总结

| 实验 | Val AUC | Test AUC | 结论 |
|------|---------|----------|------|
| 原始复现（含论文边 bug） | 0.722 | **0.724** | 超论文 +0.005，管线正确 |
| 修复边 bug | 0.715 | 0.706 | 未改善 |
| Dropout 0.9→0.3 | 0.740 | 0.696 | 未改善 |
| Dropout 0.9→0.1 | 0.722 | 0.694 | 未改善 |

**整体结论：** 在论文原始数据上，模型架构的小调整无法显著改善 Unknown Enzyme + Substrate 场景的泛化能力。模型的主要瓶颈在于**数据规模和质量**，需要构建更大、更全面的 P450 专属数据集。

## 三、P450 全面数据集构建

### 3.1 背景与动机

前期工作中，我们从 RCSB PDB 中筛选出 682 条 P450 酶-配体对（153 个唯一 P450），并利用 ESIBank 训练集中的 389 个 P450 进行了排除（确保测试集与训练集无重叠）。在此基础上进行的系统性诊断发现：
- 模型在 P450 上泛化失败的部分原因是**数据不足 + 架构设计问题**
- 现有的 P450 数据量太少（ESIBank 中仅 389 个 P450 酶），不足以支撑有效训练

**因此，我们决定从头构建一个全面的 P450 数据集，涵盖尽可能多的数据源。**

### 3.5 结构获取与对接

#### 酶结构获取（1,403 + 88 = 1,491 / 1,622）

1,622 个酶中，1,403 个通过已有数据库获取了含血红素的 3D 结构：

| 来源 | 数量 | 占比 | 说明 |
|------|------|------|------|
| S1 实验 PDB | 103 | 6.4% | RCSB 晶体结构 |
| PCPD 预测 PDB | 246 | 15.2% | Maestro 生成 |
| AlphaFill | 493 | 30.4% | 含血红素的 AF2 结构，RMSD < 5Å |
| AlphaFold DB + 血红素移植 | 561 | 34.6% | 下载 AF2 裸结构，序列比对驱动移植血红素 |
| **已获取** | **1,403** | **86.5%** | |
| 待预测 | 219 | 13.5% | 无 UniProt / AlphaFold DB 未收录 |

**剩余 219 个酶的结构预测方案选择：**

老师之前给了两条路：（1）用 AlphaFold 3 预测；（2）用实验室服务器上的 AF2 + 甾体 CYP81 刚性模板。经过调研，我们选择了第三条路——**AF2 + 自动模板搜索**，理由如下：

**为什么不用 AF3：**
- AlphaFold Server（AF3 官方）每天限制 30 个提交，且只能网页手动操作，无法批量。219 个酶至少需要 8 天
- AF3 本地部署（2025 年 2 月开源）对硬件要求高，实验室服务器未安装
- Boltz-1（AF3 的开源替代）实验室服务器也未安装
- 最关键的：已获取的 1,403 个结构全部基于 **AlphaFold 2** 预测（AlphaFold DB 至今仍使用 AF2，从未换用 AF3）。为保持数据一致性，剩余 219 个也应使用 AF2

**为什么不用老师的 CYP81 固定模板：**
- 我们的 219 个酶横跨多个不同的 P450 亚家族（CYP1A2、CYP2D6、CYP71D 等），与 CYP81 的序列一致性可能只有 20-30%
- 用一个固定模板预测差异很大的目标蛋白，模板信息可能反而误导预测

**最终方案：AF2 + 自动 PDB 模板搜索**

使用实验室服务器上已安装的 LocalColabFold，加 `--templates` 参数运行。ColabFold 会自动用 **HHsearch**（隐马尔可夫模型序列搜索工具）对每个目标序列在 **PDB70**（RCSB PDB 的 70% 序列一致性聚类代表集，涵盖所有已知实验结构）中搜索同源结构，**自动匹配 20 个最相似的已知结构作为模板**输入 AF2 的 template track，无需手动指定。

测速结果（3 个蛋白试跑）：

| 蛋白 | 残基数 | 耗时 | pLDDT | 自动找到的模板示例 |
|------|--------|------|-------|-----------------|
| ENZ_G000044 | 495 | 68s | 80.3 | 6c93_A, 6ma6_A 等 20 个 |
| ENZ_G000059 | 640 | 75s | 78.5 | 5te8_A, 6ma6_A 等 20 个 |
| ENZ_G000014 | 653 | 81s | 87.7 | 5nik_J, 5ws4_B 等 20 个 |

全量 219 个在实验室服务器上约 8-9 小时完成，最终 88 个成功获得可用结构（其余因血红素移植失败等原因未能使用）。

#### 分子对接

- 工具：**Uni-Dock v1.1.3**（GPU 加速的 Vina 实现，比传统 AutoDock-GPU 快约 1000 倍）
- 参数：`--search_mode fast`（exhaustiveness=128），在云服务器 GPU 上运行
- 结果：**50,180/52,254 对完成对接**（96.1%）
- 未对接的 2,074 对原因：少数酶结构获取彻底失败（8 个无 AlphaFold 记录）+ 7 个底物无法生成 3D 构象（含通配符的模板底物）+ 对应的配对被标记为 blocked
- 对接质量：中位结合能 **-6.1 kcal/mol**，75% 的对接结果结合能优于 -5.0 kcal/mol，整体质量良好
