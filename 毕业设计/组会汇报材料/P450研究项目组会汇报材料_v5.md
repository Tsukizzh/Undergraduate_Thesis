## 一、特征文件对齐 bug 的发现与修复

### 1.1 发现过程

在 v4 汇报之后，我们原本计划做残基级几何特征（二面角 φ/ψ/χ1）的增强实验（EXP003）。在写 EXP003 代码的时候，为了确保特征加载没有问题，我们做了一次逐层的数据核对，结果发现了一个非常严重的 bug。

### 1.2 第一个 bug：ESM 嵌入错位（2026-04-13 发现）

**位置**：数据预处理脚本 `phase7_step2_esm.py` 第 45 行附近

**具体问题**：

```python
# 问题代码
uniprot_dict[str(idx)] = (len(uniprot_dict), 1)
#                        ↑ 这是"第 N 个通过过滤的酶"的顺序计数
#                          本应该用 Enzymes.csv 的真实行号
```

蛋白质序列的 ESM 嵌入保存在 LMDB 数据库里，每个嵌入需要一个唯一的 key 来索引。正确的做法是用 Enzymes.csv 中这个酶的**行号**作为 key，这样训练时就能根据样本里的"酶索引"准确取到对应嵌入。

但这段代码用的是"**当前这个酶是通过质量过滤的第几个**"作为 key。由于 1,622 个酶中有 48 个被过滤掉（序列太长或含非标准氨基酸），剩下 1,577 个酶被重新顺序编号为 0, 1, 2, ..., 1576。这个新编号和 CSV 里的行号**完全对不上**。

**结果**：训练时，当样本说"酶 ID = 500"，模型去 LMDB 取 key=500 的嵌入，拿到的却是"通过过滤的第 500 个酶"的嵌入——这可能是 CSV 里的第 530 个酶、第 480 个酶，随便哪个都有可能。

**影响范围**：

| 实验 | 训练时使用的酶特征 |
|---|---|
| EXP001（Test=0.7730） | ~95.8% 错配 |
| EXP002a（Test=0.7816） | ~95.8% 错配 |
| EXP002b（Test=0.7889） | ~95.8% 错配 |
| EXP003（Test=0.7914） | ~95.8% 错配 |

v4 汇报里的所有数字，实际上都建立在**绝大部分样本拿到错误酶特征**的基础上。

### 1.3 修复方法

采用"非破坏性修复"——不删除原有数据，新建一个正确的副本：

```
原有错误文件：enzymes.lmdb            ← 保留作为对比
新建正确文件：enzymes_fixed.lmdb       ← 新增

三阶段脚本：
  阶段 A: fix_enzyme_lmdb.py      从原始 ESM 特征重建，用 CSV 行号作 key
  阶段 B: fix_flatbin_build.py    把 LMDB 重新打包为训练用的二进制文件
  阶段 C: fix_geom_cache.py       生成修复后的样本缓存目录
```

### 1.4 修复后的首个结果：EXP003_fixed

用完全相同的训练配方，只把"特征缓存路径"换成修复后的版本：

| 指标 | 修复前（EXP003）| 修复后（EXP003_fixed）| 变化 |
|---|---|---|---|
| Test AUC-ROC | 0.7914 | **0.8943** | **+0.1029** |
| Test AUPR | 0.3814 | 0.5358 | +0.1544 |

**一次修复，AUC 跳升 0.10**，相当于之前所有超参调优加起来的总效果。

### 1.5 第二个 bug：GROVER 指纹错位（2026-04-14 深夜发现）

修复完 ESM 之后，v4 里承诺的"残基级几何特征实验"应该可以重做了。但在重做 EXP002a（Fe/HEM 实验）时，我们在训练进行到第 4 个 epoch 时对 GROVER 指纹做了一次实证检查，又发现一个类似的 bug。

**位置**：GROVER 特征生成的批处理脚本 `phase7_step5_grover.sh`

**具体问题**：

GROVER 是一个分子指纹生成工具。我们调用它处理 2,125 个底物。但其中一个底物 `*[H]`（带氢原子的通配符 SMILES）让 GROVER 崩溃。脚本的处理方式是：**直接从底物列表里删掉这一行，然后继续处理**。

问题在于：GROVER 内部用"处理到第几个分子"作为输出 key（和前面 ESM 的 bug 一模一样）。删掉第 8 个底物后，从第 9 个底物开始，它们的 key 和 CSV 行号错位了 1。

**影响**：99.6% 的底物在训练时拿到的是 CSV 里下一行那个分子的 GROVER 指纹。

**实证验证**：我们通过原子数量匹配验证了这个错位：如果 CSV 行 N 的分子有 15 个原子，但训练时加载的"行 N 的指纹"对应的是一个有 18 个原子的分子，说明错位确实存在。验证了 2,124 个底物，从索引 8 开始全部错位。

### 1.6 GROVER bug 的修复

幸运的是，修复 GROVER 不需要重跑模型（GROVER 模型推理一次要好几个小时）。只需要**重写 LMDB 的 key**：

```
原 GROVER LMDB：key=0, 1, 2, ..., 7, 8, 9, ..., 2123
                                      ↑ 从这里开始错位

修复脚本 fix_grover_lmdb.py：
  读每个旧 key，重新写入对应的正确 key
  key 0~7 不变
  key 8 对应 CSV 行 9（插入空位）
  key 9 对应 CSV 行 10
  ...
  这是纯字节操作，几秒钟完成。
```

### 1.7 双 bug 修复后的统一数据集构建

ESM 修复（EXP003_fixed）时有 48 个"孤儿酶"被过滤掉，导致样本数从 47,510 减少到 44,090。GROVER 修复后，底物对齐也变了。为了让后续实验在**完全一致的样本集**上做严格的单变量消融，我们重建了三套独立的样本缓存：

```
三种特征配置 × 两种过滤策略 = 6 套 pt_cache

三种特征配置：
  bare   —— feature_dim = 28，原始配置
  heme   —— feature_dim = 31，加入 Fe/HEM/is_hetero
  geom   —— feature_dim = 37，加入 φ/ψ/χ1 二面角

两种过滤策略：
  natural —— 每种特征独立保留各自通过的样本
  unified —— 取三种特征通过样本的交集，确保严格单变量消融

最终的 unified 样本集：
  训练：22,083
  验证：11,008
  测试：11,000
```

接下来的所有 allfix 实验都用 **unified 样本集**，保证三次消融实验**唯一变量就是 feature_dim**（其他所有因素包括样本集、分割、超参全部固定）。

### 1.8 这一节的核心收获

v4 汇报的数字建立在错位特征之上，意味着：

```
v4 报告：EXP001 Test AUC = 0.7730
实际：  该模型 95% 的训练样本拿到了错误的酶特征
        且 99.6% 的底物拿到了错位的分子指纹

数据修复后真实基线：
  EXP001_allfix_unified Test AUC = 0.9320
  比 v4 报告的数字高 0.16
```

**这是 v4 之后最重要的单一发现**。数据问题被掩盖了半年，修复后真实基线性能远超预期。后续所有实验都在这个基础上做。

## 二、allfix 真实基线三次消融实验

### 2.1 实验设计

在干净（双 bug 修复）的 unified 样本集上，做严格的 feature_dim 单变量消融。三个实验的**唯一区别是结构通道特征维度**，其他全部相同（训练集、超参、优化器、早停策略）。

| 实验编号 | feature_dim | 新增特征 | 对比目的 |
|---|---|---|---|
| EXP001_allfix_unified | 28 | 无（bare baseline）| 真实基线 |
| EXP002a_allfix_unified | 31 | + Fe 原子 + HEM 残基类型 + is_hetero 标志位 | 检验 Fe/血红素编码是否有用 |
| EXP003_allfix_unified | 37 | + φ/ψ/χ1 残基二面角（sin/cos 编码）| 检验残基级几何是否有用 |

### 2.2 训练配置

| 项目 | 配置 |
|---|---|
| 服务器 | 4×RTX 4090（96GB 显存），360GB 内存 |
| Batch size | 88/GPU × 4 GPU = 有效 352 |
| 学习率 | 4e-4，warmup 12 epochs |
| 权重衰减 | 1e-5 |
| Dropout | 0.9（与论文和 v4 一致） |
| 优化器 | AdamW |
| 精度 | FP16 混合精度 |
| 早停 | patience=15，监控 val AUPR |

### 2.3 三次实验的结果

| 实验 | 最佳 epoch | Val AUC | Test AUC | Test AUPR |
|---|---|---|---|---|
| **EXP001_allfix_unified（bare 28）** | ep43 | 0.9250 | **0.9320** | **0.6749** |
| EXP002a_allfix_unified（+Fe/HEM → 31）| ep59 | 0.9173 | 0.9270 | 0.6300 |
| EXP003_allfix_unified（+二面角 → 37）| ep62 | 0.9183 | 0.9300 | 0.6426 |

### 2.4 关键反转：三次"增补"全部失败

| 对比 | v4 汇报的老结论 | 本次新结论 | 反转程度 |
|---|---|---|---|
| Fe/HEM 编码 vs bare | EXP002a=0.7816 > EXP001=0.7730（+0.009 提升）| EXP002a=0.9270 < EXP001=0.9320（**-0.005 退步**）| 从有效到失败 |
| 二面角 vs Fe/HEM | EXP003=0.7914 > EXP002a=0.7816（+0.010 提升）| EXP003=0.9300 > EXP002a=0.9270（+0.003 微弱）| 幅度大幅缩水 |
| 二面角 vs bare | 两步累计提升 +0.019 | 整体 -0.002（**比 bare 还低**）| 从有效到失败 |

### 2.5 为什么会全部反转

v4 报告的这些"提升"在新数据上全部消失，原因是：

```
原因一：v4 的 0.7730 偏低，有很大的提升空间
  → 加任何特征都容易撞上"正确的方向"
  → 尤其是 Fe/HEM 特征，偶然补偿了 GROVER 错位造成的损失

原因二：修复后的真实基线 0.9320 已经接近当前架构上限
  → 剩余的错误主要来自架构表达力的本质限制
  → 简单增加特征维度只会引入更多可训练参数而没有相应信号来填充它们
```

这个反转说明了一件事：**之前认为"给 EGNN 加几何信息"这条路是有效的，但在干净数据上根本不成立**。结构通道的容量已经被现有特征占满，继续塞特征不会带来增益。

### 2.6 关于 v4 汇报中"模型架构优化"的四个方向

v4 里提到的四个架构优化方向（Fe 编码、边 bug、酶侧结构对称性、Dropout），现在需要重新评估：

| 方向 | v4 时的状态 | 本次汇报的新发现 |
|---|---|---|
| 一：Fe 编码（Heme 噪声） | 待做 | **已做（EXP002a），在干净数据上无效** |
| 二：边 bug 修复 | 已验证未改善 | 结论不变 |
| 三：酶侧结构对称性 | 待做 | 已做（EXP005 双图架构，见第四部分），也无效 |
| 四：Dropout 调整 | 已验证未改善 | 结论不变 |

**v4 提出的四个优化方向，目前全部经过测试，全部无效**。这是一个重要的负面结论，说明我们需要重新思考优化方向。

## 三、与论文基线的公平外部对比（EXP004）

### 3.1 对比的必要性

v4 里我们说"我们 0.7730 vs 论文 0.638"，但这是不同测试集上的数字，不构成公平对比。为了真正衡量我们的进步，需要**同一个测试集、同一套评估协议**下的对比。

### 3.2 实验设计

```
对比目标：论文训练好的模型 vs 我们训练好的模型
对比测试集：我们构建的 P450 测试集（11,000 样本）

核心难点：
  我们测试集里的一些酶可能是论文训练过的
  → 论文模型在这些酶上可能"背答案"，占便宜
  → 需要过滤掉这些酶再对比，才是公平比较
```

**过滤操作**：

```
识别论文训练集里的 P450 酶：389 个（ESIBank P450 子集）
这些酶中 356 个在我们测试集里也出现了（UniProt ID 匹配）
把这 356 个酶对应的测试样本全部剔除

过滤前测试集：10,999 样本
过滤后测试集：7,963 样本（剔除 3,036 个，占 27.6%）
```

为了确保过滤机制没有错误，我们做了"**sanity check**"：把论文模型分别在过滤前、过滤后两个测试集上都跑一遍。如果过滤机制正确，论文模型在**未过滤**集上的性能应该略高（因为包含了论文背过答案的酶），在**过滤后**集上略低。

### 3.3 四路对比 + sanity check 结果

所有对比都在同一张 RTX 5090 上进行，单次约 50 秒。

| 模型 | 测试集 | 边模式 | Test AUC | Test AUPR |
|---|---|---|---|---|
| **论文模型 ckpt** | 过滤后 (7963) | legacy_bug（论文原训练条件）| **0.5586** | 0.1004 |
| 论文模型 ckpt | 过滤后 (7963) | fixed（边修复）| 0.5596 | 0.1007 |
| **论文模型 ckpt** | **未过滤** (10999) | legacy_bug | **0.5860** | 0.1124 |
| 我们 EXP001 ep43 | 过滤后 (7963) | legacy_bug | 0.9154 | 0.6194 |
| **我们 EXP001 ep43** | **过滤后** (7963) | fixed（我们的原训练条件）| **0.9205** | 0.6403 |
| **我们 EXP001 ep43** | **未过滤** (10999) | fixed | **0.9320** | 0.6749 |

### 3.4 结果解读

**论文模型的真实水平**：在 P450 上 AUC 约 0.56，**接近随机猜测（0.5）**。即使在论文自己训练过的酶上（未过滤集包含 27.6% 的训练酶），也只有 0.586，比纯随机强一点，远达不到论文自己报告的 0.72。

**我们模型的真实水平**：0.9320（未过滤）和 0.9205（过滤后）差 0.0115，泛化能力是真实的，不是靠背诵数据。

**总体差距**：**+0.36 AUC**（0.559 → 0.921）。同一测试集、同一过滤标准下，这个差距基本上可以完全归因到两件事：

```
① 数据集规模和质量（5 个 P450 库整合 × 双 bug 修复）
② 从头训练（不依赖论文的通用催化模型权重）

架构本身没动过。这个结果和 v4 的 "+0.135"（0.638→0.773）相比，
差距从相对变化 +21% 扩大到 +65%。本质就是 bug 修复的功劳。
```

### 3.5 sanity check 通过确认

| 测试 | 结果 | 说明 |
|---|---|---|
| 论文 ckpt 过滤前后差距 | 0.586 - 0.559 = **+0.027** | 过滤机制正确，在训练过的酶上确实略占便宜 |
| 我们 ckpt 过滤前后差距 | 0.932 - 0.921 = **+0.012** | 差距很小，说明我们对非 ESIBank 酶的泛化是真实的 |
| 边模式对 inference 的影响 | 两个模型都在 0.001-0.005 范围内 | 边修复主要影响训练收敛，不影响推理数值 |

**对比有效性确认**：这个 +0.36 的差距可以作为毕业设计的核心对外结果。

## 四、双图架构尝试（EXP005）

### 4.1 实验动机

allfix 三次消融（第二部分）证明了"给 EGNN 加标量几何特征无效"。但还有一种思路：**不加特征，加整条新通路**。具体就是 EnzymeCAGE 论文（Nature Catalysis 2026）里用的**残基级 GVP 编码**。

残基级 GVP 和原子级 EGNN 的区别：
- 原子级 EGNN：节点是原子，只处理标量距离（SE(3) 不变）
- 残基级 GVP：节点是残基，同时处理标量和 3D 方向向量（SE(3) 等变）

理论上 GVP 能表达"残基侧链朝哪个方向、和邻居的相对朝向"这类原子级 EGNN 学不到的信息。

### 4.2 架构设计

在基线模型上**新增**一条残基级 GVP 通路（不改基线），采用双出口融合：

```
新增残基级 GVP 编码器（从 EnzymeCAGE 移植 335 行代码）
      ↓
输出每个口袋残基的 128 维向量 h_res
      ↓
      ├──→ 出口 1：深融合
      │    h_res 按 pocket_residue_idx 注入回酶序列表示 x_pro
      │    的对应 UniProt 位置，再进入双向交叉注意力
      │
      └──→ 出口 2：浅旁路
           scatter_mean(h_res) → g_res
           作为第 8 个向量拼接到预测头输入（维度 896 → 1024）
```

**关键设计：零初始化保证基线等价性**

两个新路径的最后一层权重都初始化为 0，训练第 0 步时 EXP005 模型的输出**严格等于**基线 EXP001 模型的输出（实测误差 4e-8）。然后通过"延迟解冻"机制，让 GVP 分支在训练过程中逐步激活。

### 4.3 前期基础设施建设

为了让每个口袋残基能正确映射到 UniProt 序列位置，我们做了大量对齐工作：

```
第 1 阶段：残基位置映射表
  对全部 1,479 个酶做 BioPython 全局序列比对
  对 experimental_pdb 子集额外用 SIFTS REST API 交叉验证（96 个样本）
  结果：1,471 gold + 6 trusted + 2 partial + 0 suspect
        = 全部 1,479 个酶 100% 成功映射到 UniProt 位置

第 2 阶段：GVP 特征抽取
  对 44,090 个训练样本抽 (node_s, node_v, edge_index, edge_s, edge_v) 等字段
  结果：44,026 成功 / 64 失败（空口袋或残基数过少）
  失败样本通过 manifest 做运行时占位合成，不污染 cache

全量 sanity check：
  2,991,586 个口袋残基 100% 覆盖、99.97% 残基类型匹配
  每步都经过多轮代码审查和字节级验证
```

### 4.4 训练结果

| 指标 | EXP001（基线）| EXP005 双图架构 | 变化 |
|---|---|---|---|
| Best Val AUC | 0.9250 (ep43) | 0.9262 (ep41) | +0.001 |
| **Test AUC-ROC** | **0.9320** | **0.9253** | **-0.0067** |
| Test AUPR | 0.6749 | 0.6174 | -0.0575 |
| 训练时长 | ~50 分钟 | 56.8 分钟 | +14% |
| 模型参数量 | 1,846,660 | 2,684,654 | +45% |
| 早停 epoch | - | 57 | - |

**结果**：双图架构未能超越基线，反而轻微退步。

### 4.5 "结构通道饱和"的三组证据

把 EXP002a、EXP003、EXP005 放在一起看，发现一个非常一致的规律：

| 实验 | 新增的结构信息 | feature_dim 或新通路 | Test AUC 变化 |
|---|---|---|---|
| EXP002a | Fe/HEM 原子 + 类型标志 | 28 → 31 | -0.005 |
| EXP003 | φ/ψ/χ1 残基二面角 | 31 → 37 | -0.002（vs bare -0.002）|
| EXP005 | 残基级 GVP 方向向量 + 双出口融合 | 新增完整通路 | -0.007 |

三次在不同层次注入的"结构信号增补"——从最简单的原子类型，到残基级标量角度，到残基级 3D 方向向量——**全部无效或轻微退步**。

这构成了一个扎实的结论：

```
在当前数据规模（1,479 个酶、44K 样本）和当前架构（原子级 EGNN + 双向交叉注意力）下，
结构通道已经接近它的表达极限。继续在结构通道做特征工程，不会带来增益。
```

这个结论有两个用途：

1. **对外发表**：即使是负面结果，也是扎实的实验论证
2. **指导后续**：如果要进一步提升，应该转向数据侧（更多酶家族、更难负样本）或模型容量侧（更深的 cross-attention、替换 ESM），而不是继续在结构通道做文章

### 6.1 原模型架构（EZSpecificity，EXP001 所用基线）

#### 6.1.1 它要解决什么问题


这是一个**二分类问题**。

#### 6.1.3a EGNN 内部展开（阶段一 ② 结构通道的核心）

EGNN 是**消息传递图神经网络**，每一层让每个原子的特征融合邻居的信息。本模型用 3 层，扩散半径 = 3 跳邻居。下图展示**一层内部**发生了什么：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  EGNN 一层的内部流程（对每个原子 i）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  输入：原子 i 的当前特征 h_i [128]
       它的每个邻居 j 的特征 h_j [128]
       它们之间的边特征 edge_ij [39]

                                    │
         ┌──────────────────────────┼──────────────────────────┐
         │            对每个邻居 j 分别执行以下步骤              │
         │                                                     │
         │  步骤 1：拼接 [h_i, h_j, edge_ij] → [295]            │
         │                                                     │
         │  步骤 2：边 MLP                                       │
         │    ┌──────────────────────────────────┐            │
         │    │ Linear 295 → 128 → ReLU          │            │
         │    │ Linear 128 → 128 → ReLU          │            │
         │    └──────────────────────────────────┘            │
         │                → message_ij [128]                   │
         │                                                     │
         │  步骤 3：★ 注意力门控                                 │
         │    gate = sigmoid(Linear(message_ij, 128 → 1))      │
         │    weighted_message_ij = gate × message_ij          │
         │                                                     │
         └─────────────────────┬───────────────────────────────┘
                               │
                               ▼
                     步骤 4：scatter_sum
                     所有邻居消息相加 → sum_msg_i [128]
                               │
                               ▼
                     步骤 5：节点 MLP
                     输入：拼接 [h_i, sum_msg_i] → [256]
                     ┌──────────────────────────────────┐
                     │ Linear 256 → 128 → ReLU          │
                     │ Linear 128 → 128 → ReLU          │
                     └──────────────────────────────────┘
                                → update_i [128]
                               │
                               ▼
                     步骤 6：★ 残差连接
                     h_i (新) = h_i (旧) + update_i [128]
```

重复 3 次（3 层），每次都让每个原子多吸收一圈邻居的信息。

**论文 Fig. 1 省略了哪些层？**

| 原子嵌入 one-hot → 128 | 原子类型编码 | GNN 需要初始节点特征。**EXP002a 就是在这里加 Fe** |
| 边特征构建（键类型 + 距离 RBF + 跨分子）| 编码原子间关系 | GNN 需要边信息 |
| 注意力门控（sigmoid）| EGNN 中给每条边消息加权 | 让重要的边贡献更大 |
| 残差连接 | GNN 每层输出 = 输入 + 更新 | 防止深层网络信息丢失 |
| Dropout 90% | 交叉注意力中随机丢弃 | 防止过拟合（极激进比例） |
| 掩码均值池化 | 忽略填充位置取平均 | 不同样本长度不同，填充位不应参与计算 |
| 预测头 MLP 3 层 | 896 维压缩到 1 维 | 论文只画了一个圆，实际是 3 层网络 |

#### 6.1.4 每条通道在做什么

**序列通道**：把酶的 ESM 嵌入（每个氨基酸 1280 维）用一个线性层压缩到 128 维。不做复杂处理，只是降维。ESM 已经把"蛋白质序列的含义"编码进了向量里。

**结构通道（核心）**：

```
  输入：对接复合物的原子集合
       - 酶口袋的原子（距离底物 10Å 以内的蛋白质原子）
       - 底物的原子
       - 注意：血红素和铁原子被数据预处理过滤掉了，不在图里

  建图：
       节点 = 原子
       边 = 化学键（单键/双键/...）+ 空间近邻（每个原子连接最近的 48 个邻居）

  EGNN 消息传递（3 层）：
       每一层让每个原子的特征融合它邻居的信息
       3 层之后，每个原子"知道"它周围 3 步以内所有原子的情况

  输出：
       ① 底物原子级结构特征 [280, 128]  → 进入底物通道
       ② 全局结构向量 str_mean [128]    → 直接送到末端拼接
```

**分子通道**：

- GROVER 是一个预训练的分子图神经网络，给每个底物原子一个 2400 维特征 + 给整个分子一个 4885 维全局特征
- Morgan 指纹是化学规则算出来的 1024 位 0/1 向量，描述分子有哪些子结构
- 两者都用一个线性层降到 128 维

**交叉注意力**：让酶和底物互相"问答"。酶的每个残基去问"底物哪些原子和我最相关"，底物的每个原子也反过来问酶。双向都做一遍。

**预测头**：7 个 128 维向量拼成 896 维，用 3 层 MLP 输出一个分数。

### 6.2 双图架构（EXP005 尝试的改进）

#### 6.2.1 想解决什么问题

原模型的结构通道只有**原子级 EGNN**一条路。EGNN 是"SE(3) 不变"的——只用标量距离，不用方向向量。

EnzymeCAGE 论文（Nature Catalysis 2026）展示了"残基级 GVP"对催化预测的帮助。GVP 是"SE(3) 等变"的——**同时处理标量和 3D 方向向量**，能表达"侧链朝哪个方向"这类 EGNN 学不到的几何信息。

EXP005 的思路：**在原模型基础上新增一条残基级 GVP 通路，不动原模型**，让模型同时利用原子级和残基级两种几何信息。

#### 6.2.4 零初始化的数学保证

这一步很关键，是整个 EXP005 实验方法论的核心。

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  训练第 0 步：EXP005 的输出必须等于 EXP001 基线
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  出口 1 的零初始化效果：
    h_res_proj 最后一层 Linear 权重 = 0
    → h_res_proj 输出全 0
    → x_pro[pos_i] += sigmoid(α) × 0 = 0
    → x_pro 完全不变
    → 后续交叉注意力、池化、拼接结果不变

  出口 2 的零初始化效果：
    预测头第一层 Linear 中，新增的 128 列（对应 g_res_proj）权重 = 0
    → g_res_proj 无论什么值，这 128 列的贡献都是 0
    → 预测头输出完全依赖原 896 列
    → logits 不变

  综合结果：
    EXP005 logits = EXP001 logits（实测误差 4e-8，浮点精度范围内）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  训练第 1 步之后：新分支逐渐"苏醒"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  反向传播计算梯度
  → 新增的零初始化权重接收到非零梯度
  → 经过 AdamW 更新，权重开始离开 0
  → GVP 分支开始对预测产生影响
  → 如果 GVP 信号有用：训练 loss 下降会比基线更快
    如果 GVP 信号无用：权重会慢慢回到接近 0（模型自己"放弃"这个分支）
```

这种设计保证：**EXP005 在训练开始时不会差于基线**，只会变好或不变。理论上它的最终 Test AUC 应该 ≥ EXP001。

**但实际结果是 EXP005 Test AUC = 0.9253，比 EXP001 的 0.9320 低 0.007**。这说明新分支虽然在训练中被激活了，但它引入的"改进方向"实际上是**错误的**——它利用了残基级几何信息，但这种信息和原子级 EGNN 已经学到的信息**高度重复**，再加一遍只是增加噪声。这就是"结构通道饱和"的另一个角度证据。

#### 6.2.5 GVP 和 EGNN 的关键区别

```
┌─────────────────────────────────────────────────────────┐
│  原子级 EGNN（原模型用的）                                │
│                                                         │
│  节点特征：只有标量（元素、氨基酸类型等）                 │
│  边特征：只有标量距离（不用方向）                         │
│  性质：SE(3) 不变（旋转输入，输出不变）                   │
│  表达：只知道 "A 和 B 距离 3.5Å"                        │
│         不知道 "A 在 B 的上方还是下方"                   │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  残基级 GVP（EXP005 新增的）                             │
│                                                         │
│  节点特征：标量 + 3D 方向向量                            │
│  边特征：标量距离 + 单位方向向量                          │
│  性质：SE(3) 等变（旋转输入，标量不变、向量跟着转）        │
│  表达：知道 "A 在 B 上方 2.5Å，侧链朝东"                 │
└─────────────────────────────────────────────────────────┘
```

一句话区分：EGNN 看**距离**，GVP 看**距离 + 方向**。

#### 6.2.6 两个出口的设计意图

**出口 1（深融合 residue backfill）**：把残基级 GVP 信号**早期注入**主干。原模型的 x_pro 里是 ESM 的残基表示，出口 1 把 GVP 的残基表示也加进去，让后续交叉注意力能同时用两种信息。这是"深度融合"，作用在模型中间。

**出口 2（浅旁路 g_res bypass）**：把整个 GVP 通路的总结作为**一个独立向量**，直接拼接到最后的预测输入上。这是"浅融合"，作用在模型末端。

两个出口都开，理论上能兼顾"局部残基级影响"和"全局几何总结"。

#### 6.2.7 实验结果：失败

| 指标 | EXP001 基线 | EXP005 双图 | 变化 |
|---|---|---|---|
| Test AUC | 0.9320 | **0.9253** | **-0.0067** |
| Test AUPR | 0.6749 | 0.6174 | -0.0575 |
| 参数量 | 1,846,660 | 2,684,654 | +45% |

参数增加了 45%，Test AUC 反而下降 0.007。结合 EXP002a（Fe/HEM）和 EXP003（二面角）的结果，三次不同层次的"加结构信息"尝试全部失败，说明当前数据规模和架构组合下，**结构通道已经接近它的表达上限**。
