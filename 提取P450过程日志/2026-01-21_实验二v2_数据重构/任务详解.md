## 一、变更背景

### 导师的两条修改意见

| 修改 | 内容 | 作用位置 |
|------|------|----------|
| **修改1** | 将方案B细分为B1/B2/B3（按配体类型） | PathA Step 3的方案B |
| **修改2** | 去重规则从"按UniProt"改为"按(UniProt + Ligand CCD)" | **本实验（实验二）的筛选漏斗** |

### 为什么需要v2？

原来的实验二（v1）使用"按UniProt去重"的规则，这意味着：
- 同一个酶（UniProt ID相同）只保留一个PDB结构
- 即使该酶与多个配体有共晶结构，也只保留一条记录

新的规则（v2）使用"按UniProt + Ligand去重"：
- 同一个酶与不同配体的组合，视为不同的数据点
- 这样可以保留更多的酶-配体相互作用信息

### Photosystem I污染问题详解

#### 第一层：现象与影响（给所有人看）

我们在数据验证过程中发现 **58条Photosystem I结构** 混入了数据集。尽管它们在PDB中与P450相关联（作为电子传递复合物），但本质上是**光合作用电子传递链**的一部分，并非具备单加氧酶活性的P450酶，因此予以剔除。

**影响范围**:
- 总数据量：740 → 682 (-58条)
- 主要影响"Other"分类：174 → 116 (-58条)
- 其他分类（bacteria, mammals, fungi, plants）数量保持不变

#### 第二层：判定证据（给审核者看）

**典型样本**:
- UniProt ID: W8SUA3, W8SY74
- PDB代表: 6ZZX (Photosystem I trimetric complex from spinach)
- 功能描述: Photosystem I reaction center subunit VII (PsaC)

**判定依据**:
1. **UniProt功能注释**: 明确标注为"Photosystem I"，非CYP家族
2. **辅基类型**: 含铁硫簇（[Fe-S] cluster），而非P450的血红素辅基
3. **EC编号缺失**: 无单加氧酶活性（EC 1.14.14.-）
4. **序列特征**: 缺失P450保守基序（heme-binding Cys附近序列）

#### 第三层：技术操作（给开发者看）

**过滤逻辑**:
```sql
-- 排除条件（58条记录全部满足）
WHERE (
  Entity_Name LIKE '%Photosystem I%'
  OR Organism_Name LIKE '%spinach%' AND Entity_Name NOT LIKE '%CYP%'
)
AND UniProt_ID IN ('W8SUA3', 'W8SY74')
```

**完整剔除列表**: 见附录 `data/03_Step3_配体分类审核/05_排除记录/非P450排除记录_58条_Photosystem_I.csv`

**根因分析**: 上游筛选使用"血红素结合蛋白"作为关键词，导致部分含铁硫簇的光合系统蛋白被误纳入。已在v2.0-Final中完全修正。

## 八、重要说明

### 1. 为什么不叫"Step 3.5"？

之前错误地将此过程命名为"Step 3.5"，这是不正确的。

- **修改2（去重规则变更）** 属于实验二的筛选漏斗，是**上游数据准备**
- **修改1（B→B1/B2/B3）** 属于PathA Step 3的方案选择，是**下游处理策略**

实验二是"数据工厂"，PathA是"数据消费者"。工厂的规则变了，就是实验二v2，而不是PathA的某个步骤。

### 2. sequence字段的重要性

`sequence`字段是RCSB API返回的**deposited sequence**（提交的完整序列），而不是PDB文件中的observed sequence（可能缺少未解析的残基）。

PathA Step 2应该直接使用CSV中的`sequence`字段，而不是从PDB文件解析。这在v1中已经验证：150/158个PDB的序列长度与CSV不一致。

### 3. 数据版本使用指南

⚠️ **严格使用规则**:
- ✅ **分析/建模**: 使用 🟢 **v2.0-Final (682条)**
- ✅ **追溯/验证**: 参考 🔴 **v2.0-Raw (740条)**
- ❌ **禁止混用**: 不要在同一分析中混合使用两个版本

### 4. v1 vs v2 数值对比

| 指标 | v1（按UniProt去重） | v2（按UniProt+Ligand去重） | 原因 |
|------|----|----|------|
| CSV记录数 | 158 | **682** | v2展开了配体，每个酶-配体组合单独记录 |
| 唯一PDB数 | 158 | **627** | 部分PDB包含多个配体，v2需要更多PDB |
| 唯一UniProt | 158 | 155 | v2数量略少是因为ESIBank排除 |
| 唯一序列数 | 158 | 294 | v2包含了突变体和不同构建体 |

### 10.2 筛选漏斗各阶段详解

#### 阶段1：展开为配体记录
```
输入：高质量P450全集_1426个.csv（实体级别，每行一个PDB）
         ↓
展开逻辑：每个实体的每个配体单独成行
         ↓
输出：完整配体列表_3510条.csv

原因：一个PDB结构可能包含多个配体
例如：PDB 1AKD 有camphor和metyrapone两个配体
     → 展开为2条记录
```

#### 阶段2：过滤辅因子和溶剂
```
输入：3510条配体记录
         ↓
排除规则（CCD黑名单）：
  - HEM：血红素（辅因子，几乎每个P450都有）
  - HOH：水分子
  - GOL：甘油
  - EDO：乙二醇
  - ... 等常见结晶添加物
         ↓
输出：有效配体_1370条

排除的原因：
- 辅因子（如血红素）不是"底物"，不应参与预测
- 溶剂和结晶添加物是实验artifact
```

#### 阶段3：按(UniProt + Ligand CCD)去重
```
输入：1370条有效配体记录
         ↓
去重逻辑：
  - 以(uniprot_id, ligand_ccd)为键
  - 同一组合保留分辨率最佳的PDB
         ↓
输出：非冗余记录_930条

为什么这样去重？
- 同一个酶与同一个配体可能有多个共晶结构
- 例如：P00183 + camphor 有PDB 1AKD(1.6Å)、2CPP(2.0Å)
- 只保留1AKD（分辨率更好）
```

#### 阶段4：排除ESIBank交集
```
输入：930条非冗余记录
         ↓
排除规则：
  - 若PDB ID出现在ESIBank训练集中，整条记录排除
  - 这是"PDB级别严格排除"，不是UniProt级别
         ↓
输出：🔴 v2.0-Raw: 独立测试集_740条

为什么这样排除？
- 确保独立性：模型训练时见过的PDB不应出现在测试集
- ESIBank原始数据使用的是AlphaFold预测结构，不是PDB实验结构
- 但如果PDB ID出现在ESIBank，该结构可能被用于训练
```

#### 阶段5：质量控制与纯化（新增）
```
输入：🔴 v2.0-Raw: 740条
         ↓
Photosystem I识别：
  - 三方验证：Claude + Codex + Gemini
  - 判定标准：UniProt注释 + 序列特征 + PDB审查
  - 发现58条非P450记录（W8SUA3, W8SY74）
         ↓
剔除非P450：
  - 740 - 58 = 682
  - 主要影响"Other"分类：174 → 116
         ↓
审计遗漏修复：
  - 发现MYT记录缺失（4ZF8|P14779）
  - 补录到审核文件：681 → 682
         ↓
配体分类审核：
  - 682条全部完成四类分类
  - SUBSTRATE/INHIBITOR/EXCLUDE/PRODUCT
         ↓
输出：🟢 v2.0-Final: 独立测试集_682条
```
