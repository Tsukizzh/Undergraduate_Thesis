## 2. 模型输出详解

### 2.1 模型输出的是什么？

模型对每个酶-底物对输出一个数字，叫**logit**（或score）。

**真实数据示例（我们P450项目）**：

| Dock Index | Enzyme Index | Substrate Index | Label | score(logit) | prob(概率) |
|------------|--------------|-----------------|-------|--------------|------------|
| 126 | 137 | 102 | 1（正） | 2.816 | 0.944 |
| 9 | 246 | 9 | 1（正） | 2.327 | 0.911 |
| 3 | 131 | 3 | 0（负） | 2.203 | 0.901 |
| 5 | 246 | 5 | 1（正） | -0.018 | 0.495 |
| 11 | 200 | 11 | 1（正） | -7.844 | 0.0004 |
| 258 | 121 | 212 | 0（负） | -21.599 | ≈0 |

### 2.2 Logit如何转换为概率？

**公式**：prob = 1 / (1 + exp(-logit))

**实际计算**：

| logit | 计算过程 | prob |
|-------|---------|------|
| 2.816 | 1/(1+exp(-2.816)) = 1/(1+0.0597) | 0.944 |
| 0 | 1/(1+exp(0)) = 1/(1+1) | 0.500 |
| -2.99 | 1/(1+exp(2.99)) = 1/(1+19.88) | 0.048 |
| -7.844 | 1/(1+exp(7.844)) = 1/(1+2548) | 0.0004 |

### 2.4 如何判断正负？

**默认方法**：prob ≥ 0.5 判为正，prob < 0.5 判为负

**我们数据的问题**：

| 样本类型 | 数量 | 平均logit | 平均prob |
|----------|------|-----------|----------|
| 正样本 | 261 | -2.99 | 约5% |
| 负样本 | 256 | -5.05 | 约0.7% |

用0.5阈值：
- 正样本261个中，只有26个prob≥0.5 → 被正确判为正
- 负样本256个中，241个prob<0.5 → 被正确判为负

**为什么正样本漏判这么多？** 因为模型对P450酶完全陌生（训练集0%重叠），给所有样本的分数都很低。

## 4. 评估指标

### 4.1 术语中英对照

| 缩写 | 英文 | 中文 | 含义 |
|------|------|------|------|
| TP | True Positive | 真正例 | 实际是正，模型也判正 |
| FP | False Positive | 假正例 | 实际是负，模型误判为正 |
| FN | False Negative | 假负例 | 实际是正，模型误判为负 |
| TN | True Negative | 真负例 | 实际是负，模型也判负 |

### 4.2 混淆矩阵（阈值=0.5）

```
                          模型预测
                    正(prob≥0.5)    负(prob<0.5)
真实    正(Label=1)   TP=26           FN=235        共261
标签    负(Label=0)   FP=15           TN=241        共256
                     共41            共476         总517

TP=26: 真正例（实际能催化，模型说能催化）
FN=235: 假负例（实际能催化，模型说不能催化）← 漏判最严重
FP=15: 假正例（实际不能催化，模型说能催化）
TN=241: 真负例（实际不能催化，模型说不能催化）
```

### 4.3 各指标计算

| 指标 | 公式 | 中文公式 | 计算 | 结果 |
|------|------|----------|------|------|
| 精确率 Precision | TP/(TP+FP) | 真正例/(真正例+假正例) | 26/(26+15) | 63.4% |
| 召回率 Recall | TP/(TP+FN) | 真正例/(真正例+假负例) | 26/(26+235) | 9.96% |
| 特异度 Specificity | TN/(TN+FP) | 真负例/(真负例+假正例) | 241/(241+15) | 94.1% |
| 准确率 Accuracy | (TP+TN)/总数 | (真正例+真负例)/总数 | (26+241)/517 | 51.6% |
| AUROC | - | 正样本得分>负样本的概率 | sklearn计算 | 66.36% |

### 4.4 AUROC计算方法

**全称**：Area Under the Receiver Operating Characteristic Curve
- **AUC** = Area Under the Curve（曲线下面积）
- **ROC** = Receiver Operating Characteristic（受试者工作特征曲线）

AUROC = 随机抽取一个正样本和一个负样本，正样本logit更高的概率

**我们的真实数据**：
- 正样本261个，负样本256个
- 共261×256=66,816对
- 其中正样本logit更高的约44,300对
- AUROC = 44,300/66,816 ≈ 0.6636

**AUROC的两种等价定义**：

| 定义 | 说明 | sklearn用哪个？ |
|------|------|----------------|
| **几何定义** | ROC曲线下的面积 | ✓ 实际计算用这个 |
| 概率定义 | 随机抽正负样本，正样本分数更高的概率 | 数学上等价，便于理解 |

**sklearn实际计算过程（几何定义）**：

```
Step 1: 按logit分数从高到低排序所有517个样本

排名    Dock Index    Label    logit
─────────────────────────────────────
1       126           1(正)    +2.816
2       9             1(正)    +2.327
3       3             0(负)    +2.203   ← 负样本混入前列
4       ...           ...      ...
...
516     ...           0(负)    -21.3
517     258           0(负)    -21.599
```

```
Step 2: 从高到低遍历，计算每个位置的TPR和FPR

当阈值设在排名1和2之间时（只有Dock126被判为正）：
├── 预测为正的样本：1个（Dock126，是真正例）
├── TPR = TP/总正样本 = 1/261 = 0.38%
└── FPR = FP/总负样本 = 0/256 = 0%

当阈值设在排名2和3之间时（Dock126和Dock9被判为正）：
├── 预测为正的样本：2个（都是真正例）
├── TPR = 2/261 = 0.77%
└── FPR = 0/256 = 0%

当阈值设在排名3和4之间时（前3个被判为正）：
├── 预测为正的样本：3个（2个正+1个负）
├── TPR = 2/261 = 0.77%
└── FPR = 1/256 = 0.39%  ← 第一个假正例出现

... 继续遍历所有517个位置 ...
```

```
Step 3: 画ROC曲线并计算面积

TPR(真正例率)
↑
1.0|                                    ****
   |                               *****
   |                          *****
   |                     *****
   |                *****
   |           *****
   |      *****        ← 我们的ROC曲线
   | *****
   |**
0.0└────────────────────────────────→ FPR(假正例率)
   0                               1.0

曲线下面积 = 0.6636（用梯形法则积分）
```

**为什么两种定义等价？**

数学上可以证明：ROC曲线下面积 = P(正样本分数 > 负样本分数)

这是因为：
- ROC曲线上的每个点对应一个阈值
- 面积积分等价于统计"正样本排在负样本前面"的比例

**我们的真实数据验证**：

```python
from sklearn.metrics import roc_auc_score
auc = roc_auc_score(labels, scores)  # = 0.6636
```

sklearn内部做的就是Step 1-3的过程，不是两两配对比较。

### 4.5 AUPR计算方法

**全称**：Area Under the Precision-Recall Curve
- **AUPR** = Area Under the Precision-Recall curve（精确率-召回率曲线下面积）
- **Precision** = 精确率（预测为正的样本中，真正是正的比例）
- **Recall** = 召回率（实际为正的样本中，被正确预测为正的比例）

AUPR = 精确率-召回率曲线下的面积

**我们的真实数据**：
- AUPR = 0.6360
- 这比AUROC（0.6636）略低

**AUPR vs AUROC的关键区别**：

| 特性 | AUROC | AUPR |
|------|-------|------|
| 横轴 | FPR（假正例率）| Recall（召回率）|
| 纵轴 | TPR（真正例率=Recall）| Precision（精确率）|
| 关注点 | 整体排序能力 | 正样本的预测质量 |
| 适用场景 | 样本均衡时 | **样本不均衡时更有意义** |
| 随机基线 | 0.5（固定） | 正样本比例（我们是261/517=50.5%）|

**sklearn实际计算过程（几何定义）**：

```
Step 1: 按logit分数从高到低排序所有517个样本

排名    Dock Index    Label    logit
─────────────────────────────────────
1       126           1(正)    +2.816
2       9             1(正)    +2.327
3       3             0(负)    +2.203   ← 负样本混入
4       ...           ...      ...
...
517     258           0(负)    -21.599
```

```
Step 2: 从高到低遍历，计算每个位置的Precision和Recall

当阈值设在排名1和2之间时（只有Dock126被判为正）：
├── 预测为正的样本：1个（Dock126，是真正例）
├── Precision = TP/(TP+FP) = 1/1 = 100%
└── Recall = TP/总正样本 = 1/261 = 0.38%

当阈值设在排名2和3之间时（Dock126和Dock9被判为正）：
├── 预测为正的样本：2个（都是真正例）
├── Precision = 2/2 = 100%
└── Recall = 2/261 = 0.77%

当阈值设在排名3和4之间时（前3个被判为正）：
├── 预测为正的样本：3个（2个正+1个负）
├── Precision = 2/3 = 66.7%  ← Precision开始下降
└── Recall = 2/261 = 0.77%

... 继续遍历所有517个位置 ...

当所有样本都被判为正时：
├── Precision = 261/517 = 50.5%（正样本比例）
└── Recall = 261/261 = 100%
```

```
Step 3: 画Precision-Recall曲线并计算面积

Precision(精确率)
↑
1.0|**
   |  **
   |    ***
   |       ****
   |           *****
   |                *****        ← 我们的PR曲线
   |                     ******
   |                           ****
0.5|                               ***
   └────────────────────────────────→ Recall(召回率)
   0                               1.0

曲线下面积 = 0.6360（用梯形法则积分）
```

**为什么AUPR < AUROC？**

```
AUROC = 0.6636 > AUPR = 0.6360

原因分析：
┌────────────────────────────────────────────────────────┐
│ AUROC关注"能否把正样本排在负样本前面"                    │
│ - 只要正样本logit普遍>负样本logit就能得高分              │
│ - 我们的数据：正样本平均-2.99，负样本-5.05               │
│ - 差距2个logit单位，所以AUROC有66%                       │
└────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────┐
│ AUPR关注"预测为正的样本中，有多少真的是正"               │
│ - 不仅要排序好，还要确保高分区域没有太多负样本混入        │
│ - 我们的数据：正负样本分布重叠严重                        │
│   (负样本最高+2.20，正样本最低-14.58，大量重叠区域)       │
│ - 所以AUPR稍低（63.6%）                                  │
└────────────────────────────────────────────────────────┘
```

**实际例子（我们的数据）**：

| 阈值位置 | Precision | Recall | 说明 |
|---------|-----------|--------|------|
| Top 10 | 90% | 3.4% | 前10个样本中9个是正样本，Precision很高 |
| Top 50 | 74% | 14.2% | 前50个中37个是正样本 |
| Top 100 | 65% | 24.9% | 前100个中65个是正样本 |
| Top 200 | 58% | 44.4% | 前200个中116个是正样本 |
| 全部517 | 50.5% | 100% | 降到正样本比例基线 |

**AUPR在不平衡数据中的优势**：

假设有两个模型A和B在1000个样本（10个正+990个负）上测试：

```
模型A：随机猜测
- AUROC = 0.50（总能得到50%）
- AUPR ≈ 0.01（只有1%，远低于50%）

模型B：我们的P450模型
- AUROC = 0.6636
- AUPR = 0.6360（远高于正样本比例50.5%）
```

**结论**：虽然AUPR < AUROC，但AUPR = 0.6360仍然**远高于随机基线**（50.5%），说明模型在P450上有实际预测价值。

### 4.6 召回率为什么只有9.96%？

**根因分析**：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                      召回率低的原因链条                                       │
└─────────────────────────────────────────────────────────────────────────────┘

原因1: 模型对P450完全陌生
       ↓
原因2: 所有样本得分普遍偏低
       ↓
原因3: 正样本平均prob只有5%，远低于50%阈值
       ↓
结果: 261个正样本中，只有26个能过阈值
```

**数据证据**：

| 正样本得分区间 | 数量 | 占比 | 能过0.5阈值？ |
|---------------|------|------|--------------|
| logit ≥ 0 (prob ≥ 50%) | 26 | 10.0% | ✓ 能 |
| -3 ≤ logit < 0 (prob 5%~50%) | 89 | 34.1% | ✗ 不能 |
| -7 ≤ logit < -3 (prob 0.1%~5%) | 102 | 39.1% | ✗ 不能 |
| logit < -7 (prob < 0.1%) | 44 | 16.9% | ✗ 不能 |
| **总计** | **261** | **100%** | 仅26个能过 |

**关键结论**：90%的正样本的概率值低于50%阈值，所以召回率只有10%。

**这是模型失败吗？** 不完全是：
- 正样本仍然**整体高于**负样本（正样本平均-2.99，负样本-5.05）
- 只是**整体分布向左偏移**，导致绝对值都很低
- AUC-ROC=66%说明**排序能力仍然存在**

| 25%分位 | -5.99 | -7.11 | +1.12 |
| 最小值 | -14.58 | -21.60 | +7.02 |
| **平均值** | **-2.99** | **-5.05** | **+2.06** |
| 标准差 | 3.52 | 3.97 | -0.45 |

**关键观察**：
1. 两组分布有**大量重叠**（负样本最高+2.20，正样本最低-14.58）
2. 正样本**整体右移约2个logit单位**，这是AUC>50%的原因
3. 两组**都严重负偏移**，说明模型对P450普遍"不自信"

### 4.8 论文中的阈值选择

**关键澄清：阈值到底影响什么？**

| 指标类型 | 需要阈值吗？ | 阈值影响结果吗？ | 例子 |
|---------|------------|----------------|------|
| **混淆矩阵指标** | ✓ 需要 | ✓ 影响 | Precision、Recall、Accuracy、F1 |
| **排序指标** | ✗ 不需要 | ✗ 不影响 | AUC-ROC、AUC-PR |

**具体说明**：

```
场景1: 计算Precision/Recall（需要阈值）
─────────────────────────────────────
1. 先选阈值: prob ≥ 0.5 → 判为正
2. 然后分类: 517个样本分成正/负两类
3. 算混淆矩阵: TP=26, FP=15, FN=235, TN=241
4. 计算指标: Recall = 26/261 = 9.96%

如果换阈值: prob ≥ 0.1 → 判为正
             Recall就会变高（更多正样本被判为正）

结论: 这些指标**依赖阈值选择**
```

```
场景2: 计算AUROC（不需要阈值）
─────────────────────────────────────
1. 不选阈值，遍历所有可能阈值（517个）
2. 每个阈值算一组(FPR, TPR)
3. 画ROC曲线，计算面积
4. AUROC = 0.6636

无论你后续选0.5还是0.1作为阈值:
AUROC永远是0.6636（只要模型打分不变）

结论: 这个指标**与阈值无关**
```

**论文原文做法**：

| 场景 | 论文方法 | 是否用固定阈值 | 说明 |
|------|---------|---------------|------|
| 模型评估 | AUROC, AUPR | **不用固定阈值** | 遍历所有阈值，所以不受单个阈值影响 |
| 验证集选模型 | 按AUPR排序 | **不用固定阈值** | 只看排序能力，不看分类结果 |
| 实际部署使用 | 输出logit/prob给用户 | 用户自定义阈值 | 不同应用场景需要不同阈值 |

**论文为什么不报告Precision/Recall？**

因为这些指标**必须先选阈值**，而：
- 默认0.5阈值对域外数据（如我们的P450）不适用
- 不同应用场景需要不同阈值（药物筛选可能用0.8，基础研究可能用0.3）
- 报告单个阈值下的结果容易误导

**我们的报告为什么有Precision/Recall？**

因为我们需要分析**为什么召回率这么低**，所以：
- 用默认0.5阈值算了一次（Recall=9.96%）
- 发现阈值不适配，又算了最优阈值0.0379（Recall=58.6%）

**论文中会不会也有召回率低的问题？**

**答案：不太可能**。原因如下：

| 对比项 | 论文测试集 | 我们的P450测试集 | 结果 |
|--------|-----------|----------------|------|
| **负样本定义** | 随机配对（酶A+底物X，X不相关） | 抑制剂（能结合但不催化） | 论文更容易区分 |
| **酶的分布** | 与训练集同分布 | 完全不重叠（0%） | 论文分数不会整体偏低 |
| **底物的分布** | 与训练集同分布 | 部分重叠（10.8%） | 论文分数更可信 |
| **0.5阈值适用性** | ✓ 适用 | ✗ 不适用 | 论文召回率应该正常 |

**具体分析**：

```
论文的情况（推测）：
─────────────────────
训练集: 正样本 vs 随机配对负样本
验证集: 正样本 vs 随机配对负样本  ← 用来选checkpoint
测试集: 正样本 vs 随机配对负样本

因为三个集合的分布一致：
├── 正样本的prob应该普遍 > 50%
├── 负样本的prob应该普遍 < 50%
└── 用0.5阈值是合理的，召回率应该不会很低

我们的情况（实际）：
─────────────────────
训练集: 正样本 vs 随机配对负样本（论文的数据）
测试集: 正样本 vs 抑制剂负样本（我们的P450）

分布完全不同（domain shift）：
├── 模型对P450"不自信"
├── 正样本的prob普遍只有5%
├── 负样本的prob普遍只有0.7%
└── 用0.5阈值，90%正样本被漏判
```

**论文为什么不报告召回率？**

可能的原因：
1. **避免阈值争议**：Recall依赖阈值选择，报告单个阈值容易误导
2. **通用性考虑**：不同应用场景需要不同阈值（药物筛选vs基础研究）
3. **学术惯例**：分子预测领域更看重排序能力（AUC），而非分类准确性

**我们的召回率低说明了什么？**

| 指标 | 数值 | 含义 |
|------|------|------|
| AUROC | 0.6636 | 模型**仍有排序能力**，能区分正负样本 |
| Recall@0.5 | 9.96% | 默认阈值**完全不适用**于P450 |
| Recall@0.0379 | 58.6% | 重新校准阈值后**恢复正常** |

**结论**：
- 论文的召回率应该不会像我们这么低（因为测试分布与训练一致）
- 我们的低召回率是**域偏移**的正常现象，不代表模型失败
- 解决方案：阈值校准（已做）或模型微调（路径C）

**总结**：

| 问题 | 答案 |
|------|------|
| 0.5阈值影响Recall吗？ | **影响**！换成0.0379，Recall从10%升到59% |
| 0.5阈值影响AUROC吗？ | **不影响**！AUROC永远是0.6636 |
| 论文有固定阈值吗？ | **没有**，用AUROC评估所以不需要 |
| 实际应用需要阈值吗？ | **需要**，但由用户根据场景自定义 |

**我们如何选择最优阈值？**

使用Youden's J统计量：J = Sensitivity + Specificity - 1

```
阈值选择过程：

阈值(prob)    阈值(logit)    Recall    Specificity    J值
───────────────────────────────────────────────────────────────
0.90          +2.20          3.1%       99.2%         0.023
0.50          0.00           10.0%      94.1%         0.041
0.10          -2.20          41.4%      69.5%         0.109
0.0379        -3.23          58.6%      57.4%         0.160 ← 最优
0.01          -4.60          73.9%      39.8%         0.137
0.001         -6.91          86.6%      20.7%         0.073
───────────────────────────────────────────────────────────────

最优阈值: prob = 0.0379 (logit = -3.23)
此时: Recall = 58.6%, Specificity = 57.4%
```

**为什么最优阈值是0.0379而不是0.5？**

因为模型对P450酶完全陌生，给所有样本的分数都很低。0.5阈值是针对训练分布设计的，不适用于P450这种域外数据。

### 4.9 训练集和测试集类别比例不同的影响

**关键问题**：ESIBank训练集正负样本比例为1:9.36，我们的P450测试集比例为1:1（261正/256负），这种差异会影响评估结果吗？

**答案：对AUROC影响很小，但对概率校准影响很大**

#### 4.9.1 AUROC对类别比例稳健（有强文献支持）

**最新研究证据（2024年）**：

[Richardson et al. (2024)](https://pmc.ncbi.nlm.nih.gov/articles/PMC11240176/) 在*Patterns*期刊发表的研究明确指出：

> **"ROC曲线对类别不平衡稳健，而PR曲线对类别不平衡高度敏感"**

> **"评估分类器使用ROC-AUC的一个便利特性是，它的值对类别不平衡是不变的"**

> **"ROC-AUC在分数分布不被类别不平衡改变时，对类别不平衡是不变的，而PR-AUC会随类别比例剧烈变化"**

**数学原理**：

```
AUROC = P(正样本得分 > 负样本得分)

这个定义只涉及：
├── 正样本和负样本的相对排序
└── 不涉及正负样本的数量比例

因此：
- 训练集 1:9.36（正:负）
- 测试集 1:1（正:负）
- 对AUROC的影响：很小（如果分数分布稳定）
```

**文献对比证据**：

[McDermott et al. (2024)](https://arxiv.org/html/2401.06091v1) 在arXiv论文中指出：

> **"PR-AUC值不仅依赖于类别不平衡，而且分类器的排序也依赖于不平衡率。这意味着两个分类器在不同不平衡率下可能互换位置"**

相比之下，AUROC在不同类别比例下保持稳定。

#### 4.9.2 我们项目的实际情况

| 数据集 | 正样本数 | 负样本数 | 正负比例 | AUROC可比性 |
|--------|----------|----------|----------|------------|
| ESIBank训练集 | ~34,500 | ~323,000 | 1:9.36 | - |
| 论文测试集 | - | - | ~1:9.36（推测）| ✓ 与训练集一致 |
| **我们P450测试** | 261 | 256 | **1:1** | ✓ **仍可与论文比较** |

**为什么我们的AUROC = 0.6636仍然可信？**

1. **AUROC衡量排序能力**：模型能否把正样本排在负样本前面
   - 我们的数据：正样本平均-2.99，负样本-5.05
   - 差距2.06个logit单位，AUROC = 66.36%
   - 这个排序能力是真实的，不受测试集类别比例影响

2. **与论文的比较是有效的**：
   - 论文Unknown enzyme+substrate: AUROC = 0.7198
   - 我们P450测试: AUROC = 0.6636
   - 差距5.6%主要来自：
     - 负样本定义不同（抑制剂 vs 随机配对）
     - 酶完全不重叠（0%）
     - 化学空间差异

3. **文献支持**：AUROC在不同类别比例下的排序是一致的

#### 4.9.3 但概率校准受影响很大 ⚠️

**问题：模型输出的概率值不可信**

[MachineLearningMastery](https://machinelearningmastery.com/probability-calibration-for-imbalanced-classification/) 指出：

> **"在不平衡数据上训练的模型，预测概率会系统性地低估少数类的概率"**

> **"重采样方法改变了数据的类别分布。如果将模型应用到测试数据并获得预测概率，这些概率不会反映原始数据的分布"**

**我们的实际表现**：

| 现象 | 数值 | 原因 |
|------|------|------|
| 正样本平均prob | 5% | 模型在1:9.36训练集上学到"正类很少" |
| 负样本平均prob | 0.7% | 整体分布向负偏移 |
| 默认阈值0.5 | Recall=9.96% | 完全不适用 |
| 最优阈值 | 0.0379 | 需要重新校准 |

**分布偏移示例**（来自我们的真实数据）：

```
如果模型在训练时学到：
- 正样本概率分布：均值60%，标准差20%
- 负样本概率分布：均值40%，标准差20%
- 在1:9.36比例下，阈值0.5是合理的

但应用到我们的1:1测试集时：
- 模型"不自信"，给所有样本打低分
- 正样本概率分布：均值5%，标准差？%  ← 整体左移
- 负样本概率分布：均值0.7%，标准差？%
- 阈值0.5变得不适用，需要降到0.04
```

#### 4.9.4 重要限制和反对意见

**最新质疑（2026年1月）**：

[Recent paper (MDPI, Jan 2026)](https://www.mdpi.com/2227-7080/14/1/54) 指出：

> **"在极度不平衡（<3%正样本）时，几乎任何非退化分类器都能达到0.90-0.99的ROC-AUC，掩盖了驱动操作成本的错误"**

**但这不适用于我们的情况**：
- 我们的测试集：50%正样本（261/517）
- **不属于"极度不平衡"**
- AUROC = 0.6636是真实的排序能力

#### 4.9.5 总结：两个层面的影响

| 层面 | 影响程度 | 说明 | 文献支持 |
|------|----------|------|----------|
| **AUROC指标** | ✅ 很小 | 可以与论文的0.7198直接比较 | [Richardson 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC11240176/) |
| **概率输出** | ⚠️ 很大 | 需要重新校准阈值（0.5→0.04） | [MachineLearningMastery](https://machinelearningmastery.com/probability-calibration-for-imbalanced-classification/) |

**对我们项目的实际意义**：

1. **AUROC = 0.6636是可靠的**
   - 可以与论文的0.7198比较
   - 5.6%的差距主要来自任务不匹配（负样本定义）
   - 类别比例差异（1:9.36 vs 1:1）的影响很小

2. **但概率值需要校准**
   - 不能直接使用prob>0.5判断
   - 需要在P450验证集上重新选择阈值
   - 我们找到的最优阈值是0.0379

3. **模型仍有预测价值**
   - AUROC = 0.6636 远高于随机（0.5）
   - AUPR = 0.6360 远高于基线（0.505）
   - 说明模型在P450上仍能区分正负样本

## 5. 结果分析

### 5.1 为什么AUROC只有66%？

**原因1：模型对P450酶完全陌生**
- 训练集8000+酶，我们测试148个P450
- 重叠率：0%

**原因2：负样本定义不同**
- 训练时：负样本=随机配对的酶-底物（通常完全不相关）
- 我们测试：负样本=抑制剂（能结合到酶上，只是不发生催化）

**原因3：分数分布向负偏移**
- 正样本平均logit：-2.99（对应prob≈5%）
- 负样本平均logit：-5.05（对应prob≈0.7%）
- 正样本仍略高于负样本，所以AUC>50%

### 5.2 结果对比

| 场景 | AUROC |
|------|---------|
| 论文Unknown enzyme+substrate | 0.7198 |
| 我们P450测试 | 0.6636 |
| 随机猜测 | 0.5000 |

差距5.6%主要来自负样本定义差异。

## 6. 结构数据可能的问题

以下是结构特征提取中可能存在的问题（非已发现问题，是潜在风险点）：

### 6.1 口袋提取阶段

| 潜在问题 | 风险 | 检查方法 |
|----------|------|----------|
| 10Å阈值不适合P450 | P450活性口袋较大，可能截断关键残基 | 检查提取的口袋是否包含血红素配位残基 |
| 多链PDB处理 | 提取口袋时可能只取了一条链 | 对比口袋残基数与PDB总残基数 |
| 水分子/辅因子处理 | 血红素是否被正确保留或排除 | 检查提取的pocket文件 |

### 6.2 配体对齐阶段

| 潜在问题 | 风险 | 检查方法 |
|----------|------|----------|
| SMILES与PDB配体不一致 | 原子顺序错配导致坐标混乱 | 对比对齐前后的RMSD |
| 立体化学丢失 | CCD提取的SMILES可能丢失手性信息 | 检查含手性中心的配体 |
| 键级错误 | 芳香环可能被错误处理 | 可视化对齐后的SDF |

### 6.3 如何验证？

```
验证步骤：
1. 随机抽取10个高分正样本 + 10个低分正样本
2. 用PyMOL对比：
   - 原始PDB中的配体位置
   - 提取的口袋是否完整
   - 对齐后的配体RMSD
3. 如果低分正样本的结构质量明显差于高分正样本，说明结构特征提取有问题
```

## 7. 改进方向

### 7.1 快速判断：哪些改进能提升AUROC？

| 改进 | 能提升AUROC吗 | 说明 |
|------|:--------------:|------|
| 调整阈值 | **不能** | AUC只看排序，与阈值无关 |
| 用P450数据微调模型 | **能** | 让模型学习P450特征 |
| 用随机配对做负样本 | **能** | 与训练时任务一致 |
| 修复结构提取问题 | **可能** | 取决于是否真的有问题 |

### 7.2 三条改进路径详解

#### 路径1：随机配对负样本测试（验证任务匹配假说）

**目标**：验证"任务不匹配"是否是AUROC偏低的主因

**方法**：
1. 保留现有517个P450酶-底物对
2. 重新生成负样本：随机配对酶和底物（而非使用抑制剂）
3. 使用相同的best-checkpoint.ckpt重新预测
4. 对比AUROC变化

**预期结果**：
- 如果AUROC提升至≥0.72（接近论文的0.7198），证实任务不匹配是主因
- 如果AUROC仍然≤0.67，说明存在其他问题（数据质量、P450特性等）

**时间成本**：1-2天（仅需重新生成data.csv和运行推理）

**价值**：
- ✅ 明确问题根源，指导后续研究方向
- ✅ 快速、成本低
- ❌ 不能提升实际预测能力（仅诊断性）

---

#### 路径2：P450专属模型微调（Path C）

**目标**：让模型学习P450特异性，提升真实预测能力

**方法**：
1. 构建P450训练集（Path B）
   - 从BRENDA提取P450酶-底物对（正样本）
   - 生成随机配对负样本（与ESIBank一致）
   - 预计规模：1000-5000对
2. 在best-checkpoint.ckpt基础上微调
   - 学习率降低10倍（防止过拟合）
   - 训练5-10 epochs
3. 在我们的测试集上验证

**预期结果**：
- AUROC提升至0.75-0.82
- 对P450底物预测更准确

**时间成本**：2-3个月
- Path B（数据集构建）：4-6周
- Path C（模型训练）：2-4周
- 调试优化：2-4周

**价值**：
- ✅ 实质性提升P450预测能力
- ✅ 可产出论文/工具
- ❌ 工作量大，需GPU资源

---

#### 路径3：数据质量修复

**目标**：排除数据问题导致的性能低估

**子任务**：

**3.1 标签验证**（优先级：高）
- 问题：PDB配体可能被错误分类（如底物误标为抑制剂）
- 方法：
  1. 抽查20个低分正样本（模型认为不匹配，但标签为正）
  2. 查阅原始文献，验证配体真实角色
  3. 统计错标率
- 时间：1周
- 预期：如果错标率>10%，修正后AUROC可能提升2-5%

**3.2 结构特征检查**（优先级：中）
- 问题：口袋提取或配体对齐可能有误
- 方法：
  1. 随机抽取10个高分正样本 + 10个低分正样本
  2. 用PyMOL可视化：
     - 提取的口袋是否完整
     - 配体对齐RMSD是否合理
  3. 如果低分样本结构明显更差，说明特征提取有问题
- 时间：3-5天
- 预期：如果有系统性问题，修正后AUROC可能提升3-8%

**3.3 特征工程**（优先级：低）
- 尝试不同的蛋白质嵌入（ESM-1b vs ESM-2）
- 调整GROVER指纹参数
- 时间：1-2周
- 预期：提升有限（1-3%）
