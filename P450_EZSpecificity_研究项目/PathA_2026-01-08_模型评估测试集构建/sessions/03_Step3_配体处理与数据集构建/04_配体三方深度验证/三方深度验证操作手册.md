## 三方协作流程详解

### 强制执行的三步流程

每条记录必须执行以下三步，**禁止跳过任何一步**：

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: Gemini文献搜索（强制）                               │
│  ├── 搜索enzyme + ligand的文献                               │
│  ├── 获取Ki/IC50/Km定量数据                                  │
│  └── 返回PMID                                               │
├─────────────────────────────────────────────────────────────┤
│  Step 2: Codex结构分析（强制）                               │
│  ├── 分析PDB结构                                            │
│  ├── 测量Fe-配体距离                                        │
│  └── 评估结合模式                                           │
├─────────────────────────────────────────────────────────────┤
│  Step 3: Claude汇总决策（强制）                              │
│  ├── 整合Gemini文献 + Codex结构                             │
│  ├── 判断三方是否一致                                       │
│  └── 输出最终分类 + 置信度                                  │
└─────────────────────────────────────────────────────────────┘
```

### MCP调用示例

**Gemini文献搜索**：
```python
mcp__gemini__gemini(
    PROMPT="""
    Literature search for: CYP2D6 + Ajmalicine

    Search for:
    1. Is it SUBSTRATE or INHIBITOR?
    2. Ki, IC50 values
    3. PMID

    Brief answer.
    """,
    cd="<project_root>"
)
```

**Codex结构分析**：
```python

    1. Fe-ligand distance
    2. Binding mode
    3. Classification: SUBSTRATE/INHIBITOR?
    """,
    cd="<project_root>",
    sandbox="read-only"
)
```

### 必填字段

| 字段 | 说明 |
|------|------|
| `gemini_result` | Gemini的完整返回（必须包含） |
| `codex_result` | Codex的完整返回（必须包含） |
| `consensus` | 三方是否一致 |
| `final_class` | 最终分类（SUBSTRATE/INHIBITOR/PRODUCT/EXCLUDE） |
| `confidence` | 置信度（HIGH/MEDIUM/LOW） |
| `evidence_level` | A（定量数据）/B（文献明确）/C（结构推断）/D（证据不足） |
| `needs_human_review` | 是否需要人工复审 |
| `reasoning` | 详细推理过程 |

## 质量控制

### 有效记录标准

**有效记录必须满足**：
1. 包含`gemini_result`字段（证明调用了Gemini）
2. 包含`codex_result`字段（证明调用了Codex）
3. `reasoning`字段引用了Gemini和Codex的结果

**无效记录特征**：
- 缺少`gemini_result`或`codex_result`
- `reasoning`只有"我认为是xxx"没有引用证据
- `evidence_level`标为A但没有定量数据

### 验收检查

合并后运行验收检查：
```python
# 检查每条记录是否包含三方结果
import json
with open('三方深度验证结果_merged.jsonl', 'r') as f:
    for line in f:
        r = json.loads(line)
        if 'gemini_result' not in r or 'codex_result' not in r:
            print(f"[INVALID] {r['record_id']}: 缺少三方结果")
```

## 常见问题

### Q1: Gemini找不到文献怎么办？

**处理方式**：
1. Gemini明确返回"No literature found"
2. 在`gemini_result`中记录这个结果
3. 依赖Codex结构分析
4. 如果Codex也不确定，标记`needs_human_review=true`

### Q2: Codex和Gemini结论冲突怎么办？

**处理方式**：
1. 分析冲突原因（野生型vs突变体？配体双重行为？）
2. 如果能解决，记录解决过程
3. 如果无法解决，标记`needs_human_review=true`

### Q3: MCP调用超时怎么办？

**处理方式**：
1. 重试一次
2. 如果仍然超时，记录错误信息
3. 该记录标记`needs_human_review=true`
