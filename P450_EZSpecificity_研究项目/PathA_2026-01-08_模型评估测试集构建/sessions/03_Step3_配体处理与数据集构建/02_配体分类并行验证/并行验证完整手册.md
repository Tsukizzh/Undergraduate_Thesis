## 第一部分：项目背景与目标

### 1.1 为什么需要配体分类验证？

在P450酶-底物特异性研究中，我们从PDB数据库获取了682条P450酶-配体共晶结构记录。这些记录已经过初步人工分类（`final_class`字段），但需要系统性验证以确保：

1. **分类准确性**：确认每个配体的分类（SUBSTRATE/INHIBITOR/PRODUCT/EXCLUDE）是否正确
2. **陷阱检测**：识别容易混淆的案例（如底物vs产物、野生型vs突变体）
3. **质量标记**：为不确定的记录标注置信度，筛选需要深度复审的高风险记录

### 1.2 为什么采用并行处理？

682条记录若串行处理（每条3分钟），需要约34小时。通过6个窗口并行处理：

```
传统串行：682条 × 3分钟 = 34小时
并行处理：682条 ÷ 6窗口 × 3分钟 = 5.7小时
效率提升：6倍
```

### 1.3 混合方案设计理念

**核心思想**：分层处理，资源最优化

```
┌─────────────────────────────────────────────────────────────┐
│                    混合方案架构                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│   阶段1：快速并行验证（6个窗口）                              │
│   ├── 目标：快速处理全部682条                                │
│   ├── 方法：单Claude窗口 + 简化验证流程                      │
│   ├── 工具：Read + WebSearch(可选) + Write + Bash(只读)      │
│   ├── 耗时：6-8小时                                          │
│   └── 输出：标记高风险记录（needs_human_review=true）        │
│                          ↓                                   │
│   阶段1.5：合并与筛选                                        │
│   ├── 合并6个chunk的结果                                     │
│   ├── 筛选高风险记录（约50-100条）                           │
│   └── 耗时：10分钟                                           │
│                          ↓                                   │
│   阶段2：深度三方复审（仅高风险记录）                        │
│   ├── 目标：确保高风险记录分类正确                           │
│   ├── 方法：Claude + Codex + Gemini 三方协作                 │
│   ├── 每条耗时：10-15分钟                                    │
│   └── 总耗时：2-3小时（按50条计算）                          │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**为什么不在阶段1就用三方协作？**

1. **资源冲突**：6个窗口同时调用Codex/Gemini会导致API资源争用
2. **效率低下**：大部分记录（约80%）分类明确，不需要深度分析
3. **流程混乱**：每个窗口各自讨论会产生难以统一的结果

## 第二部分：数据分块与分配

### 2.1 输入数据来源

**原始文件**：682条P450酶-配体记录，来自Step 3.01的配体分类审核结果

**关键字段**：
- `record_id`：全局唯一ID（REC_0001 ~ REC_0682）

- `enzyme_name`：酶名称

## 第四部分：验证方法论

### 4.1 分类标准

| 分类 | 定义 | 关键证据 | 常见例子 |
|------|------|----------|----------|
| **SUBSTRATE** | 被酶催化/代谢的配体 | Km、Kcat、turnover、产物鉴定 | 底物、反应物 |
| **INHIBITOR** | 抑制酶活性的配体 | Ki、IC50、抑制曲线、Fe-N距离 | 氮唑类、三唑类 |
| **PRODUCT** | 酶促反应的产物 | 反应机制明确显示为产物 | 羟基化产物 |
| **EXCLUDE** | 应排除的配体 | 辅因子、溶剂、突变体矛盾 | O2、水、缓冲液、探针 |

### 4.2 置信度评级标准

| 置信度 | 定义 | 触发条件 |
|--------|------|----------|
| **HIGH** | 高度确定 | 有定量实验数据（Km/Ki/IC50）或明确文献支持 |
| **MEDIUM** | 中等确定 | 基于化学结构或酶功能推断，缺乏直接实验证据 |
| **LOW** | 低度确定 | 证据不足或存在矛盾，需要进一步验证 |

### 4.3 证据等级标准

| 等级 | 定义 | 示例 |
|------|------|------|
| **A** | 定量实验数据 | Fe-N距离测量（2.0-2.5Å）、Km=50μM、Ki=10nM |
| **B** | 定性文献支持 | Notes明确说明"substrate"/"inhibitor" |
| **C** | 结构/化学推断 | 基于配体骨架或酶功能推断 |
| **D** | 证据不足 | 缺乏直接证据，需要补充实验 |

### 4.4 陷阱检测机制

**陷阱1：野生型 vs 突变体矛盾 (wildtype_mutant_conflict)**

```
检测逻辑：
1. 检查PDB标题是否包含 mutation/mutant/variant
2. 如果PDB是突变体但UniProt是野生型：
   - 突变是否改变了底物特异性？
   - 野生型能否代谢该配体？
3. 如果存在矛盾且无法确定 → 标记为EXCLUDE或needs_human_review

示例：
- PDB: "CYP2D6 F120A mutant with debrisoquine"
- 问题：F120A突变可能改变了底物谱
- 处理：需要文献确认野生型是否也代谢debrisoquine
```

**陷阱2：底物 vs 产物混淆 (substrate_product_confusion)**

```
检测逻辑：
1. 检查配体是反应物还是生成物
2. 关键词"product"不一定意味着PRODUCT分类！
3. 需要查文献确认反应方向

示例：
- 配体：5-exo-hydroxycamphor
- 误判：看到"hydroxy"以为是底物
- 实际：是CYP101催化camphor的产物
- 处理：分类为PRODUCT，并标记trap_detected

本次实际检出：19例
```

**陷阱3：机制驱动抑制剂 (mechanism_based_inhibitor)**

```
检测逻辑：
1. 这类配体同时有底物特征和抑制特征
2. 被酶激活后形成共价修饰
3. 应分类为INHIBITOR，不是SUBSTRATE

示例：
- 配体：4-methylaniline (REC_0354)
- 特点：芳香胺可被N-氧化（底物行为）或Fe-N配位（抑制行为）
- 分类：标记needs_human_review，待确认

本次实际检出：2例
```

### 4.6 窗口批量处理流程详解

每个窗口拿到分配的chunk（约114条记录）后，按照以下流程处理：

#### 4.6.1 启动阶段（前5分钟）

```
Step 1: 窗口启动并读取SOP
├── 阅读"覆盖全局配置"声明
├── 确认工具限制（Read/WebSearch/Write/Bash只读）
└── 确认不使用Codex/Gemini

Step 2: 读取输入文件
├── 使用Read工具读取chunk_XX.csv
├── 确认记录数量（应为114或112）
└── 查看CSV表头和前几行样本

Step 3: 创建输出文件路径
├── 确认输出目录：02_输出数据_results/chunk_XX_results/
├── 初始化空的JSONL文件：verified_results.jsonl
└── 准备报告文件：verification_report.md
```

#### 4.6.2 批量处理阶段（主要工作）

窗口通常采用**分批次处理策略**：

**策略A：小批次迭代**（Chunk 01, 02, 03使用）
```
第1批：处理记录1-20（约40-60分钟）
  ├── 读取CSV的第1-20行
  ├── 逐条验证（每条2-3分钟）
  ├── 写入20条JSONL记录
  └── 使用bash wc -l确认已写入20行

第2批：处理记录21-40
  ├── 读取CSV的第21-40行
  ├── 逐条验证
  ├── 追加写入JSONL（现在共40行）
  └── 确认累计40行

... 依此类推 ...

第6批：处理记录101-114
  ├── 读取CSV剩余行
  ├── 完成最后14条
  └── 最终确认114行
```

**策略B：大批次处理**（Chunk 04, 05, 06使用）
```
第1批：处理记录1-60（约2-3小时）
  ├── 一次性读取大量记录
  ├── 连续验证60条
  └── 写入60条JSONL

第2批：处理记录61-114
  ├── 读取剩余记录
  ├── 完成剩余54条
  └── 最终确认114行
```

#### 4.6.3 验证报告生成阶段（最后30分钟）

```
Step 1: 统计分析
├── 使用bash grep或手动统计JSONL中的分类分布
├── 统计置信度分布（HIGH/MEDIUM/LOW）
├── 统计needs_human_review=true的记录数
└── 统计检测到的陷阱类型

Step 2: 生成验证报告
├── 写入verification_report.md
├── 包含统计表格、关键发现、修正案例
└── 列出需要人工复审的记录

Step 3: 完成确认
├── 最后一次使用wc -l确认行数
├── 向用户报告任务完成
└── 提供文件路径和统计摘要
```

### 4.7 典型HIGH置信度记录处理示例

> **本节回答**：那667条不需要复审的记录是如何被快速处理的？

让我们以几个真实案例展示典型记录的完整处理过程。

#### 案例1：经典氮唑类抑制剂（最快速，<1分钟）

**输入记录**（来自chunk_01, REC_0021）：
```
record_id: REC_0021
enzyme_name: CYP51 (C. albicans)
ligand_name: FLUCONAZOLE
pdb_id: 1EA1
final_class: inhibitor
confidence: high
notes: "Triazole antifungal, Fe-N distance 2.10Å, clinical drug"
```

**窗口处理流程**：

```
[读取记录]
↓
[识别配体类型]
- "FLUCONAZOLE" → 立即识别为已知三唑类抗真菌药
- 化学结构包含三唑环（triazole）→ Type II抑制剂特征
↓
[检查notes]
- "Fe-N distance 2.10Å" → 明确的Fe-N配位证据（Level A证据）
- "clinical drug" → FDA批准药物，文献支持充分
↓
[快速决策]
- 原始分类"inhibitor"正确 ✓
- 有定量Fe-N距离 → HIGH confidence
- X-ray测量数据 → Evidence Level A
- 无任何疑问 → needs_human_review = false
↓
[输出JSONL]（耗时<1分钟）
{
  "record_id": "REC_0021",
  "verified_class": "INHIBITOR",
  "confidence": "HIGH",
  "evidence_level": "A",
  "is_correct": true,
  "trap_detected": "none",
  "needs_human_review": false,
  "reasoning": "Fluconazole is well-known triazole antifungal. Fe-N distance 2.10Å confirms Type II inhibition. HIGH confidence."
}
```

**关键点**：
- 窗口依靠**配体名称识别** + **notes中的Fe-N距离**直接确认
- 无需WebSearch或深度分析
- 这类记录约占40%（~270条），都是经典抑制剂

#### 案例2：经典底物（快速，1-2分钟）

### 4.8 分类决策树详解

本节详细说明窗口如何判断配体属于哪一类。

#### 4.8.1 INHIBITOR判断标准

**触发条件**（满足任一即可）：

```
决策树：

配体名称包含以下关键词？
├── "azole" (唑类) → INHIBITOR
├── "triazole" (三唑) → INHIBITOR
├── "imidazole" (咪唑) → INHIBITOR
├── "ketoconazole", "fluconazole" 等已知药物名 → INHIBITOR
└── 不包含 → 继续检查

Notes中是否有Fe-N距离？
├── 有（1.9-2.8Å） → Type II抑制剂 → INHIBITOR
└── 没有 → 继续检查

Notes中是否明确说"inhibitor"？
├── 是 → INHIBITOR
└── 否 → 继续检查

配体是否含氮配位基团（pyridine, amine, cyanide）？
├── 是 + 无turnover证据 → INHIBITOR
└── 否 → 可能是SUBSTRATE
```

**典型INHIBITOR特征**：
- **化学结构**：含氮杂环（咪唑、三唑、吡啶）
- **Fe-N配位**：notes中有Fe-N距离测量
- **临床药物**：氟康唑、伊曲康唑、咪康唑等
- **Ki/IC50数据**：notes中有抑制常数

#### 4.8.2 SUBSTRATE判断标准

**触发条件**（满足任一即可）：

```
决策树：

配体是否是酶的已知天然底物？
├── CYP101A1 + camphor → SUBSTRATE
├── CYP102A1 + 脂肪酸 → SUBSTRATE
├── CYP2B4 + benzphetamine → SUBSTRATE
└── 不确定 → 继续检查

Notes中是否有Km/Kcat数据？
├── 有 → SUBSTRATE
└── 没有 → 继续检查

Notes中是否明确说"substrate"/"natural substrate"？
├── 是 → SUBSTRATE
└── 否 → 继续检查

配体化学性质是否匹配酶功能？
├── CYP51 + 胆固醇/羊毛甾醇 → SUBSTRATE
├── CYP121 + 环(Tyr-Tyr) → SUBSTRATE
├── EryF + 红霉素 → SUBSTRATE
└── 不匹配 → 可能不是SUBSTRATE
```

**典型SUBSTRATE特征**：
- **天然底物**：酶的生理底物（camphor for P450cam）
- **Km数据**：notes中有Michaelis常数
- **产物鉴定**：notes中明确描述羟化产物
- **化学匹配**：配体结构与酶功能一致

#### 4.8.3 PRODUCT判断标准

**触发条件**（需谨慎判断）：

```
决策树：

配体名称是否有氧化标志？
├── 含"hydroxy-" / "hydroxylated" → 可能是PRODUCT
├── 含"-ol" / "-one" 且底物是烷烃 → 可能是PRODUCT
└── 无 → 继续检查

Notes中是否明确说"product"？
├── 是 → 需要进一步确认（有可能是陷阱！）
│   ├── 如果底物是A，产物是B，配体是B → PRODUCT ✓
│   └── 如果底物是A，产物是B，但B还能被进一步氧化 → B可能是下一轮的SUBSTRATE！
└── 否 → 继续检查

是否检测到substrate_product_confusion陷阱？
├── 是 → 标记needs_human_review=true
└── 否 → 按照notes分类
```

**陷阱警告**：
- **底物/产物混淆是最常见的陷阱**（19例）
- 某些"product"实际上是进一步氧化的底物
- 例如：胆固醇 → 羟基胆固醇 → 二羟基胆固醇
  - 羟基胆固醇既是第一步的产物，又是第二步的底物

#### 4.8.4 EXCLUDE判断标准

**触发条件**（满足任一即可）：

```
决策树：

配体是否是辅因子/辅助分子？
├── 血红素(heme) → EXCLUDE
├── 氧分子(O2) → EXCLUDE
├── 水(H2O) → EXCLUDE
└── 不是 → 继续检查

配体是否是结晶助剂？
├── 去垢剂(detergent, PEG, CTAB) → EXCLUDE
├── 缓冲液组分(酒石酸, 琥珀酸, 丙二酸) → EXCLUDE
├── 多胺(精胺, 亚精胺) → EXCLUDE
└── 不是 → 继续检查

配体是否是研究探针？
├── 荧光探针(Dansyl, Pyrene) → EXCLUDE
├── 亲和探针(Biotin标记) → EXCLUDE
├── 光敏剂(Ruthenium络合物) → EXCLUDE
└── 不是 → 继续检查

配体是否是化学试剂？
├── 交联剂(bis-maleimide) → EXCLUDE
├── 有机溶剂 → EXCLUDE
└── 不是 → 可能不是EXCLUDE
```

**典型EXCLUDE特征**：
- **辅因子**：血红素、NAD(P)H、氧气
- **溶剂/缓冲液**：DMSO、酒石酸、MOPS
- **探针分子**：荧光基团、亲和标签
- **金属离子**：Cd²⁺、Hg²⁺（非生理性）

### 4.9 置信度判断详解

窗口如何分配HIGH/MEDIUM/LOW置信度？

#### 4.9.1 HIGH置信度（550条，80.6%）

**必须满足以下条件之一**：

```
条件组A：有定量实验数据
├── Fe-N距离测量（X-ray结构）
├── Km/Kcat数据（酶动力学）
├── Ki/IC50数据（抑制常数）
└── 产物结构鉴定（NMR/MS）

条件组B：明确的文献支持
├── Notes明确说"substrate"/"inhibitor"/"product"
├── 配体是已知的经典底物/抑制剂
│   ├── Camphor for P450cam
│   ├── Fluconazole for CYP51
│   └── Testosterone for steroid hydroxylases
└── 酶功能与配体性质完美匹配

条件组C：化学结构明确
├── 氮唑类化合物 + Fe-N配位 → 必然是抑制剂
├── 辅因子/溶剂 → 必然是EXCLUDE
└── 天然底物 → 必然是SUBSTRATE
```

**HIGH置信度示例**：
```json
{
  "record_id": "REC_0021",
  "ligand_name": "FLUCONAZOLE",
  "verified_class": "INHIBITOR",
  "confidence": "HIGH",
  "evidence_level": "A",
  "reasoning": "Fe-N distance 2.10Å measured by X-ray. Clinical triazole antifungal."
}
```

#### 4.9.2 MEDIUM置信度（131条，19.2%）

**触发条件**（满足任一）：

```
情况1：缺乏直接实验证据
├── Notes没有定量数据
├── 但配体结构和酶功能匹配
└── 基于化学推断分类

情况2：底物类似物
├── 配体不是天然底物
├── 但化学结构相似
└── 可能被催化但活性未知

情况3：非典型案例
├── BM3变体处理修饰脂肪酸
├── 非天然配体测试
└── 文献支持有限

情况4：存在轻微不确定性
├── 配体可能有双重行为（但倾向某一类）
├── Notes信息不完整
└── 需要推断但不至于LOW
```

**MEDIUM置信度示例**：
```json
{
  "record_id": "REC_0347",
  "ligand_name": "Omega-3 fatty acid derivative",
  "enzyme_name": "CYP102A1 variant",
  "verified_class": "SUBSTRATE",
  "confidence": "MEDIUM",
  "evidence_level": "C",
  "reasoning": "Modified fatty acid. BM3 variant likely processes it but no Km data. Chemical structure suggests substrate."
}
```

#### 4.9.3 LOW置信度（1条，0.1%）

**触发条件**（极少使用）：

```
必须同时满足：
├── 证据严重不足
├── 存在矛盾信息
├── 无法合理推断
└── 但又不能直接标记needs_human_review（因为给出了分类）

注意：大部分极度不确定的情况会标记needs_human_review=true，
     而不是给出LOW置信度
```

**LOW置信度示例**（仅1例）：
```json
{
  "record_id": "REC_0515",
  "ligand_name": "Androstenedione",
  "enzyme_name": "EryF",
  "verified_class": "INHIBITOR",
  "confidence": "LOW",
  "evidence_level": "C",
  "needs_human_review": true,
  "reasoning": "Non-native steroid for macrolide biosynthesis enzyme. Uncertain if substrate or inhibitor."
}
```

**为什么LOW置信度只有1条？**
- 因为窗口被指示：如果真的不确定，直接标记`needs_human_review=true`
- LOW confidence用于"给出了分类但不太确定"的罕见情况

### 4.10 证据等级判断详解

窗口如何分配A/B/C/D证据等级？

#### 4.10.1 Level A（409条，60.0%）

**必须有定量实验数据**：

```
测量类型：

X-ray晶体学数据
├── Fe-N距离（1.9-2.8Å for Type II inhibitors）
├── 配体-蛋白质相互作用距离
└── 结合口袋几何参数

酶动力学数据
├── Km（Michaelis常数）
├── Kcat（催化常数）
├── Ki（抑制常数）
└── IC50（半抑制浓度）

产物鉴定数据
├── NMR结构鉴定
├── MS质谱分析
└── HPLC分离纯化
```

**Level A示例**：
```json
{
  "evidence_level": "A",
  "reasoning": "Fe-N distance 2.25Å measured in crystal structure. Quantitative Type II inhibition."
}
```

#### 4.10.2 Level B（219条，32.1%）

**文献明确陈述但无定量数据**：

```
文献支持类型：

Notes明确说明
├── "This is a substrate"
├── "Known inhibitor"
└── "Product of hydroxylation"

已知的经典案例
├── Camphor is substrate of P450cam（教科书级别）
├── Fluconazole is CYP51 inhibitor（FDA批准药物）
└── Testosterone is steroid hydroxylase substrate

文献共识
├── 多篇文献报道
└── 无争议的分类
```

**Level B示例**：
```json
{
  "evidence_level": "B",
  "reasoning": "Notes explicitly state 'natural substrate'. Well-documented in literature."
}
```

#### 4.10.3 Level C（26条，3.8%）

**基于结构/化学推断**：

```
推断依据：

化学结构特征
├── 配体含氮杂环 → 可能是抑制剂
├── 配体是脂肪酸 → BM3的可能底物
└── 配体有羟基 → 可能是产物

酶功能匹配
├── CYP51酶 + 甾醇类似物 → 可能是底物
├── CYP121酶 + DKP衍生物 → 可能是底物
└── 类固醇羟化酶 + 类固醇 → 可能是底物

但缺乏直接证据
├── Notes没有明确说明
├── 没有定量数据
└── 完全基于化学知识推断
```

**Level C示例**：
```json
{
  "evidence_level": "C",
  "reasoning": "Cholesterol analog. CYP51 function is sterol demethylation. Likely substrate based on structure but no Km data."
}
```

#### 4.10.4 Level D（28条，4.1%）

**证据不足或不确定**：

```
触发条件：

完全缺乏证据
├── Notes为空或信息极少
├── 配体是非天然化合物
└── 无法从化学结构推断

矛盾信息
├── 不同来源说法不一
└── PDB标注与化学性质矛盾

辅助试剂（EXCLUDE类）
├── 去垢剂、缓冲液等
├── 明显不参与催化
└── 但无需证据等级（本身就是排除）
```

**Level D示例**：
```json
{
  "evidence_level": "D",
  "reasoning": "Detergent used in crystallization. No catalytic relevance. EXCLUDE classification."
}
```

## 第五部分：needs_human_review标记机制（核心章节）

> **本章节是回答"15条记录如何被识别"这一关键问题的核心内容**

### 5.1 标记机制概述

`needs_human_review` 是JSONL输出中的一个布尔字段。当窗口在验证过程中遇到以下情况时，会将该字段设为 `true`：

```json
{
  "record_id": "REC_XXXX",
  "needs_human_review": true,    // ← 关键字段
  "review_reason": "原因描述",   // ← 必须说明原因
  ...
}
```

### 5.2 触发 `needs_human_review=true` 的五类情况

#### 情况1：原始分类明显错误（本次11例）

**触发条件**：
- 原始分类（`original_class`）与验证后分类（`verified_class`）不同
- 且错误具有代表性或需要确认修正是否正确

**典型案例**：研究探针被错标为substrate
```
原始CSV中：final_class = "substrate"
验证结果：verified_class = "EXCLUDE"
原因：配体是研究探针（荧光探针、亲和探针、光敏剂），不是酶的催化底物
```

**本次实际触发的记录**：
- REC_0195：Ruthenium bipyridine complex（光敏剂探针）
- REC_0205-0210：Biotin-PEG-adamantane、Dansyl荧光探针系列
- REC_0213：Bis-maleimide crosslinker（交联剂）
- REC_0214：Pyrene acetamide（芘荧光探针）
- REC_0216：Cyanide ion（氰离子是抑制剂不是底物）

#### 情况2：检测到分类陷阱（本次2例被标记）

**触发条件**：
- `trap_detected` 字段不为 "none"
- 且陷阱可能影响分类正确性

**典型案例**：底物/产物混淆
```
trap_detected = "substrate_product_confusion"
原因：配体可能是底物也可能是产物，需要文献确认反应方向
```

**本次实际触发的记录**：
- REC_0220：5-exo-hydroxycamphor（camphor羟化产物，原标为substrate）
- REC_0500：Hydroxymethoxy-DKP（可能是底物或产物）
- REC_0590：Cyclopropylidene-lanosterol（原标为product，实为底物类似物）

#### 情况3：配体具有双重行为（本次1例）

**触发条件**：
- 配体同时具有底物特征和抑制剂特征
- 实际行为取决于具体酶变体或实验条件

**典型案例**：芳香胺
```
配体：4-methylaniline
问题：芳香胺可被N-氧化（底物行为）或Fe-N配位（抑制行为）
trap_detected = "mechanism_based_inhibitor"
```

**本次实际触发的记录**：
- REC_0354：4-methylaniline（BM3变体的底物/抑制剂歧义）

#### 情况4：置信度过低（本次1例）

**触发条件**：
- `confidence = "LOW"`
- 证据等级为C或D

**典型案例**：非天然底物
```
配体：Androstenedione（非天然类固醇）
酶：EryF（红霉素生物合成酶）
问题：非天然底物，可能是弱底物或抑制剂
```

**本次实际触发的记录**：
- REC_0515：Androstenedione（EryF的非天然配体，LOW confidence）

#### 情况5：原始分类与验证分类矛盾且需确认

**触发条件**：
- `is_correct = false`（原始分类被判定为错误）
- 修正后的分类需要确认

**注意**：并非所有 `is_correct=false` 的记录都会标记 `needs_human_review=true`。
只有当修正存在不确定性时才会标记。

### 5.3 标记流程详解

```
┌─────────────────────────────────────────────────────────────┐
│           窗口判断是否标记 needs_human_review 的流程         │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│   读取一条记录                                               │
│         ↓                                                    │
│   ┌─────────────────────────────────────────────────────┐   │
│   │  快速判断：分类是否明确？                            │   │
│   │  - 氮唑抑制剂 + Fe-N距离 → 明确的INHIBITOR          │   │
│   │  - 经典底物 + Km数据 → 明确的SUBSTRATE              │   │
│   │  - 缓冲液/去垢剂 → 明确的EXCLUDE                    │   │
│   └─────────────────────────────────────────────────────┘   │
│         ↓                                                    │
│   分类明确？ ──是──→ needs_human_review = false             │
│         │                                                    │
│         否                                                   │
│         ↓                                                    │
│   ┌─────────────────────────────────────────────────────┐   │
│   │  深度分析：检查五类触发条件                          │   │
│   │  □ 原始分类明显错误？                               │   │
│   │  □ 检测到分类陷阱？                                 │   │
│   │  □ 配体具有双重行为？                               │   │
│   │  □ 置信度过低（LOW）？                              │   │
│   │  □ 修正后需要确认？                                 │   │
│   └─────────────────────────────────────────────────────┘   │
│         ↓                                                    │
│   满足任一条件？ ──是──→ needs_human_review = true          │
│         │                    + 填写 review_reason            │
│         否                                                   │
│         ↓                                                    │
│   needs_human_review = false                                 │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 8.2 JSONL输出格式详解

每条记录的JSON结构：

```json
{
  "record_id": "REC_0001",
  "chunk_id": "01",
  "uniprot_id": "P00183",
  "enzyme_name": "CYP101A1 (P450cam)",
  "ligand_name": "Camphor",
  "pdb_id": "1DZ4",
  "original_class": "substrate",
  "verified_class": "SUBSTRATE",
  "confidence": "HIGH",
  "evidence_level": "A",
  "is_correct": true,
  "is_mutant": false,
  "trap_detected": "none",
  "needs_human_review": false,
  "review_reason": "",
  "reasoning": "Camphor is the canonical substrate of CYP101A1..."
}
```

**字段说明**：

| 字段 | 类型 | 说明 | 示例值 |
|------|------|------|--------|
| record_id | string | 全局唯一ID | "REC_0001" |
| chunk_id | string | 所属chunk编号 | "01" |
| uniprot_id | string | UniProt ID | "P00183" |
| enzyme_name | string | 酶名称 | "CYP101A1 (P450cam)" |
| ligand_name | string | 配体名称 | "Camphor" |
| pdb_id | string | PDB结构ID | "1DZ4" |
| original_class | string | 原始分类（小写） | "substrate" |
| verified_class | string | 验证后分类（大写） | "SUBSTRATE" |
| confidence | string | 置信度 | "HIGH"/"MEDIUM"/"LOW" |
| evidence_level | string | 证据等级 | "A"/"B"/"C"/"D" |
| is_correct | boolean | 原始分类是否正确 | true/false |
| is_mutant | boolean | PDB是否为突变体 | true/false |
| trap_detected | string | 检测到的陷阱类型 | "none"/"substrate_product_confusion"/"mechanism_based_inhibitor" |
| **needs_human_review** | **boolean** | **是否需要人工复审** | **true/false** |
| review_reason | string | 复审原因 | "" 或具体原因 |
| reasoning | string | 验证推理过程 | "..." |

## 第十部分：故障排查指南

### 10.1 窗口调用了Codex/Gemini

**症状**：在窗口输出中看到`mcp__codex__codex`或`mcp__gemini__gemini`

**原因**：全局CLAUDE.md配置覆盖了SOP

**解决**：
1. 立即在窗口输入：
   ```
   停止！你违反了SOP中的工具限制。本次任务禁止使用Codex和Gemini。
   请重新阅读SOP开头的"覆盖全局配置"声明。
   ```
2. 如果继续违规，关闭窗口重开

### 10.2 窗口进度太慢

**症状**：1小时后仍不足20条记录

**原因**：可能在做深度分析

**解决**：提醒窗口：
```
这是快速并行验证（2-3分钟/条），不是深度审核。
对于不确定的记录，标记needs_human_review=true即可。
```

### 10.3 窗口卡住不动

**症状**：超过10分钟没有输出

**解决**：
1. 关闭该窗口
2. 打开新窗口
3. 粘贴相同的SOP
4. JSONL格式支持断点续传

### 10.4 合并脚本报错

**常见错误1**：JSON解析错误
- 原因：某条记录格式不正确
- 解决：脚本已包含容错机制，会跳过错误行

**常见错误2**：找不到文件
- 原因：文件路径或命名不正确
- 解决：检查Chunk 05是否已重命名
